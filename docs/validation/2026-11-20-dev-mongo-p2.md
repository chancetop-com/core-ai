# Dev: Mongo decommission P2 — runtime decoupling

- 日期：2026-11-20
- 环境：`FBRDevAKSCluster / dev-ai / core-ai-server`
- 镜像：`chancetop/core-ai-server:2.0.327`（包含 P2 commits `aa7341fd5`、`d4b8a83ac`、`12f308de7`、`8b8148afe`）
- 配置：`SYS_STORE_MODE=pg`、`SYS_DATASET_STORE=postgresql`
- 结论：**PASS**，dev 在 Mongo 不可达时正常启动并完成 E2E，core-ai Mongo 连接数为 0

## 实现

- `StoreMode.mongoRequired()` 根据 store 开关判断是否还需要 Mongo；`ServerApp` 在模块初始化阶段缓存
  `mongoRequired` / `postgresConfigured`，启动 hook 只读取字段（core-ng 在 hook 阶段已关闭 property 校验，
  直接调用 `property()` 会 NPE）。
- `registerMongo()` 在 pg/postgresql/auto 组合下直接返回，不创建 `MongoConfig`/`Mongo` bean。
- `SchemaMigrationManager` 只在需要 Mongo 时绑定。
- `StartupDependencyCheck` 始终探测 PostgreSQL（`SELECT 1`），只有需要 Mongo 时才探测 Mongo。
- PG 分支不再绑定 28 个 `*MigrationService`；`app.g2_migration_markers` 保留为历史证据。
- `sys.gateway.legacy.secret` 成为 legacy key 的显式属性，`sys.mongo.uri` 仍作为临时 fallback 并保持声明/读取。

| 恢复 `SYS_MONGO_URI` 为 ConfigMap 值并滚动 | 2/2；仍只有 PostgreSQL 启动探测 |

## 说明

- 这次验证只证明 **dev 不再连接 Mongo**；P2 的 7 天 soak、NetworkPolicy 阻断和 UAT/prod 推广仍未执行。
- `sys.mongo.uri` 仍保留（`SettingsModule` legacy fallback 和 P3 前的属性校验），但不再用于建立连接。
- dev 当前通过 `kubectl set image` 跑 `2.0.327`；env 仓库 manifest 由另一会话维护，未在本记录中改动。
