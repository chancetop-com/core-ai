# UAT 2.0.390：LLM Ops 500 与 trace 摄取中断（V57/V58 未应用）

## 现象

- 2.0.390 于 2026-11-26T05:16Z 完成 rollout（两 pod 均为 `chancetop/core-ai-server:2.0.390`）。
- Admin → Dashboard → **LLM Ops** 页面 500。
- 同时两个 pod 持续打印 trace 摄取失败：
  - `column "resolved_model" of relation "traces" does not exist`
  - `Failed to create trace for started span: gateway.responses`

## 根因

2.0.390 包含 V57/V58 两个 Flyway 迁移，但 UAT 在 rollout 前没有执行迁移。`app.flyway_schema_history`
当时的 head 是 **V55**，数据库缺列：

| 迁移 | 缺列 |
|---|---|
| V57 `trace_resolved_model` | `app.traces.resolved_model`、`app.spans.resolved_model` |
| V58 `span_reasoning_and_first_content` | `app.spans.reasoning_tokens`、`app.spans.first_content_ms` |

- LLM Ops 的 `GET /api/admin/analytics/llm-metrics` 走 `PgSpanStore.llmModelMetrics`，SQL 引用
  `first_content_ms` → 500。
- trace 摄取 insert 引用 `resolved_model` → 每条记录重试 3 次后丢弃（`SpanBuffer - trace ingest failed
  after 3 attempts, dropping record`）。

## 修复

```powershell
kubectl port-forward -n uat-ai svc/postgresql-rw 15433:5432
.\gradlew.bat :core-ai-server-db-migration:flywayMigrate -Penv=uat --console=plain
```

2026-11-26T06:32Z 执行成功：V56 的两列已存在（skipped），V57/V58 正常应用并写入
`app.flyway_schema_history`，head 变为 **V58**；随后 `flywayValidate -Penv=uat` 通过。
`public.flyway_schema_history` 仍只有 V1，是历史遗留的无效 ledger，实际生效的是 `app`。

## 验证

- schema：`traces.resolved_model`、`spans.resolved_model`、`spans.reasoning_tokens`、
  `spans.first_content_ms` 均为 1（存在）。
- 错误停止：两个 pod 最后一条 `does not exist` 为 **06:32:16Z**，之后 3 分钟无新增。
- LLM Ops API：`GET /api/admin/analytics/llm-metrics?minutes=360&bucket_minutes=5` → **200**，
  `bucketMinutes=5`、59 个点、4 个模型（deepseek-flash 1103 calls / 15 errors / avg TTFT 10045 ms，
  等等）。
- trace 摄取：06:32:30Z 之后已写入 8 条 trace / 82 条 span，恢复。
- Prod 不受影响：prod 仍为 2.0.369（早于 decode-rate 功能），不依赖 V57/V58。

## 影响与后续

- 05:16Z–06:32Z 约 76 分钟内 UAT 的所有 trace/span 摄取记录被丢弃，无法回补（源端只有实时 buffer）。
  该窗口内 LLM Ops 与 Trace 列表本应展示的数据缺失。
- 流程修正：以后 UAT 升级如果包含新的 `V*.sql`，先在 `postgresql-rw` 上做 port-forward 并执行
  `flywayMigrate -Penv=uat`，再 rollout 镜像；已更新 `project/uat-deployment.md` 的 Deploy workflow。
