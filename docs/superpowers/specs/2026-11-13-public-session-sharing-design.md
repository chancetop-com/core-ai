# 会话与 Trace 匿名分享设计

日期：2026-11-13

状态：用户已确定“任何拿到链接的人都能查看，无需登录”，并在查看方案后授权继续实现。功能已合并并推送 `master`，UAT 发布目标为 `2.0.224`。

UAT 发布约束（2026-11-13）：现有 Mongo span 约 140 GiB，而 PostgreSQL 实例磁盘为 20 GiB。用户选择保留 Mongo span 读写，因此 UAT 配置 `SYS_TRACE_SPAN_STORE_MODE=mongo`，不启动历史 span 复制。其他业务数据及会话分享仍使用 PostgreSQL。新增配置默认 `auto`，延续其他环境原有的存储选择。UAT 的 `app` schema 从 V31 补齐 V32–V34，其中 span 表保留为空，不代表历史数据已经迁移。

## 目的与范围

Chat 页面提供分享入口，让接收者沿着同一段对话查看对应执行 Trace、工具结果、图片和产物，用于排查问题。

接收者无需登录，只能读取链接授权的内容。创建、查看自己已有分享、撤销分享仍需登录，并验证会话所有权。由于第一版固定包含 Trace，创建还要求创建者具有 `TRACE_VIEW`，且原 Trace 可见范围允许读取纳入分享的 Trace；不能通过分享扩大创建者自己的读取权限。分享不赋予发送消息、运行工具、Replay、审批、终端访问或修改原会话的能力。

第一版分享整个会话从开头到一个已完成轮次的范围，不提供任意消息挑选、接续会话、评论、全文导出或长期证据存档。原 Chat 和 Trace 接口的现有权限保持各自语义，匿名能力由独立分享接口提供。

## 已核实的现状

- `SessionHistoryHelper` 已返回消息序号和 `traceId`；前端 `historyToChatMessages` 尚未把两者保留到展示模型。
- 当前会话历史按所有者校验，Trace 另有 `TRACE_VIEW` 和 SELF/API/ALL 范围校验，普通 URL 不能作为分享授权。
- `TraceDetailPanel` / `TraceInspector` 已有调用树、输入输出和按需加载 span payload 的能力，但包含私有 API、Replay 和原会话跳转，需要为分享页提供只读配置和可注入的数据读取方法。
- 文件分享已有随机 token 模式可参考，但当前文件分享没有可直接复用的到期/撤销模型。
- sessions/messages 和 spans 已有 Mongo/Pg 存储适配；trace 主记录仍使用 Mongo。
- Trace 归档会移除在线记录、span 及 payload blobs，当前读取接口不提供归档回读。
- 普通 subagent 延续父调用的 Trace，以 `spanId/parentSpanId` 构成子树；没有通用的跨 Trace 父子关系。
- 产物挂在 session 累计列表中，没有消息序号；上传附件也需要从消息中的平台引用与附件记录核对归属。

## 方案选择

| 方案 | 收益 | 代价与决定 |
| --- | --- | --- |
| 登录后持链接读取 | 可增加接收者身份约束 | 用户已选择无需登录，因此不采用 |
| 匿名链接，固定分享范围，读取原始记录 | 接收方操作最少，复用现有存储与展示 | 本方案建议；依赖原数据保留时间，需独立校验每个读取请求 |
| 匿名链接，复制完整排障快照 | 可独立于原数据长期保存 | 增加 payload、附件复制和快照生命周期管理，留待长期留证需求明确后再做 |

固定范围表示消息、Trace 与文件的授权集合固定，不表示其内容已经复制成不可变快照。迟到的 span 可以补全同一已授权 Trace，但之后的新轮次不会进入旧链接。

## 用户交互

Chat 顶栏及会话菜单均提供“分享会话”。同一会话第一版至多有一个有效分享；再次打开弹窗可复制现有链接或撤销。撤销后重新生成新 token，旧链接不恢复有效。

弹窗明确展示：

```text
分享会话
任何拿到链接的人均可查看本次会话、Trace 和相关附件。
Trace 包含执行时的输入输出，可能含系统提示词、记忆和检索内容。
分享范围：截至第 N 轮完成（时间）
包含：会话内容、Trace、相关图片及文件
有效期：[7 天 ▾]          可选 1 / 7 / 30 天
[生成并复制链接]
```

建议默认 7 天，服务端限制最长 30 天。第一版固定包含 Trace，避免接收者拿到无法排障的半份信息。不具备 Trace 查看权限时不能生成，并显示所缺权限。生成时会话必须已结束当前轮次且至少存在一个完整轮次；执行中禁用生成，并说明等待本轮完成。失败但已落库的终止轮次也属于可分享范围。已有链接在后续轮次执行期间仍可复制，其范围不变。

第一版生成整个当前会话的分享，不支持回选更早轮次。弹窗展示将包含的 session 产物清单，生成时固定该清单；这个限制避免在尚无产物-轮次关联的模型上猜测文件属于哪一轮。

分享链接为 `/shared/sessions/:token`，位于前端登录守卫之外：

```text
会话标题 · 只读分享 · 分享截至时间
┌──────────────────────────┬────────────────────────┐
│ 用户消息、附件             │ 当前回复对应的 Trace    │
│ Agent 回复、工具结果       │ 调用树 / 输入输出 / 错误 │
│             [查看 Trace] │ 耗时 / token / 模型     │
└──────────────────────────┴────────────────────────┘
```

移动端先显示会话，Trace 使用抽屉或独立面板。没有 Trace ID、尚未取得、已确认归档分别显示明确状态；没有归档证据时只能显示“Trace 当前不可用”，不能猜测原因。消息列表分页；Trace 摘要、span 详情与附件均按需读取。

分享页可以复制文字、展开工具结果、放大图片和下载授权附件。隐藏输入框、快捷回复、审批按钮、反馈提交、图片编辑、Replay、终端以及跳转私有管理页面的操作。使用独立 `SharedSession` 页面，不挂载会恢复运行态/SSE 的整个 `Chat` 页面。

## 分享记录与授权范围

新增 `SessionShare` 及独立 store，至少包含：

- `id`、`sessionId`、`ownerUserId`。
- `token`：沿用现有文件分享的安全随机 32 字节、URL-safe 编码模式，用于公开请求查找；它是授予读取权限的秘密，仅管理接口可向经验证的所有者返回。
- `createdAt`、`expiresAt`、`revokedAt`。
- `maxMessageSeq`、`titleAtCreation`。
- 明确的 `allowedTraceIds`、`allowedFileIds` 和附件对象引用清单。
- 分享创建时的截止轮次/时间及可解释的缺失内容状态。

不得将大段 Trace、span payload 或文件内容塞进分享主记录。大型授权清单可采用独立关联记录，避免 Mongo 文档大小限制；分页和范围查询需要在存储层完成。

token 建立唯一索引。登录所有者可再次获得完整分享链接；公开 metadata 和通用会话/Trace DTO 不序列化 token 字段。过期/撤销的记录仅供管理状态查询，不可重新启用旧 token。

创建时先确认当前用户拥有且可读取该会话，且没有执行中的轮次，再选定持久化完整轮次的最大序号，建立授权清单。读取清单后复核持久化的最新消息序号与轮次终止状态；若期间开始新轮次则返回范围已变化，让弹窗刷新。全部范围计算完成后才使分享生效，失败时不得留下部分可用的分享。一个有效分享的约束需要由存储层原子创建/替换保证，不能仅凭前端按钮防重。

消息查询增加 `seq <= maxMessageSeq` 的上界，Mongo/Pg 两种实现均需支持。不能先读整个会话再仅依赖前端隐藏后续内容。

根 Trace ID 从已覆盖 agent 消息中的持久化 `traceId` 获取，读取时必须同时核对 `trace.sessionId == share.sessionId` 和 `trace.userId == share.ownerUserId`。尚未入库的候选 ID 可保留为等待状态，后来入库也必须通过相同核对。普通 subagent 的 spans 已包含在同一个 Trace 中；第一版不展开其他 Trace，包括 workflow 的独立 child Trace，只显示未纳入分享。不能仅凭时间窗口、相同用户、同一个 Agent 或消息正文里的 ID 扩大授权。只允许访问清单内 Trace 的 spans，span ID 和 Trace ID 必须同时匹配。

文件/图片只允许访问两类明确清单：已覆盖消息引用且通过 owner/session 核对的附件，以及创建时固定的当前 session 产物清单。公开请求不实时展开 session 累计列表，后续新增文件不会加入。每个文件读取请求重新验证清单。非 `FileRecord` 的多模态附件需使用稳定的服务端对象引用，不能允许访客传入任意存储路径或 URL。

## 接口边界

建议沿用当前 `/api/sessions` 命名，具体 WebService 类划分留给实施：

| 接口 | 访问者与作用 |
| --- | --- |
| `POST /api/sessions/:id/shares` | 登录所有者创建分享，返回链接及范围摘要 |
| `GET /api/sessions/:id/shares` | 登录所有者读取当前分享状态及有效链接 |
| `DELETE /api/sessions/:id/shares/:shareId` | 登录所有者撤销，幂等 |
| `GET /api/public/session-shares/:token` | 匿名读取标题、范围和有效状态 |
| `GET /api/public/session-shares/:token/messages` | 匿名分页读取范围内消息 |
| `GET /api/public/session-shares/:token/traces/:traceId` | 匿名读取授权 Trace 概况 |
| `GET /api/public/session-shares/:token/traces/:traceId/spans` | 匿名读取授权 span 摘要 |
| `GET /api/public/session-shares/:token/traces/:traceId/spans/:spanId` | 匿名按需读取授权 span 详情 |
| `GET /api/public/session-shares/:token/files/:refId/content` | 匿名读取授权文件或图片 |

每个公开接口都校验 token、到期/撤销、源会话是否仍可分享以及资源归属，不能只在页面 metadata 请求校验一次。创建者账号被禁用或失去 Trace 查看权限后，分享整体不可用；具体 Trace 读取还必须在创建者当前可见范围内。权限解析接收显式的所有者身份，不伪造匿名请求的登录上下文。缩略图等衍生资源遵循同一规则。错误响应不泄露另一会话、Trace 或文件是否存在。

服务端分享服务通过存储层和已有 payload 还原逻辑读取数据，在完成范围校验后生成专用 DTO。不能借所有者身份代理任意私有接口。保留 Trace 图片引用还原能力，避免给接收者展示 `coreai-image://` 裸引用。

## 匿名内容与撤销语义

- 专用分享 DTO 只输出页面所需字段，不额外提供实体、Agent 配置、sandbox 连接信息或环境变量的读取接口。
- 保留已授权 Trace 中实际记录的完整执行输入输出，包括其中的 system prompt、注入记忆、检索内容和工具结果；不额外查询记忆库或配置补全未被记录的内容。“不提供 Agent 配置接口”不表示执行输入中原本存在的指令会自动移除。创建弹窗展示这一公开范围。
- 消息工具结果、Trace、span 及 Raw 展示统一经过同一服务端投影和脱敏流程。已知认证头、cookie、API key、access/refresh token、URL 认证参数等结构化字段屏蔽；可解析 JSON 字符串递归处理。
- 任意自然语言和自由文本中的秘密无法承诺全部自动识别。创建弹窗应明确公开内容包含工具参数/结果和 Trace 输入输出；不使用“已完全脱敏”等保证性描述。
- 分享文件通过本分享接口交付，不调用已有永久文件分享操作，不复制到公开对象存储，也不将私有下载地址直接交给接收者。分享页中已识别的平台文件链接改写为受分享范围约束的链接。
- 页面及数据/附件响应使用 `Cache-Control: no-store`，页面采用 `Referrer-Policy: no-referrer`、禁止搜索索引；日志和遥测不记录明文分享 token，不加载会收到 token 的第三方分析脚本。
- 分享页不执行工具结果或附件中的 HTML/脚本。HTML/SVG 等主动内容采用安全下载或隔离预览，沿用附件类型检查和路径校验。
- 撤销或到期后，后续所有分享读取立即失效；已经下载的文件和复制的文字不能收回，已有独立公开文件链接也不会被本功能撤销。
- 原会话软删除后，本会话分享读取失效。已归档或被清理的 Trace/附件显示“原始数据已不可用”，其他仍在的会话内容可以继续展示。
- 公开接口需要请求频率、分页数量和 payload 读取的资源限制，具体阈值采用仓库现有机制并由实施阶段确定。

## 前后端改动边界

前端补齐 `ChatMessage.seq/traceId` 及历史映射，增加分享弹窗与独立分享路由。复用消息组件并显式提供 `readOnly`；Trace 组件注入分享 API loader，覆盖 trace、span 和 payload 全链路。普通 Chat 的即时 Trace 入口可在完成后刷新历史，不依赖本次额外扩展 SSE 协议。

后端新增分享服务、公开/管理 API、DTO、存储适配及索引迁移。Mongo/Pg 模式都应支持分享记录与消息上界查询。Mongo 实体注册、绑定顺序、实体包装类型、DTO/实体枚举分离等遵循仓库约束，动态异构 payload 使用 JSON 字符串。

不修改原有会话/Trace 权限范围，不提供匿名写接口，不依赖直接读取 sandbox 临时文件。创建、撤销与到期是分享本身的生命周期，不触发 Agent 执行。

## 验收依据

1. 所有者生成链接后，未登录的独立浏览器能查看范围内消息、对应 Trace/span 输入输出及图片/附件。
2. 其他登录用户不能为不属于自己的会话创建、查看管理状态或撤销分享。
   有会话权限但无 Trace 查看权限的用户也不能借此生成匿名 Trace 访问；所有者账号禁用或相关权限被撤销后，已有分享失效。
3. 替换 token、Trace ID、span ID、文件 ID 或分页游标，均不能读到范围外数据；分享前后追加的新轮次不会出现在旧链接中。
4. 撤销、到期及源会话删除后，消息、Trace、span、附件和缩略图读取全部失效。
5. 分享模式没有可执行操作；访问不会恢复会话、运行工具、发起 Replay 或修改消息。
6. 正常消息和多层 JSON payload 中的已知凭据字段，在消息、Trace 详情与 Raw 展示中一致屏蔽。
7. Trace 迟到、缺失、归档和附件失效均显示准确状态，不把部分可读称为完整快照。
8. 大会话分页、懒加载、Mongo/Pg store 行为，以及已知平台附件链接改写具有针对性回归覆盖。
