## 5.1 批处理系统概述

### 5.1.1 批处理系统的角色

批处理系统负责高效地处理大量测试项：

```
List<BFCLItem> (测试项列表)
    ↓
BatchProcessor (批处理器)
    ├─ 分割批次
    ├─ 并发执行
    └─ 进度跟踪
    ↓
List<BFCLItemEvalResult> (结果列表)
```

💡 **核心目标**：最大化吞吐量，同时控制资源使用。

### 5.1.2 批处理架构

```
┌─────────────────────────────────────────┐
│         批处理系统层                     │
├─────────────────────────────────────────┤
│  BatchProcessor<T, R>                   │
│  ├─ process(List<T> items)              │
│  ├─ splitIntoBatches(items)             │
│  └─ processBatch(batch)                 │
├─────────────────────────────────────────┤
│  ConcurrentBatchExecutor                │
│  ├─ execute(List<Runnable> tasks)       │
│  ├─ 线程池管理                          │
│  └─ 优雅关闭                            │
└─────────────────────────────────────────┘
```

💡 **设计意图**：分离批处理逻辑和并发执行逻辑，便于独立优化和测试。

### 5.1.3 关键特性

| 特性 | 说明 |
|------|------|
| **批量处理** | 将数据分成批次，避免内存溢出 |
| **并发执行** | 多线程并发处理，提升吞吐量 |
| **进度跟踪** | 实时显示处理进度 |
| **错误隔离** | 单个批次失败不影响其他批次 |
| **优雅关闭** | 等待所有任务完成后关闭 |

## 5.2 BatchProcessor 批处理器

### 5.2.1 类定义

**位置**: `processor/BatchProcessor.java`

```java
public class BatchProcessor<T, R> {
    private static final Logger LOGGER = LoggerFactory.getLogger(BatchProcessor.class);

    private final int batchSize;
    private final int threadPoolSize;
    private final Function<T, R> itemProcessor;
    private final BiConsumer<T, R> resultWriter;

    public BatchProcessor(int batchSize,
                          int threadPoolSize,
                          Function<T, R> itemProcessor,
                          BiConsumer<T, R> resultWriter) {
        this.batchSize = batchSize;
        this.threadPoolSize = threadPoolSize;
        this.itemProcessor = itemProcessor;
        this.resultWriter = resultWriter;
    }
}
```

💡 **泛型参数**：
- `T`：输入项类型（如 BFCLItem）
- `R`：结果类型（如 BFCLItemEvalResult）

💡 **构造参数**：
- `batchSize`：每批处理的数据量
- `threadPoolSize`：并发线程数
- `itemProcessor`：处理单个项的函数
- `resultWriter`：写入结果的函数

### 5.2.2 process() 方法

```java
public void process(List<T> items) {
    if (items.isEmpty()) {
        LOGGER.warn("No items to process");
        return;
    }

    int totalItems = items.size();
    LOGGER.info("Processing {} items with batch size {} and {} threads",
                totalItems, batchSize, threadPoolSize);

    // 1. 分割批次
    List<List<T>> batches = splitIntoBatches(items);
    LOGGER.info("Split into {} batches", batches.size());

    // 2. 创建任务
    AtomicInteger processedCount = new AtomicInteger(0);
    List<Runnable> tasks = new ArrayList<>(batches.size());

    for (int i = 0; i < batches.size(); i++) {
        final int batchIndex = i;
        final List<T> batch = batches.get(i);
        tasks.add(() -> processBatch(batch, batchIndex, processedCount, totalItems));
    }

    // 3. 并发执行
    ConcurrentBatchExecutor executor = ConcurrentBatchExecutor.create(threadPoolSize);
    try {
        LOGGER.info("Starting concurrent batch execution");
        executor.execute(tasks);
        LOGGER.info("All batches completed. Total processed: {}/{}", 
                    processedCount.get(), totalItems);
    } finally {
        executor.shutdown();
    }
}
```

💡 **处理流程**：
1. 检查输入是否为空
2. 将数据分割成批次
3. 为每个批次创建任务
4. 使用并发执行器执行所有任务
5. 等待所有任务完成
6. 优雅关闭执行器

### 5.2.3 splitIntoBatches() 方法

```java
private List<List<T>> splitIntoBatches(List<T> items) {
    int batchCount = (items.size() + batchSize - 1) / batchSize;
    List<List<T>> batches = new ArrayList<>(batchCount);
    
    for (int i = 0; i < items.size(); i += batchSize) {
        int end = Math.min(i + batchSize, items.size());
        batches.add(items.subList(i, end));
    }
    
    return batches;
}
```

💡 **分割逻辑**：
- 计算批次数量：`(size + batchSize - 1) / batchSize`（向上取整）
- 使用 `subList` 分割列表，避免复制数据
- 最后一批可能少于 batchSize

**示例**：
```
输入：100 个项，batchSize = 30
批次 1: [0, 29]    (30 个)
批次 2: [30, 59]   (30 个)
批次 3: [60, 89]   (30 个)
批次 4: [90, 99]   (10 个)
```

### 5.2.4 processBatch() 方法

```java
private void processBatch(List<T> batch, int batchIndex, 
                         AtomicInteger processedCount, int totalItems) {
    try {
        LOGGER.info("Processing batch {} with {} items", batchIndex, batch.size());

        for (T item : batch) {
            // 1. 处理单个项
            R result = itemProcessor.apply(item);
            
            // 2. 写入结果
            resultWriter.accept(item, result);
            
            // 3. 更新进度
            int processed = processedCount.incrementAndGet();
            logProgress(processed, totalItems);
        }

        LOGGER.info("Completed batch {} ({} items)", batchIndex, batch.size());

    } catch (Exception e) {
        LOGGER.error("Error processing batch {}", batchIndex, e);
    }
}
```

💡 **处理逻辑**：
1. 遍历批次中的每个项
2. 调用 `itemProcessor` 处理项
3. 调用 `resultWriter` 写入结果
4. 更新并记录进度
5. 捕获异常，避免影响其他批次

💡 **错误隔离**：单个批次的异常不会中断整个处理流程。

## 5.3 ConcurrentBatchExecutor 并发执行器

### 5.3.1 类定义

**位置**: `executor/ConcurrentBatchExecutor.java`

```java
public class ConcurrentBatchExecutor {
    private static final Logger LOGGER = LoggerFactory.getLogger(ConcurrentBatchExecutor.class);

    public static ConcurrentBatchExecutor create() {
        return new ConcurrentBatchExecutor(Runtime.getRuntime().availableProcessors());
    }

    public static ConcurrentBatchExecutor create(int threadPoolSize) {
        return new ConcurrentBatchExecutor(threadPoolSize);
    }

    private final int threadPoolSize;
    private final ExecutorService executorService;

    public ConcurrentBatchExecutor(int threadPoolSize) {
        this.threadPoolSize = threadPoolSize;
        this.executorService = Executors.newFixedThreadPool(threadPoolSize);
    }
}
```

💡 **工厂方法**：
- `create()`：使用 CPU 核心数作为线程池大小
- `create(int)`：指定线程池大小

💡 **线程池**：使用 `Executors.newFixedThreadPool` 创建固定大小的线程池。

### 5.3.2 execute() 方法

```java
public void execute(List<Runnable> tasks) {
    LOGGER.info("Submitting {} tasks to executor with {} threads", 
                tasks.size(), threadPoolSize);

    // 1. 提交所有任务
    List<CompletableFuture<Void>> futures = tasks.stream()
            .map(task -> CompletableFuture.runAsync(task, executorService))
            .toList();

    // 2. 等待所有任务完成
    CompletableFuture.allOf(futures.toArray(CompletableFuture[]::new)).join();

    LOGGER.info("All {} tasks completed", tasks.size());
}
```

💡 **执行逻辑**：
1. 将每个任务包装为 `CompletableFuture`
2. 使用 `executorService` 异步执行
3. 使用 `allOf` 等待所有任务完成
4. 使用 `join` 阻塞等待

💡 **优势**：
- 使用 `CompletableFuture` 提供灵活的异步编程
- `allOf` 确保所有任务完成
- 异常会被包装并抛出

### 5.3.3 shutdown() 方法

```java
public void shutdown() {
    executorService.shutdown();
    try {
        // 1. 等待 60 秒
        if (!executorService.awaitTermination(60, TimeUnit.SECONDS)) {
            // 2. 强制关闭
            executorService.shutdownNow();
            
            // 3. 再等待 60 秒
            if (!executorService.awaitTermination(60, TimeUnit.SECONDS)) {
                LOGGER.error("ExecutorService did not terminate");
            }
        }
    } catch (InterruptedException e) {
        executorService.shutdownNow();
        Thread.currentThread().interrupt();
    }
}
```

💡 **关闭策略**：
1. 调用 `shutdown()`：停止接受新任务，等待现有任务完成
2. 等待 60 秒
3. 如果超时，调用 `shutdownNow()`：强制中断所有任务
4. 再等待 60 秒
5. 如果仍超时，记录错误
6. 处理中断异常

💡 **优雅关闭**：给任务足够时间完成，避免数据丢失。

### 5.3.4 使用示例

```java
// 创建执行器
ConcurrentBatchExecutor executor = ConcurrentBatchExecutor.create(8);

try {
    // 创建任务列表
    List<Runnable> tasks = new ArrayList<>();
    for (int i = 0; i < 100; i++) {
        final int taskId = i;
        tasks.add(() -> {
            System.out.println("Executing task " + taskId);
            // 执行实际工作
        });
    }
    
    // 执行所有任务
    executor.execute(tasks);
    
} finally {
    // 优雅关闭
    executor.shutdown();
}
```

## 5.4 批处理流程详解

### 5.4.1 完整流程

```
1. 初始化批处理器
   ├─ 设置批次大小
   ├─ 设置线程池大小
   ├─ 设置处理函数
   └─ 设置写入函数
   ↓
2. 分割批次
   ├─ 计算批次数量
   └─ 使用 subList 分割
   ↓
3. 创建任务
   ├─ 为每个批次创建 Runnable
   └─ 捕获批次索引和数据
   ↓
4. 并发执行
   ├─ 提交任务到线程池
   ├─ 使用 CompletableFuture 包装
   └─ 等待所有任务完成
   ↓
5. 处理批次（每个线程）
   ├─ 遍历批次项
   ├─ 调用处理函数
   ├─ 调用写入函数
   └─ 更新进度
   ↓
6. 完成处理
   ├─ 记录统计信息
   └─ 关闭执行器
```

### 5.4.2 数据流示例

```java
// 输入：100 个测试项
List<BFCLItem> items = loadItems(100);

// 创建批处理器
BatchProcessor<BFCLItem, BFCLItemEvalResult> processor = new BatchProcessor<>(
    20,  // 批次大小
    8,   // 线程池大小
    item -> inferenceHandle.handle(item),  // 处理函数
    (item, result) -> writeResult(item, result)  // 写入函数
);

// 执行批处理
processor.process(items);

// 执行过程：
// 批次 0: [0-19]   → 线程 1 处理
// 批次 1: [20-39]  → 线程 2 处理
// 批次 2: [40-59]  → 线程 3 处理
// 批次 3: [60-79]  → 线程 4 处理
// 批次 4: [80-99]  → 线程 5 处理
// 
// 8 个线程并发处理 5 个批次
// 每个批次包含 20 个测试项
// 每个测试项独立推理并写入结果
```

### 5.4.3 线程模型

```
主线程
  │
  ├─ 分割批次
  ├─ 创建任务
  └─ 启动执行器
       │
       ├─ 线程池（8 个线程）
       │   ├─ 线程 1: 处理批次 0
       │   ├─ 线程 2: 处理批次 1
       │   ├─ 线程 3: 处理批次 2
       │   ├─ 线程 4: 处理批次 3
       │   ├─ 线程 5: 处理批次 4
       │   ├─ 线程 6: 空闲
       │   ├─ 线程 7: 空闲
       │   └─ 线程 8: 空闲
       │
       └─ 等待所有任务完成
```

💡 **线程分配**：
- 批次数量 < 线程数：部分线程空闲
- 批次数量 > 线程数：线程轮流处理批次
- 批次数量 = 线程数：每个线程处理一个批次

## 5.5 进度跟踪

### 5.5.1 logProgress() 方法

```java
private void logProgress(int processed, int total) {
    if (processed % 10 == 0 || processed == total) {
        double progress = (double) processed / total * 100;
        String progressBar = generateProgressBar(progress);
        LOGGER.info("Progress: {} [{}/{}]", progressBar, processed, total);
    }
}
```

💡 **触发条件**：
- 每处理 10 项记录一次
- 处理完所有项时记录

💡 **输出格式**：
```
Progress: [=====>                    ] 10.0% [10/100]
Progress: [==========>               ] 20.0% [20/100]
...
Progress: [==========================] 100.0% [100/100]
```

### 5.5.2 generateProgressBar() 方法

```java
private String generateProgressBar(double percentage) {
    int barLength = 30;
    int filled = (int) (barLength * percentage / 100);
    int empty = barLength - filled;

    return "["
            + "=".repeat(Math.max(0, filled))
            + ">".repeat(filled > 0 && empty > 0 ? 1 : 0)
            + " ".repeat(Math.max(0, empty - (filled > 0 && empty > 0 ? 1 : 0)))
            + "]"
            + String.format(" %.1f%%", percentage);
}
```

💡 **进度条组成**：
- `[`：左边界
- `=`：已完成部分
- `>`：当前进度指示器
- ` `：未完成部分
- `]`：右边界
- `xx.x%`：百分比

**示例**：
```
百分比: 33.3%
进度条: [==========>                   ] 33.3%

百分比: 66.7%
进度条: [====================>         ] 66.7%

百分比: 100%
进度条: [==============================] 100.0%
```

### 5.5.3 自定义进度跟踪

```java
public class ProgressTracker {
    private final int total;
    private final AtomicInteger processed = new AtomicInteger(0);
    private final long startTime = System.currentTimeMillis();
    
    public ProgressTracker(int total) {
        this.total = total;
    }
    
    public void increment() {
        int current = processed.incrementAndGet();
        
        if (current % 10 == 0 || current == total) {
            double progress = (double) current / total * 100;
            long elapsed = System.currentTimeMillis() - startTime;
            double speed = current / (elapsed / 1000.0);
            double eta = (total - current) / speed;
            
            System.out.printf("Progress: %.1f%% [%d/%d] Speed: %.1f items/s ETA: %.0fs%n",
                progress, current, total, speed, eta);
        }
    }
}
```

💡 **增强功能**：
- 处理速度（items/s）
- 预计剩余时间（ETA）
- 已用时间

### 5.6.3 重试机制

```java
public class RetryBatchProcessor<T, R> extends BatchProcessor<T, R> {
    private final int maxRetries;
    
    public RetryBatchProcessor(int batchSize, int threadPoolSize,
                               Function<T, R> itemProcessor,
                               BiConsumer<T, R> resultWriter,
                               int maxRetries) {
        super(batchSize, threadPoolSize, itemProcessor, resultWriter);
        this.maxRetries = maxRetries;
    }
    
    @Override
    protected void processBatch(List<T> batch, int batchIndex, 
                               AtomicInteger processedCount, int totalItems) {
        for (T item : batch) {
            int attempts = 0;
            boolean success = false;
            
            while (attempts < maxRetries && !success) {
                try {
                    R result = itemProcessor.apply(item);
                    resultWriter.accept(item, result);
                    processedCount.incrementAndGet();
                    success = true;
                } catch (Exception e) {
                    attempts++;
                    LOGGER.warn("Attempt {} failed for item in batch {}: {}", 
                               attempts, batchIndex, e.getMessage());
                    
                    if (attempts < maxRetries) {
                        try {
                            Thread.sleep(1000 * attempts);  // 指数退避
                        } catch (InterruptedException ie) {
                            Thread.currentThread().interrupt();
                            return;
                        }
                    }
                }
            }
            
            if (!success) {
                LOGGER.error("Failed to process item after {} attempts", maxRetries);
            }
        }
    }
}
```

💡 **增强功能**：
- 自动重试失败项
- 指数退避（1s, 2s, 3s...）
- 最大重试次数限制

## 5.7 性能调优

### 5.7.1 批次大小调优

| 批次大小 | 优点 | 缺点 | 适用场景 |
|---------|------|------|---------|
| **小（10-20）** | 进度更新频繁，内存占用少 | 批次管理开销大 | 数据量小，需要频繁进度更新 |
| **中（50-100）** | 平衡进度更新和管理开销 | 平衡 | 大多数场景 |
| **大（200-500）** | 批次管理开销小 | 进度更新少，内存占用大 | 数据量大，不需要频繁进度更新 |

💡 **建议**：
- 默认使用 50
- 数据量 < 1000：使用 20
- 数据量 > 10000：使用 100

### 5.7.2 线程池大小调优

| 线程池大小 | 优点 | 缺点 | 适用场景 |
|-----------|------|------|---------|
| **小（2-4）** | 资源占用少 | 吞吐量低 | CPU 密集型任务 |
| **中（8-16）** | 平衡 | 平衡 | 大多数场景 |
| **大（32-64）** | 吞吐量高 | 资源占用多 | I/O 密集型任务 |

💡 **建议**：
- CPU 密集型：`Runtime.getRuntime().availableProcessors()`
- I/O 密集型：`availableProcessors() * 2`
- 混合负载：`availableProcessors() * 1.5`

### 5.7.3 内存优化

```java
// 使用流式处理，避免加载所有数据到内存
public void processStream(Stream<T> items) {
    List<T> batch = new ArrayList<>(batchSize);
    
    items.forEach(item -> {
        batch.add(item);
        
        if (batch.size() >= batchSize) {
            processBatch(new ArrayList<>(batch), ...);
            batch.clear();
        }
    });
    
    // 处理剩余项
    if (!batch.isEmpty()) {
        processBatch(batch, ...);
    }
}
```

💡 **优化点**：
- 使用 Stream 延迟加载
- 批次处理，避免内存溢出
- 及时清理批次数据
