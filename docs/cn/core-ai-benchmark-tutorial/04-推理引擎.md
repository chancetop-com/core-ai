## 4.1 推理引擎概述

### 4.1.1 推理引擎的角色

推理引擎是 benchmark 框架的核心组件，负责：

```
BFCLItem (测试输入)
    ↓
推理引擎处理
    ↓
LLM API 调用
    ↓
BFCLItemEvalResult (测试结果)
```

### 4.1.2 推理引擎架构

```
┌─────────────────────────────────────────┐
│         推理引擎层                       │
├─────────────────────────────────────────┤
│  InferenceHandle<T, R>                  │
│  ├─ handle(T item): R                   │
│  └─ 策略接口                            │
├─────────────────────────────────────────┤
│  BFCLInferenceHandle                    │
│  ├─ handle(item)                        │
│  ├─ prepareMessages(item)               │
│  ├─ prepareTools(item)                  │
│  ├─ invoke(id, messages, tools)         │
│  └─ postProcess(result)                 │
├─────────────────────────────────────────┤
│  BFCLInferenceFCHandle                  │
│  └─ invoke() - 函数调用推理             │
├─────────────────────────────────────────┤
│  BFCLInferencePlanHandle                │
│  └─ invoke() - 计划推理                 │
└─────────────────────────────────────────┘
```

💡 **设计意图**：使用模板方法模式，定义统一的推理流程，子类只需实现核心推理逻辑。

### 4.1.3 推理策略对比

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| **FCHandle** | 函数调用推理 | 测试 LLM 的工具调用能力 |
| **PlanHandle** | 计划推理 | 测试 LLM 的规划能力 |

## 4.3 BFCLInferenceHandle 抽象类

### 4.3.1 类定义

**位置**: `inference/BFCLInferenceHandle.java`

```java
public abstract class BFCLInferenceHandle 
    implements InferenceHandle<BFCLItem, BFCLItemEvalResult> {
    
    @Override
    public BFCLItemEvalResult handle(BFCLItem item) {
        // 1. 准备消息
        List<Message> messages = prepareMessages(item);
        
        // 2. 准备工具
        List<Tool> tools = prepareTools(item);
        
        // 3. 调用推理（由子类实现）
        BFCLItemEvalResult result = invoke(item.id, messages, tools);
        
        // 4. 后处理
        return postProcess(result);
    }
    
    // 模板方法：由子类实现
    protected abstract BFCLItemEvalResult invoke(
        String id, 
        List<Message> messages, 
        List<Tool> tools
    );
}
```

💡 **模板方法模式**：
- `handle()` 定义算法骨架
- `invoke()` 由子类实现具体推理逻辑
- 子类无需关心数据准备和后处理

### 4.3.2 prepareMessages() 方法

```java
protected List<Message> prepareMessages(BFCLItem item) {
    List<Message> messages = new ArrayList<>();
    
    // 添加系统提示（可选）
    messages.add(Message.of(RoleType.SYSTEM, 
        "You are a helpful assistant with access to the following functions."));
    
    // 添加多轮对话
    for (List<BFCLItem.Message> turn : item.question) {
        for (BFCLItem.Message msg : turn) {
            Message llmMsg = new Message();
            llmMsg.role = convertRole(msg.role);
            llmMsg.content = msg.content;
            messages.add(llmMsg);
        }
    }
    
    return messages;
}

private String convertRole(String role) {
    return switch (role) {
        case "user" -> "user";
        case "assistant" -> "assistant";
        case "system" -> "system";
        default -> "user";
    };
}
```

💡 **说明**：
- 添加系统提示，引导 LLM 使用工具
- 支持多轮对话
- 转换角色格式

### 4.3.3 prepareTools() 方法

```java
protected List<Tool> prepareTools(BFCLItem item) {
    List<Tool> tools = new ArrayList<>();
    
    for (FunctionDefinition funcDef : item.function) {
        Tool tool = new Tool();
        tool.type = "function";
        
        Function function = new Function();
        function.name = funcDef.name;
        function.description = funcDef.description;
        function.parameters = convertParameters(funcDef.parameters);
        
        tool.function = function;
        tools.add(tool);
    }
    
    return tools;
}

private JsonSchema convertParameters(Parameters params) {
    if (params == null) {
        return null;
    }
    
    JsonSchema schema = new JsonSchema();
    schema.type = params.type;
    schema.required = params.required;
    schema.properties = new LinkedHashMap<>();
    
    for (Map.Entry<String, JsonPropertyInfo> entry : params.properties.entrySet()) {
        schema.properties.put(entry.getKey(), convertProperty(entry.getValue()));
    }
    
    return schema;
}

private JsonSchema convertProperty(JsonPropertyInfo prop) {
    JsonSchema schema = new JsonSchema();
    schema.type = prop.type;
    schema.description = prop.description;
    
    if (prop.enumValues != null) {
        schema.enumValues = prop.enumValues;
    }
    
    if (prop.defaultValue != null) {
        schema.defaultValue = prop.defaultValue;
    }
    
    if (prop.properties != null) {
        schema.properties = new LinkedHashMap<>();
        for (Map.Entry<String, JsonPropertyInfo> entry : prop.properties.entrySet()) {
            schema.properties.put(entry.getKey(), convertProperty(entry.getValue()));
        }
    }
    
    if (prop.items != null) {
        schema.items = convertProperty(prop.items);
    }
    
    return schema;
}
```

💡 **说明**：
- 将 BFCL 函数定义转换为 LLM Tool 格式
- 递归转换参数定义
- 支持嵌套对象和数组

## 4.4 BFCLInferenceFCHandle 实现

### 4.4.1 类定义

**位置**: `inference/BFCLInferenceFCHandle.java`

```java
public class BFCLInferenceFCHandle extends BFCLInferenceHandle {
    final LLMProvider llmProvider;

    public BFCLInferenceFCHandle(LLMProvider llmProvider) {
        this.llmProvider = llmProvider;
    }

    @Override
    protected BFCLItemEvalResult invoke(String id, List<Message> messages, List<Tool> tools) {
        // 1. 构建请求
        var request = CompletionRequest.of(
            messages, 
            tools, 
            llmProvider.config.getTemperature(), 
            llmProvider.config.getModel(), 
            "eval-req"
        );
        
        // 2. 调用 LLM
        var resp = invokeLLM(request);
        
        // 3. 转换响应
        return fromCompletionResponse(resp, id);
    }
}
```

💡 **说明**：FCHandle 专注于函数调用推理，测试 LLM 的工具调用能力。

### 4.4.2 invokeLLM() 方法

```java
private CompletionResponseWithLatency invokeLLM(CompletionRequest request) {
    long startTime = System.currentTimeMillis();
    
    // 调用 LLM API
    var completionResponse = llmProvider.completion(request);
    
    long endTime = System.currentTimeMillis();
    double latency = (endTime - startTime) / 1000.0;
    
    return CompletionResponseWithLatency.of(completionResponse, latency);
}
```

💡 **说明**：
- 记录推理开始和结束时间
- 计算延迟（秒）
- 封装响应和延迟信息

### 4.4.3 fromCompletionResponse() 方法

```java
private BFCLItemEvalResult fromCompletionResponse(
    CompletionResponseWithLatency completionResponseWithLatency, 
    String id
) {
    List<Map<String, Object>> result = Lists.newArrayList();
    var rawRes = completionResponseWithLatency.response;
    
    // 提取工具调用
    if (rawRes.choices.getFirst().finishReason == FinishReason.TOOL_CALLS) {
        var tools = rawRes.choices.getFirst().message.toolCalls;
        tools.stream()
            .map(tool -> Map.of(tool.function.name, (Object) tool.function.arguments))
            .forEach(result::add);
    }
    
    // 如果没有工具调用，使用文本输出
    if (result.isEmpty()) {
        result.add(Map.of("output", rawRes.choices.getFirst().message.content));
    }
    
    // 创建结果对象
    return BFCLItemEvalResult.of(
        id,
        result,
        rawRes.usage.getPromptTokens(),
        rawRes.usage.getCompletionTokens(),
        completionResponseWithLatency.latency
    );
}
```

💡 **转换逻辑**：
1. 检查结束原因是否为 TOOL_CALLS
2. 提取工具调用列表
3. 每个工具调用转换为 `{函数名: 参数}` 格式
4. 如果没有工具调用，使用文本输出
5. 提取 Token 使用量和延迟

### 4.4.4 CompletionResponseWithLatency 内部类

```java
static class CompletionResponseWithLatency {
    static CompletionResponseWithLatency of(CompletionResponse response, Double latency) {
        var cl = new CompletionResponseWithLatency();
        cl.response = response;
        cl.latency = latency;
        return cl;
    }
    
    CompletionResponse response;
    Double latency;
}
```

💡 **用途**：封装 LLM 响应和延迟信息，便于传递。

### 4.4.5 使用示例


## 4.5 BFCLInferencePlanHandle 实现

### 4.5.1 类定义

**位置**: `inference/BFCLInferencePlanHandle.java`

```java
public class BFCLInferencePlanHandle extends BFCLInferenceHandle {
    final LLMProvider llmProvider;

    public BFCLInferencePlanHandle(LLMProvider llmProvider) {
        this.llmProvider = llmProvider;
    }

    @Override
    protected BFCLItemEvalResult invoke(String id, List<Message> messages, List<Tool> tools) {
        // 1. 添加规划提示
        List<Message> planMessages = addPlanningPrompt(messages);
        
        // 2. 构建请求
        var request = CompletionRequest.of(
            planMessages, 
            tools, 
            llmProvider.config.getTemperature(), 
            llmProvider.config.getModel(), 
            "eval-req"
        );
        
        // 3. 调用 LLM
        long startTime = System.currentTimeMillis();
        var completionResponse = llmProvider.completion(request);
        long endTime = System.currentTimeMillis();
        double latency = (endTime - startTime) / 1000.0;
        
        // 4. 转换响应
        return fromPlanResponse(completionResponse, id, latency);
    }
    
    private List<Message> addPlanningPrompt(List<Message> messages) {
        List<Message> planMessages = new ArrayList<>(messages);
        
        // 在系统提示后添加规划指令
        planMessages.add(1, Message.of(RoleType.SYSTEM, 
            "Before using any functions, please provide a step-by-step plan."));
        
        return planMessages;
    }
    
    private BFCLItemEvalResult fromPlanResponse(
        CompletionResponse response, 
        String id, 
        double latency
    ) {
        // 类似 FCHandle，但可能包含额外的规划信息
        List<Map<String, Object>> result = Lists.newArrayList();
        
        if (response.choices.getFirst().finishReason == FinishReason.TOOL_CALLS) {
            var tools = response.choices.getFirst().message.toolCalls;
            tools.stream()
                .map(tool -> Map.of(tool.function.name, (Object) tool.function.arguments))
                .forEach(result::add);
        }
        
        if (result.isEmpty()) {
            result.add(Map.of("output", response.choices.getFirst().message.content));
        }
        
        return BFCLItemEvalResult.of(
            id,
            result,
            response.usage.getPromptTokens(),
            response.usage.getCompletionTokens(),
            latency
        );
    }
}
```

💡 **说明**：PlanHandle 在推理前添加规划提示，测试 LLM 的规划能力。

### 4.5.2 FCHandle vs PlanHandle

| 特性 | FCHandle | PlanHandle |
|------|----------|------------|
| **目标** | 测试函数调用 | 测试规划能力 |
| **提示** | 标准系统提示 | 添加规划指令 |
| **输出** | 函数调用列表 | 规划 + 函数调用 |
| **适用场景** | 工具调用评估 | 复杂任务评估 |

## 4.6 推理流程详解

### 4.6.1 完整流程

```
1. 加载测试数据
   ↓
2. 准备消息 (prepareMessages)
   ├─ 添加系统提示
   └─ 转换多轮对话
   ↓
3. 准备工具 (prepareTools)
   ├─ 转换函数定义
   └─ 构建 JSON Schema
   ↓
4. 构建 LLM 请求
   ├─ 设置消息列表
   ├─ 设置工具列表
   ├─ 设置温度参数
   └─ 设置模型名称
   ↓
5. 调用 LLM API
   ├─ 发送 HTTP 请求
   └─ 记录延迟时间
   ↓
6. 解析 LLM 响应
   ├─ 检查结束原因
   ├─ 提取工具调用
   └─ 提取 Token 使用量
   ↓
7. 创建评估结果
   ├─ 设置 ID
   ├─ 设置结果
   ├─ 设置 Token 统计
   └─ 设置延迟
   ↓
8. 返回结果
```

### 4.6.3 错误处理

```java
protected BFCLItemEvalResult invoke(String id, List<Message> messages, List<Tool> tools) {
    try {
        var request = CompletionRequest.of(messages, tools, ...);
        var resp = invokeLLM(request);
        return fromCompletionResponse(resp, id);
    } catch (Exception e) {
        // 记录错误

        // 返回错误结果
        return BFCLItemEvalResult.of(
            id,
            List.of(Map.of("error", e.getMessage())),
            0,
            0,
            0.0
        );
    }
}
```

💡 **错误处理策略**：
- 捕获异常，避免中断整个测试
- 记录错误信息
- 返回包含错误信息的结果对象

## 4.7 性能优化

### 4.7.1 批量推理

```java
public class BatchInferenceHandle extends BFCLInferenceHandle {
    private final LLMProvider llmProvider;
    private final int batchSize;
    
    public BatchInferenceHandle(LLMProvider llmProvider, int batchSize) {
        this.llmProvider = llmProvider;
        this.batchSize = batchSize;
    }
    
    public List<BFCLItemEvalResult> handleBatch(List<BFCLItem> items) {
        // 分批处理
        List<BFCLItemEvalResult> results = new ArrayList<>();
        
        for (int i = 0; i < items.size(); i += batchSize) {
            int end = Math.min(i + batchSize, items.size());
            List<BFCLItem> batch = items.subList(i, end);
            
            // 并发处理批次
            List<CompletableFuture<BFCLItemEvalResult>> futures = batch.stream()
                .map(item -> CompletableFuture.supplyAsync(() -> handle(item)))
                .toList();
            
            // 等待批次完成
            futures.forEach(f -> results.add(f.join()));
        }
        
        return results;
    }
}
```

💡 **优化点**：
- 分批处理，避免一次性加载所有数据
- 并发推理，提升吞吐量
- 控制并发度，避免触发速率限制

### 4.7.2 缓存机制

```java
public class CachedInferenceHandle extends BFCLInferenceHandle {
    private final BFCLInferenceHandle delegate;
    private final Map<String, BFCLItemEvalResult> cache;
    
    public CachedInferenceHandle(BFCLInferenceHandle delegate) {
        this.delegate = delegate;
        this.cache = new ConcurrentHashMap<>();
    }
    
    @Override
    public BFCLItemEvalResult handle(BFCLItem item) {
        // 检查缓存
        BFCLItemEvalResult cached = cache.get(item.id);
        if (cached != null) {
            LOGGER.info("Cache hit for item: {}", item.id);
            return cached;
        }
        
        // 调用委托处理
        BFCLItemEvalResult result = delegate.handle(item);
        
        // 存入缓存
        cache.put(item.id, result);
        
        return result;
    }
}
```

💡 **优化点**：
- 避免重复推理相同测试项
- 使用 ConcurrentHashMap 保证线程安全
- 支持断点续传

### 4.7.3 重试机制

```java
public class RetryInferenceHandle extends BFCLInferenceHandle {
    private final BFCLInferenceHandle delegate;
    private final int maxRetries;
    private final long retryDelayMs;
    
    public RetryInferenceHandle(BFCLInferenceHandle delegate, int maxRetries, long retryDelayMs) {
        this.delegate = delegate;
        this.maxRetries = maxRetries;
        this.retryDelayMs = retryDelayMs;
    }
    
    @Override
    public BFCLItemEvalResult handle(BFCLItem item) {
        int attempts = 0;
        
        while (attempts < maxRetries) {
            try {
                return delegate.handle(item);
            } catch (Exception e) {
                attempts++;
                LOGGER.warn("Attempt {} failed for item {}: {}", 
                    attempts, item.id, e.getMessage());
                
                if (attempts >= maxRetries) {
                    throw e;
                }
                
                // 等待后重试
                try {
                    Thread.sleep(retryDelayMs * attempts);  // 指数退避
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw new RuntimeException(ie);
                }
            }
        }
        
        throw new RuntimeException("Max retries exceeded");
    }
}
```

💡 **优化点**：
- 自动重试失败请求
- 指数退避，避免频繁重试
- 可配置最大重试次数和延迟
