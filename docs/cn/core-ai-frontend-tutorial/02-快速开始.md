## 0.1 开发命令速查

| 命令 | 说明 | 输出 |
|------|------|------|
| `npm run dev` | 启动开发服务器 | http://localhost:3000 |
| `npm run build` | 构建生产版本 | `build/dist/` 目录 |
| `npm test` | 运行单元测试 | Vitest 测试报告 |
| `npm run lint` | 代码风格检查 | ESLint 报告 |
| `npm run preview` | 预览生产构建 | http://localhost:4173 |

💡 **设计意图**：每个命令职责单一。`dev` 用于日常开发（带 HMR 热更新），`build` 用于生成部署产物，`test` 用于质量保证，`lint` 用于代码规范。

## 0.2 首次运行

### 0.2.1 安装依赖

```bash
# 进入前端项目目录
cd core-ai-frontend

# 安装依赖
npm install

# 安装成功后会看到类似：
# added 320 packages in 12s
```

💡 **设计意图**：`npm install` 读取 `package.json` 和 `package-lock.json`，安装精确版本的依赖。lock 文件确保团队所有成员使用完全相同的依赖版本。

### 0.2.2 确认后端服务

前端依赖后端 API（默认 `http://localhost:8080`）。启动前端之前，确保后端正在运行：

```bash
# 检查后端是否运行
curl http://localhost:8080/api/health

# 如果返回 200，说明后端正常
# 如果连接失败，先启动后端服务
```

如果你的后端运行在其他端口或地址，需要修改 `vite.config.ts` 中的 `API_TARGET`：

```ts
// vite.config.ts
const API_TARGET = 'http://localhost:8080' // 修改为你的后端地址
```

### 0.2.3 启动开发服务器

```bash
# 启动开发服务器
npm run dev

# 输出示例：
#   VITE v8.0.0  ready in 500 ms
#
#   ➜  Local:   http://localhost:3000/
#   ➜  Network: use --host to expose
#   ➜  press h + enter to show help
```

打开浏览器访问 http://localhost:3000

### 0.2.4 登录流程

首次访问时，根据后端配置有两种情况：

**情况 A：需要认证**

```
http://localhost:3000
  → 自动重定向到 /login
  → 输入用户名和密码
  → 登录成功 → 重定向到 /for-you（仪表盘）
```

**情况 B：无需认证**

```
http://localhost:3000
  → 自动以 'local' 用户登录
  → 直接进入 /for-you（仪表盘）
```

💡 **设计意图**：开发环境默认支持无认证模式，降低本地开发门槛。生产环境通过后端配置启用认证。

## 0.3 核心页面导览

### 0.3.1 /for-you — 仪表盘

仪表盘是登录后的默认页面，展示个人概览信息：

- 最近的活动和会话
- 常用功能快捷入口
- 系统通知

💡 **设计意图**：作为用户的"首页"，提供全局视图和快速导航，减少找到核心功能的路径。

### 0.3.2 /chat — 对话页面

对话页面是与 AI 交互的核心界面：

- 支持多轮对话
- SSE 流式输出，实时显示 AI 回复
- 支持文件上传
- 对话历史管理

💡 **设计意图**：Chat 是最高频使用的页面，流式输出让用户在等待 AI 回复时不会感到焦虑，文件上传扩展了交互维度。

### 0.3.3 /agents — Agent 管理

管理 AI Agent 的页面：

- 创建新 Agent
- 编辑 Agent 配置（模型、系统提示词、工具等）
- 查看 Agent 列表
- 删除 Agent

💡 **设计意图**：Agent 是 core-ai 的核心概念，这个页面提供了完整的 Agent 生命周期管理。

### 0.3.4 /workflows — 工作流编辑器

可视化工作流编辑器，基于 `@xyflow/react`：

- 拖拽节点创建流程
- 连接节点定义数据流
- 配置节点参数
- 运行和调试工作流

💡 **设计意图**：工作流将复杂的多步骤任务可视化，降低编排门槛。基于 xyflow 的编辑器提供了流畅的拖拽体验。

### 0.3.5 /traces — Trace 查看器

查看 AI 调用链追踪：

- 按时间线展示调用过程
- 每个步骤的耗时、输入输出
- 错误追踪和诊断

💡 **设计意图**：Trace 是调试和优化 AI 应用的关键工具，通过可视化调用链，开发者可以快速定位性能瓶颈和错误。

### 0.3.6 /settings — 系统设置

系统级配置管理：

- API Keys 管理
- 网关配置
- 系统参数
- 费用告警
- 用户管理
- 任务管理

💡 **设计意图**：将管理员功能集中在 Settings 下，普通用户只看得到自己权限范围内的配置项。

## 0.4 Vite 配置详解

### 0.4.1 完整配置概览

```ts
// core-ai-frontend/vite.config.ts (简化)
import { defineConfig } from 'vite'
import react from '@vitejs/plugin-react'

const API_TARGET = 'http://localhost:8080'

export default defineConfig({
  plugins: [react()],
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: API_TARGET,
        changeOrigin: true,
        configure: (proxy) => {
          // SSE 流式响应处理
          proxy.on('proxyRes', (proxyRes) => {
            const contentType = proxyRes.headers['content-type'] || ''
            if (contentType.includes('text/event-stream')) {
              // 禁用缓存和缓冲
              proxyRes.headers['cache-control'] = 'no-cache'
              proxyRes.headers['x-accel-buffering'] = 'no'
            }
          })
        },
      },
    },
  },
  build: {
    outDir: 'build/dist',
    rollupOptions: {
      output: {
        manualChunks: {
          // 将大依赖拆分为独立 chunk
          recharts: ['recharts'],
          codemirror: ['@codemirror/view', '@codemirror/commands'],
          markdown: ['react-markdown'],
          speech: ['speech-synthesis'],
        },
      },
    },
    modulePreload: {
      // 排除重型 chunk 的预加载，减少首屏负担
      resolveDependencies: (filename, deps) => {
        const exclude = ['recharts', 'codemirror', 'markdown', 'speech']
        return deps.filter(d => !exclude.some(e => filename.includes(e)))
      },
    },
  },
})
```

💡 **设计意图**：配置分三块——开发服务器（代理 + SSE）、构建产物（代码分割）、预加载策略（优化首屏）。重型库（recharts、codemirror 等）被拆分为独立 chunk 且不在首屏预加载，只在真正需要时才下载。

### 0.4.2 代理与 SSE 处理

开发环境下，所有 `/api` 开头的请求被代理到后端。SSE（Server-Sent Events）需要特殊处理：

```
浏览器 → http://localhost:3000/api/chat/stream
                │
                ▼ (Vite Proxy)
        http://localhost:8080/api/chat/stream
                │
                ▼ (SSE 响应)
        Content-Type: text/event-stream
        Cache-Control: no-cache
                │
                ▼ (代理回浏览器)
        逐 token 流式输出
```

💡 **设计意图**：如果不禁用代理缓冲，Nginx 或中间件可能会攒一批 token 再发送，导致用户看到的输出"一顿一顿"的。设置 `no-cache` 和 `no-proxy-buffering` 确保 token 实时到达。

### 0.4.3 代码分割策略

```ts
manualChunks: {
  recharts: ['recharts'],          // 图表库 ~200KB
  codemirror: ['@codemirror/view'], // 代码编辑器 ~150KB
  markdown: ['react-markdown'],     // Markdown 渲染 ~80KB
  speech: ['speech-synthesis'],     // 语音合成 ~50KB
}
```

💡 **设计意图**：这些库只在特定页面使用（如 recharts 在 Dashboard、codemirror 在 Agent 编辑），拆分后首屏不需要下载它们，节省 400KB+ 的初始加载。

## 0.5 常见问题排查

### 0.5.1 端口被占用

```bash
# 错误：Port 3000 is already in use

# 方案 1：杀掉占用进程
lsof -ti:3000 | xargs kill -9

# 方案 2：使用其他端口
npm run dev -- --port 3001
```

### 0.5.2 后端连接失败

```bash
# 错误：502 Bad Gateway (代理到后端失败)

# 1. 检查后端是否运行
curl http://localhost:8080/api/health

# 2. 如果后端在其他端口，修改 vite.config.ts
# const API_TARGET = 'http://localhost:你的端口'

# 3. 重启开发服务器
```

### 0.5.3 登录页面无限循环

```bash
# 可能原因：token 过期但未被清理

# 1. 清理浏览器存储
# 开发者工具 → Application → Local Storage → 清除所有

# 2. 刷新页面重新登录
```

### 0.5.4 热更新不生效

```bash
# 1. 检查文件是否保存
# 2. 检查终端是否有编译错误
# 3. 重启开发服务器
npm run dev
```

### 0.5.5 构建失败

```bash
# 1. 清理缓存
rm -rf node_modules/.vite
rm -rf build/

# 2. 重新安装依赖
rm -rf node_modules package-lock.json
npm install

# 3. 重新构建
npm run build
```
