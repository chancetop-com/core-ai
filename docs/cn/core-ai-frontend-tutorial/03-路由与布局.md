## 0.1 路由系统概览

core-ai-frontend 使用 `react-router-dom` v7 管理客户端路由。整个路由系统有几个核心特征：

- **全量懒加载**：所有页面组件通过 `React.lazy` 按需加载
- **三重保护**：公开路由、权限守卫、能力门控
- **嵌套布局**：Layout 组件包裹所有受保护页面
- **特殊路由**：共享制品链接绕过认证

```
BrowserRouter
  └── Routes
       ├── /login                ← 公开，无需认证
       ├── /shared/artifacts/:token ← 公开，特殊用途
       └── Layout (受保护)
            ├── /for-you         ← 需 dashboard.view 权限
            ├── /chat            ← 需 chat.use 权限 + caps.chat
            ├── /agents          ← 需 agent.view 权限
            ├── /workflows       ← 需 workflow.view 权限
            ├── /traces          ← 需 trace.view 权限 + caps.traces
            ├── /settings/*      ← 设置子路由
            └── /*               ← 默认重定向到 /for-you
```

💡 **设计意图**：路由即文档。通过观察路由定义，就能快速了解应用有哪些页面、哪些需要认证、哪些需要特定权限。

## 0.2 App.tsx 路由定义

### 0.2.1 基本结构

```tsx
// core-ai-frontend/src/App.tsx (路由部分简化)
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom'
import { Suspense, lazy } from 'react'
import Layout from './components/Layout'
import ErrorBoundary from './components/ErrorBoundary'
import PageFallback from './components/PageFallback'

// 所有页面组件懒加载
const Login = lazy(() => import('./pages/login/Login'))
const Dashboard = lazy(() => import('./pages/for-you/Dashboard'))
const Chat = lazy(() => import('./pages/chat/Chat'))
const Agents = lazy(() => import('./pages/agents/Agents'))
const Workflows = lazy(() => import('./pages/workflows/Workflows'))
const Traces = lazy(() => import('./pages/traces/Traces'))
const SystemPrompts = lazy(() => import('./pages/prompts/SystemPrompts'))
const Skills = lazy(() => import('./pages/skills/Skills'))
const Tools = lazy(() => import('./pages/tools/Tools'))
const Datasets = lazy(() => import('./pages/datasets/Datasets'))
const Projects = lazy(() => import('./pages/projects/Projects'))
const Experiments = lazy(() => import('./pages/experiments/Experiments'))
const Settings = lazy(() => import('./pages/settings/Settings'))
const SharedArtifact = lazy(() => import('./pages/shared/SharedArtifact'))

function App() {
  return (
    <BrowserRouter>
      <Routes>
        {/* 公开路由 */}
        <Route path="/login" element={<Login />} />
        <Route path="/shared/artifacts/:token" element={<SharedArtifact />} />

        {/* 受保护路由 - 包裹在 Layout 中 */}
        <Route element={
          <ErrorBoundary>
            <Layout />
          </ErrorBoundary>
        }>
          <Route path="/for-you" element={<Dashboard />} />
          <Route path="/chat" element={<Chat />} />
          <Route path="/agents" element={<Agents />} />
          <Route path="/workflows" element={<Workflows />} />
          <Route path="/traces" element={<Traces />} />
          <Route path="/system-prompts" element={<SystemPrompts />} />
          <Route path="/skills" element={<Skills />} />
          <Route path="/tools" element={<Tools />} />
          <Route path="/datasets" element={<Datasets />} />
          <Route path="/projects" element={<Projects />} />
          <Route path="/experiments" element={<Experiments />} />

          {/* Settings 子路由 */}
          <Route path="/settings" element={<Settings />}>
            <Route path="api-keys" element={<ApiKeys />} />
            <Route path="gateway" element={<Gateway />} />
            <Route path="system" element={<System />} />
            <Route path="cost-alerts" element={<CostAlerts />} />
            <Route path="users" element={<Users />} />
            <Route path="tasks" element={<Tasks />} />
          </Route>
        </Route>

        {/* 默认重定向 */}
        <Route path="*" element={<Navigate to="/for-you" replace />} />
      </Routes>
    </BrowserRouter>
  )
}
```

💡 **设计意图**：所有页面统一懒加载，`ErrorBoundary` 包裹 Layout 防止局部错误导致白屏。Settings 使用嵌套路由，子页面共享 Settings 的侧边栏。

## 0.3 懒加载与代码分割

### 0.3.1 React.lazy 的使用

```tsx
// 每个页面都通过 lazy() 包裹
const Chat = lazy(() => import('./pages/chat/Chat'))
const Agents = lazy(() => import('./pages/agents/Agents'))

// lazy() 返回一个特殊组件，首次渲染时触发动态 import()
// Vite 将每个 import() 打包为独立 chunk
```

💡 **设计意图**：`React.lazy` 让每个页面成为独立 chunk，首屏只下载当前路由对应的代码。用户导航到新页面时才下载对应 chunk，实现"按需加载"。

### 0.3.2 Suspense 降级 UI

```tsx
// Suspense 包裹所有懒加载组件
<Suspense fallback={<PageFallback />}>
  <Routes>...</Routes>
</Suspense>

// PageFallback 组件 — 加载时显示的占位 UI
function PageFallback() {
  return (
    <div className="flex items-center justify-center h-screen">
      <div className="text-gray-500">Loading...</div>
    </div>
  )
}
```

💡 **设计意图**：`Suspense` 捕获 lazy 组件的加载状态，`PageFallback` 提供友好的加载提示。没有 Suspense 的话，lazy 组件加载时会白屏。

### 0.3.3 代码分割效果

```
首屏加载 (访问 /for-you)：
  ├── main.js         ~50KB   (React + 核心)
  ├── vendor.js       ~100KB  (react-router-dom 等)
  ├── Layout.js       ~30KB   (布局组件)
  └── Dashboard.js    ~20KB   (当前页面)
  总计: ~200KB

延迟加载 (用户点击 /chat)：
  └── Chat.js         ~80KB   (流式聊天相关)

延迟加载 (用户打开 /workflows)：
  ├── Workflows.js    ~60KB
  ├── xyflow.js       ~150KB  (流程图库)
  └── codemirror.js   ~150KB  (代码编辑器)
```

💡 **设计意图**：首屏 200KB 保证了快速加载，重型库（xyflow、codemirror）只在需要时下载。对于不访问工作流的用户，永远不会下载这些代码。

## 0.4 认证与能力门控

### 0.4.1 启动时认证流程

```tsx
// App.tsx 中的认证逻辑
function App() {
  const [caps, setCaps] = useState(null)
  const [user, setUser] = useState(() => {
    const stored = localStorage.getItem('user')
    return stored ? JSON.parse(stored) : null
  })
  const [loading, setLoading] = useState(true)

  useEffect(() => {
    async function init() {
      try {
        // 1. 获取系统能力
        const capsData = await fetch('/api/capabilities').then(r => r.json())
        setCaps(capsData)

        // 2. 检查是否需要认证
        if (capsData.authRequired && !user) {
          // 需要认证但没有用户信息 → 跳转登录
          window.location.href = '/login'
          return
        }
      } catch (err) {
        console.error('Init failed:', err)
      } finally {
        setLoading(false)
      }
    }
    init()
  }, [])

  if (loading) return <PageFallback />

  return (
    <AuthContext.Provider value={{ user, setUser }}>
      <CapabilitiesContext.Provider value={caps}>
        {/* 路由定义 */}
      </CapabilitiesContext.Provider>
    </AuthContext.Provider>
  )
}
```

💡 **设计意图**：启动时一次性获取 Capabilities 和用户状态，通过 Context 传递给所有子组件。子组件不需要重复请求，也避免了认证状态的竞态条件。

### 0.4.2 能力门控路由

某些功能需要后端启用才显示：

```tsx
// 只有后端启用 chat 功能时，/chat 路由才存在
{caps?.chat && (
  <Route path="/chat" element={
    <RequirePermission permission="chat.use">
      <Chat />
    </RequirePermission>
  } />
)}

// 只有后端启用 traces 功能时，/traces 路由才存在
{caps?.traces && (
  <Route path="/traces" element={
    <RequirePermission permission="trace.view">
      <Traces />
    </RequirePermission>
  } />
)}

// 只有后端启用 systemPrompts 功能时，/system-prompts 路由才存在
{caps?.systemPrompts && (
  <Route path="/system-prompts" element={
    <RequirePermission permission="prompt.view">
      <SystemPrompts />
    </RequirePermission>
  } />
)}
```

💡 **设计意图**：能力门控是"功能开关"——后端可以动态启用/禁用功能模块。即使前端代码包含了该页面，如果后端未启用对应功能，路由根本不会注册，用户也无法访问。

## 0.5 权限守卫组件

### 0.5.1 RequirePermission 实现

```tsx
// core-ai-frontend/src/components/RequirePermission.tsx
import { usePermissions } from '../hooks/usePermissions'

interface RequirePermissionProps {
  permission: string
  children: React.ReactNode
}

export function RequirePermission({ permission, children }: RequirePermissionProps) {
  const { hasPermission } = usePermissions()

  if (!hasPermission(permission)) {
    return (
      <div className="flex items-center justify-center h-full">
        <div className="text-center">
          <h2 className="text-xl font-bold text-gray-700">无权限访问</h2>
          <p className="text-gray-500 mt-2">请联系管理员获取 "{permission}" 权限</p>
        </div>
      </div>
    )
  }

  return <>{children}</>
}
```

💡 **设计意图**：声明式权限控制——在 JSX 中直接表达"这个页面需要这个权限"，比命令式的 `if (!hasPermission) redirect` 更直观。

### 0.5.2 使用示例

```tsx
// 在路由中使用
<Route path="/chat" element={
  <RequirePermission permission="chat.use">
    <Chat />
  </RequirePermission>
} />

// 在页面内使用（保护局部功能）
function Agents() {
  return (
    <div>
      <h1>Agent 管理</h1>
      <RequirePermission permission="agent.create">
        <button>创建 Agent</button>
      </RequirePermission>
    </div>
  )
}
```

💡 **设计意图**：`RequirePermission` 既可以保护整个页面（路由级），也可以保护页面内的局部功能（组件级），实现细粒度的权限控制。

## 0.6 Layout.tsx 布局实现

### 0.6.1 整体结构

```tsx
// core-ai-frontend/src/components/Layout.tsx
import { useState, useEffect } from 'react'
import { Outlet, useLocation, Link, Navigate } from 'react-router-dom'
import { useTheme } from '../hooks/useTheme'
import { useAuth } from '../hooks/useAuth'
import { useCapabilities } from '../hooks/useCapabilities'

// 侧边栏宽度常量
const SIDEBAR_WIDTH = {
  collapsed: 60,   // 折叠状态：只显示图标
  expanded: 224,   // 展开状态：显示图标 + 文字
}

export default function Layout() {
  const [collapsed, setCollapsed] = useState(false)
  const { theme, toggleTheme } = useTheme()
  const { user, logout } = useAuth()
  const caps = useCapabilities()
  const location = useLocation()

  // 动态设置页面标题
  useEffect(() => {
    const title = getPageTitle(location.pathname)
    document.title = `${title} - Core AI`
  }, [location.pathname])

  // 认证检查
  if (!user) {
    return <Navigate to="/login" replace />
  }

  return (
    <div className="flex h-screen bg-gray-50 dark:bg-gray-900">
      {/* 侧边栏 */}
      <Sidebar collapsed={collapsed} theme={theme} user={user}>
        <NavItems collapsed={collapsed} caps={caps} currentPath={location.pathname} />
        <SidebarFooter
          collapsed={collapsed}
          user={user}
          theme={theme}
          onToggleTheme={toggleTheme}
          onLogout={logout}
          onToggleCollapse={() => setCollapsed(!collapsed)}
        />
      </Sidebar>

      {/* 主内容区 */}
      <main
        className="flex-1 overflow-auto transition-all duration-300"
        style={{ marginLeft: 0 }}
      >
        <Outlet />
      </main>
    </div>
  )
}
```

💡 **设计意图**：Layout 采用经典的"侧边栏 + 主内容"布局。`<Outlet />` 是 react-router 的插槽，渲染当前路由匹配的页面组件。`transition-all` 让侧边栏折叠/展开有流畅动画。

### 0.7.2 导航渲染与权限过滤

```tsx
function NavItems({ collapsed, caps, currentPath }) {
  const { hasPermission } = usePermissions()

  // 过滤：只显示用户有权限且后端已启用的导航项
  const visibleItems = navItems.filter(item => {
    // 权限检查
    if (!hasPermission(item.permission)) return false
    // 能力检查
    if (item.capability && !caps?.[item.capability]) return false
    return true
  })

  return (
    <ul className="space-y-1 p-2">
      {visibleItems.map(item => (
        <NavItemComponent
          key={item.path}
          item={item}
          collapsed={collapsed}
          isActive={isRouteActive(currentPath, item.path)}
        />
      ))}
    </ul>
  )
}
```

💡 **设计意图**：导航项在渲染前过滤，用户只能看到自己有权限访问的菜单项。这避免了"幽灵入口"——用户点击后才发现无权限的糟糕体验。

### 0.7.3 活跃路由检测

```tsx
// 判断当前路由是否匹配导航项
function isRouteActive(currentPath: string, itemPath: string): boolean {
  // 精确匹配
  if (currentPath === itemPath) return true

  // 前缀匹配（处理子路由）
  // 例如 /triggers/webhook 匹配 /triggers
  if (currentPath.startsWith(itemPath + '/')) return true

  return false
}
```

💡 **设计意图**：活跃状态用于高亮当前导航项。前缀匹配确保访问 `/triggers/webhook` 时，父菜单 `/triggers` 也会高亮。

### 0.7.4 子菜单展开

```tsx
function NavItemComponent({ item, collapsed, isActive }) {
  const [expanded, setExpanded] = useState(isActive)

  if (item.children) {
    return (
      <li>
        <button onClick={() => setExpanded(!expanded)}>
          <item.icon className="w-5 h-5" />
          {!collapsed && <span>{item.label}</span>}
          {!collapsed && <ChevronDown className={expanded ? 'rotate-180' : ''} />}
        </button>
        {expanded && !collapsed && (
          <ul className="ml-4 space-y-1">
            {item.children.map(child => (
              <li key={child.path}>
                <Link to={child.path}>{child.label}</Link>
              </li>
            ))}
          </ul>
        )}
      </li>
    )
  }

  return (
    <li>
      <Link to={item.path} className={isActive ? 'bg-blue-50 text-blue-600' : ''}>
        <item.icon className="w-5 h-5" />
        {!collapsed && <span>{item.label}</span>}
      </Link>
    </li>
  )
}
```

💡 **设计意图**：子菜单默认收起，当前路由在子菜单中时自动展开。折叠状态下隐藏子菜单，只显示父图标。

## 0.8 主题切换

### 0.8.1 useTheme Hook

```tsx
// core-ai-frontend/src/hooks/useTheme.ts
import { useState, useEffect } from 'react'

type Theme = 'light' | 'dark'

export function useTheme() {
  const [theme, setTheme] = useState<Theme>(() => {
    // 从 localStorage 读取，默认 'light'
    return (localStorage.getItem('theme') as Theme) || 'light'
  })

  useEffect(() => {
    // 同步到 HTML 根元素
    document.documentElement.classList.toggle('dark', theme === 'dark')
    localStorage.setItem('theme', theme)
  }, [theme])

  const toggleTheme = () => {
    setTheme(prev => prev === 'light' ? 'dark' : 'light')
  }

  return { theme, toggleTheme }
}
```

💡 **设计意图**：主题状态持久化到 localStorage，用户下次访问自动恢复偏好。`dark` 类添加到 `<html>` 元素，Tailwind 的 `dark:` 前缀自动生效。

### 0.8.2 主题在 Layout 中的应用

  alt="Core AI"

## 0.9 动态页面标题

### 0.9.1 实现

```tsx
// Layout.tsx 中监听路由变化
useEffect(() => {
  const title = getPageTitle(location.pathname)
  document.title = `${title} - Core AI`
}, [location.pathname])

// 路径到标题的映射
function getPageTitle(pathname: string): string {
  const titleMap: Record<string, string> = {
    '/for-you': '仪表盘',
    '/chat': '对话',
    '/agents': 'Agent 管理',
    '/workflows': '工作流',
    '/traces': 'Trace 查看',
    '/system-prompts': '系统提示词',
    '/skills': '技能管理',
    '/tools': '工具管理',
    '/datasets': '数据集',
    '/projects': '项目管理',
    '/experiments': '实验',
    '/settings': '系统设置',
    '/login': '登录',
  }

  // 精确匹配
  if (titleMap[pathname]) return titleMap[pathname]

  // 前缀匹配（处理子路由如 /settings/api-keys）
  for (const [path, title] of Object.entries(titleMap)) {
    if (pathname.startsWith(path + '/')) return title
  }

  return 'Core AI'
}
```

💡 **设计意图**：浏览器标签页显示当前页面名称，多标签页切换时容易辨识。路由变化时自动更新，不需要每个页面手动设置。
