## 0.1 MCP 服务器与工具

MCP（Model Context Protocol）是一种标准化的协议，允许 Agent 与外部工具和服务进行交互。通过 MCP 服务器，Agent 可以调用各种工具来完成复杂任务。

### 0.1.1 MCP 服务器列表

MCP 服务器列表页面位于 `pages/mcp/Mcp.tsx`，展示了所有已配置的 MCP 服务器。

**核心数据结构：**

```typescript
// MCP 工具信息
interface McpToolInfo {
  name: string;           // 工具名称
  description: string;    // 工具描述
  input_schema: object;   // 输入参数 schema
  group?: string;         // 工具分组
}

// 工具注册视图
interface ToolRegistryView {
  id: string;
  name: string;
  description: string;
  type: string;           // 工具类型
  category: string;       // 分类
  config: object;         // 配置
  raw_config: object;     // 原始配置
  enabled: boolean;       // 是否启用
}

// MCP 服务器状态响应
interface McpServerStatusResponse {
  state: McpConnectionState;  // 连接状态
  tools_count: number;        // 工具数量
  last_connected?: string;    // 最后连接时间
}

// 连接状态枚举
type McpConnectionState =
  | 'NOT_CONNECTED'    // 未连接
  | 'CONNECTING'       // 连接中
  | 'CONNECTED'        // 已连接
  | 'DISCONNECTED'     // 已断开
  | 'RECONNECTING'     // 重连中
  | 'FAILED';          // 连接失败
```

**主要 API 操作：**

```typescript
// 获取 MCP 服务器列表
const servers = await api.tools.list();

// 获取服务器分类
const categories = await api.tools.categories();

// 创建 MCP 服务器
const newServer = await api.tools.createMcpServer({
  name: 'My MCP Server',
  type: 'stdio',
  config: { command: 'node', args: ['server.js'] }
});

// 启用/禁用服务器
await api.tools.enableMcpServer(serverId);
await api.tools.disableMcpServer(serverId);

// 导入多个 MCP 服务器
await api.tools.importMcpServers(serversJson);
```

💡 **设计意图**：MCP 服务器采用插件化架构，支持动态添加和移除。通过 `enabled` 字段可以快速启用或禁用工具，而无需删除配置。连接状态管理确保系统能够自动处理网络异常和重连。

### 0.1.2 MCP 服务器详情

MCP 服务器详情页面位于 `pages/mcp/McpDetail.tsx`，展示了单个服务器的详细信息、工具列表和测试功能。

**核心功能：**

```typescript
// 获取服务器工具列表
const tools: McpServerToolsResponse = await api.tools.listMcpServerTools(serverId);

// 获取服务器状态
const status: McpServerStatusResponse = await api.tools.getMcpServerStatus(serverId);

// 连接服务器
await api.tools.connectMcpServer(serverId);

// 测试工具调用
const result: TestMcpToolResponse = await api.tools.testMcpServerTool(
  serverId,
  toolName,
  { param1: 'value1', param2: 'value2' }
);

// 更新服务器配置
await api.tools.updateMcpServer(serverId, {
  config: { /* new config */ }
});

// 删除服务器
await api.tools.deleteMcpServer(serverId);
```

**工具测试功能：**

工具测试页面允许你在实际调用前验证工具是否正常工作：

1. 选择要测试的工具
2. 根据 `input_schema` 填写参数
3. 点击"测试"按钮
4. 查看返回结果

💡 **设计意图**：工具测试功能降低了调试难度，开发者可以在将工具集成到 Agent 之前验证其正确性。这种"先测试后使用"的模式提高了系统的可靠性。

### 0.1.3 连接状态管理

MCP 服务器的连接状态通过状态机进行管理：

```
NOT_CONNECTED → CONNECTING → CONNECTED
                   ↓              ↓
               FAILED ←←← DISCONNECTED
                   ↓
              RECONNECTING
```

**状态说明：**

- `NOT_CONNECTED`: 初始状态，服务器尚未尝试连接
- `CONNECTING`: 正在建立连接
- `CONNECTED`: 连接成功，可以调用工具
- `DISCONNECTED`: 主动断开或连接丢失
- `RECONNECTING`: 尝试重新连接
- `FAILED`: 连接失败，需要人工干预

💡 **设计意图**：状态机模式使得连接管理更加清晰和可预测。自动重连机制提高了系统的容错能力，而明确的状态展示帮助用户理解系统当前状况。

## 0.2 API 工具

API 工具是另一种扩展 Agent 能力的方式，通过调用外部 REST API 服务来实现特定功能。

### 0.2.1 API 应用列表

API 工具页面位于 `pages/api-tools/ApiTools.tsx`，展示了所有可用的 API 应用。

**核心数据结构：**

```typescript
// API 应用视图
interface ApiAppView {
  name: string;           // 应用名称
  base_url: string;       // 基础 URL
  version: string;        // 版本
  description: string;    // 描述
}

// API 服务视图
interface ApiServiceView {
  name: string;
  operations: ApiOperationView[];
}

// API 操作视图
interface ApiOperationView {
  name: string;               // 操作名称
  description: string;        // 描述
  method: string;             // HTTP 方法 (GET, POST, etc.)
  path: string;               // 路径
  request_type: string;       // 请求类型
  response_type: string;      // 响应类型
  input_schema: object;       // 输入 schema
  output_schema: object;      // 输出 schema
}
```

**主要 API 操作：**

```typescript
// 获取 API 应用列表
const apps = await api.serviceApis.list();

// 获取应用详情
const app: ApiServiceView = await api.serviceApis.get(appId);

// 创建 API 应用
const newApp = await api.serviceApis.create({
  name: 'Weather API',
  base_url: 'https://api.weather.com',
  version: 'v1'
});

// 启用/禁用应用
await api.serviceApis.enable(appId);
await api.serviceApis.disable(appId);
```

💡 **设计意图**：API 工具采用应用-操作的两级结构，将相关的 API 操作组织在一起。这种结构化的方式使得工具管理更加清晰，便于复用和维护。

### 0.2.2 API 操作详情

API 操作详情页面位于 `pages/api-tools/ApiToolDetail.tsx`，展示了单个 API 应用的详细信息和可用操作。

**核心功能：**

```typescript
// 从系统 API 更新
await api.serviceApis.updateFromSysApi(appId);

// 批量更新所有系统 API
await api.serviceApis.updateAllFromSysApi();

// 更新应用配置
await api.serviceApis.update(appId, {
  base_url: 'https://new-api-url.com'
});

// 删除应用
await api.serviceApis.delete(appId);
```

💡 **设计意图**：`updateFromSysApi` 功能允许从系统 API 定义自动同步操作列表，减少了手动配置的工作量。批量更新功能则适用于需要同时更新多个 API 应用的场景。

### 0.2.3 服务 API 管理

服务 API 是 API 工具的底层实现，包含了完整的配置信息。

**核心数据结构：**

```typescript
// 服务 API 视图
interface ServiceApiView {
  id: string;
  name: string;
  enabled: boolean;           // 是否启用
  description: string;
  base_url: string;           // 基础 URL
  url: string;                // 完整 URL
  version: string;
  payload: object;            // 请求负载配置
  service_additional: object; // 额外服务配置
  type_additional: object;    // 额外类型定义
}
```

💡 **设计意图**：服务 API 配置包含了丰富的元数据，支持复杂的 API 集成场景。`service_additional` 和 `type_additional` 字段提供了灵活性，可以适应不同的 API 规范。

## 0.4 技能管理

技能是预定义的提示词模板和工具组合，可以让 Agent 快速具备特定领域的能力。

### 0.4.1 技能列表与搜索

技能列表页面位于 `pages/skills/SkillList.tsx`，展示了所有可用的技能。

**核心数据结构：**

```typescript
// 技能定义
interface SkillDefinition {
  id: string;
  namespace: string;          // 命名空间
  name: string;               // 技能名称
  qualified_name: string;     // 完整名称
  description: string;        // 描述
  source_type: 'UPLOAD' | 'REPO';  // 来源类型
  allowed_tools: string[];    // 允许使用的工具
  metadata: object;           // 元数据
  version: string;            // 版本
}
```

**主要 API 操作：**

```typescript
// 获取技能列表
const skills = await api.skills.list();

// 获取技能详情
const skill = await api.skills.get(skillId);

// 同步技能
await api.skills.sync(skillId);

// 删除技能
await api.skills.delete(skillId);
```

💡 **设计意图**：技能采用命名空间机制避免冲突，`qualified_name` 字段提供了唯一的技能标识。`allowed_tools` 字段限制了技能可以使用的工具范围，提高了安全性。

### 0.4.2 技能编辑器

技能编辑器页面位于 `pages/skills/SkillEditor.tsx`，允许创建和编辑技能。

**核心功能：**

## 0.5 触发器

触发器页面位于 `pages/triggers/TriggersWebhook.tsx`，用于管理 Webhook 触发器。

**核心数据结构：**

```typescript
// 触发器视图
interface TriggerView {
  id: string;
  name: string;
  description: string;
  type: string;               // 触发器类型
  enabled: boolean;           // 是否启用
  config: object;             // 配置
  webhook_url: string;        // Webhook URL
  action_type: string;        // 动作类型
  action_config: object;      // 动作配置
}
```

**触发器工作流程：**

1. 外部系统发送 HTTP 请求到 `webhook_url`
2. 系统解析请求内容
3. 根据 `action_config` 执行相应动作（如启动 Agent）
4. 返回执行结果

💡 **设计意图**：Webhook 触发器实现了事件驱动的架构模式，允许外部系统与 Agent 进行集成。这种异步方式适用于需要响应外部事件的场景。

## 0.6 通信渠道

通信渠道页面位于 `pages/channels/Channels.tsx`，用于管理 Agent 的通信方式。

**核心数据结构：**

```typescript
// 渠道视图
interface ChannelView {
  channelId: string;
  channelType: string;        // 渠道类型 (web, api, webhook, etc.)

  enabled: boolean;           // 是否启用
```

💡 **设计意图**：多渠道支持使得 Agent 可以通过不同方式与用户交互。`requireAuth` 配置确保了安全性，`filterConfig` 允许对输入进行预处理和过滤。

## 0.7 调度器

调度器页面位于 `pages/scheduler/Scheduler.tsx`，用于配置定时任务。

**核心数据结构：**

```typescript
// Agent 调度视图
interface AgentScheduleView {
  id: string;
  agent_id: string;           // Agent ID
  name: string;               // 任务名称
  cron_expression: string;    // Cron 表达式
  timezone: string;           // 时区
  enabled: boolean;           // 是否启用
  input: string;              // 输入内容
  variables: object;          // 变量
  channel_id: string;         // 渠道 ID
  concurrency_policy: string; // 并发策略
  next_run_at: string;        // 下次运行时间
}

// 会话调度视图
interface SessionScheduleView {
  // 类似 AgentScheduleView
}
```

**Cron 表达式示例：**

```
# 每天上午 9 点
0 9 * * *

# 每小时
0 * * * *

# 每周一上午 10 点
0 10 * * 1

# 每 5 分钟
*/5 * * * *
```

**主要 API 操作：**

```typescript
// 获取调度列表
const schedules = await api.scheduler.list();

// 创建调度任务
const schedule = await api.scheduler.create({
  agent_id: 'agent-123',
  name: 'Daily Report',
  cron_expression: '0 9 * * *',
  timezone: 'Asia/Shanghai',
  input: '生成今日报告'
});

// 启用/禁用调度
await api.scheduler.enable(scheduleId);
await api.scheduler.disable(scheduleId);
```

💡 **设计意图**：调度器基于 Cron 表达式实现灵活的定时任务配置。`concurrency_policy` 控制并发执行策略，避免资源冲突。时区支持确保了全球用户的正确使用。
