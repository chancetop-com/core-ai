## 0.1 技术栈总览

core-ai-frontend 基于以下技术栈构建：

| 技术 | 版本 | 说明 |
|------|------|------|
| **React** | 19 | UI 组件库，支持 Concurrent 模式 |
| **TypeScript** | 5.9 | 类型安全的 JavaScript 超集 |
| **Vite** | 8 | 构建工具，开发时秒级热更新 |

## 0.2 分层架构

前端采用清晰的**七层分层架构**，每一层职责明确：

```
┌─────────────────────────────────────┐
│          入口层 (main.tsx)          │  ← React 挂载点
├─────────────────────────────────────┤
│          路由层 (App.tsx)           │  ← 路由定义与守卫
├─────────────────────────────────────┤
│          布局层 (Layout.tsx)        │  ← 侧边栏与主题
├─────────────────────────────────────┤
│          页面层 (pages/*)           │  ← 功能模块页面
├─────────────────────────────────────┤
│          组件层 (components/*)      │  ← 可复用 UI 组件
├─────────────────────────────────────┤
│          Hooks 层 (hooks/*)         │  ← 自定义 Hooks
├─────────────────────────────────────┤
│          API 层 (api/client.ts)     │  ← 后端通信
└─────────────────────────────────────┘
```

💡 **设计意图**：分层架构让各层职责独立、可单独测试。入口层只负责挂载，路由层只管导航，布局层处理全局 UI 骨架，页面层承载业务逻辑，API 层封装网络通信。修改任何一层不会影响其他层。

## 0.3 入口层与启动流程

### 0.3.1 main.tsx — 应用入口

```tsx
// core-ai-frontend/src/main.tsx
import React from 'react'
import ReactDOM from 'react-dom/client'
import App from './App'
import './index.css'

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <App />
  </React.StrictMode>,
)
```

💡 **设计意图**：入口文件极简——只创建 React 根节点并渲染 App 组件。`StrictMode` 在开发模式下帮助发现不安全的生命周期和副作用。

### 0.3.2 App.tsx — 根组件职责

App 组件承担三个关键启动职责：

1. **获取系统能力 (Capabilities)**：调用后端接口获取哪些功能模块已启用
2. **初始化认证上下文 (AuthContext)**：从 localStorage 读取用户信息
3. **路由懒加载**：使用 `React.lazy` 按需加载页面组件

```tsx
// core-ai-frontend/src/App.tsx (简化)
import { BrowserRouter, Routes, Route, Navigate } from 'react-router-dom'
import { Suspense, lazy, useEffect, useState } from 'react'
import { AuthContext } from './contexts/AuthContext'
import { CapabilitiesContext } from './contexts/CapabilitiesContext'
import Layout from './components/Layout'

// 所有页面懒加载
const Chat = lazy(() => import('./pages/chat/Chat'))
const Agents = lazy(() => import('./pages/agents/Agents'))
const Workflows = lazy(() => import('./pages/workflows/Workflows'))
// ... 约 40 个路由

function App() {
  const [caps, setCaps] = useState(null)
  const [user, setUser] = useState(() => {
    const stored = localStorage.getItem('user')
    return stored ? JSON.parse(stored) : null
  })

  useEffect(() => {
    // 启动时获取系统能力
    fetch('/api/capabilities')
      .then(res => res.json())
      .then(data => setCaps(data))
  }, [])

  return (
    <AuthContext.Provider value={{ user, setUser }}>
      <CapabilitiesContext.Provider value={caps}>
        <BrowserRouter>
          <Suspense fallback={<PageFallback />}>
            <Routes>
              {/* 路由定义 */}
            </Routes>
          </Suspense>
        </BrowserRouter>
      </CapabilitiesContext.Provider>
    </AuthContext.Provider>
  )
}
```

💡 **设计意图**：将 Capabilities 和 Auth 提升到根组件，通过 Context 传递给所有子组件，避免了 prop drilling。懒加载确保首屏只加载必要的代码。

## 0.4 路由层

### 0.4.1 路由组织策略

使用 `react-router-dom` v7 的 `BrowserRouter` + `Routes` + `Route` 组合：

```tsx
// core-ai-frontend/src/App.tsx (路由片段)
<Routes>
  {/* 公开路由 - 无需认证 */}
  <Route path="/login" element={<Login />} />
  <Route path="/shared/artifacts/:token" element={<SharedArtifact />} />

  {/* 受保护路由 - 需要认证 + 权限 */}
  <Route element={<Layout />}>
    <Route path="/for-you" element={
      <RequirePermission permission="dashboard.view">
        <Dashboard />
      </RequirePermission>
    } />

    {/* 能力门控路由 - 需要后端启用对应功能 */}
    {caps?.chat && (
      <Route path="/chat" element={
        <RequirePermission permission="chat.use">
          <Chat />
        </RequirePermission>
      } />
    )}

    <Route path="/agents" element={
      <RequirePermission permission="agent.view">
        <Agents />
      </RequirePermission>
    } />
    {/* ... 更多路由 */}
  </Route>

  {/* 默认重定向 */}
  <Route path="*" element={<Navigate to="/for-you" replace />} />
</Routes>
```

💡 **设计意图**：路由分三类——公开路由（登录页、分享链接）、受权限保护路由（需要特定权限）、能力门控路由（需要后端启用功能）。这种三重保护确保了安全性。

### 0.4.2 权限守卫组件

```tsx
// core-ai-frontend/src/components/RequirePermission.tsx
import { usePermissions } from '../hooks/usePermissions'

export function RequirePermission({ permission, children }) {
  const { hasPermission } = usePermissions()

  if (!hasPermission(permission)) {
    return <div>无权限访问</div>
  }

  return children
}
```

💡 **设计意图**：通过 HOC 模式封装权限检查逻辑，任何页面只需包裹 `<RequirePermission>` 即可获得权限保护，实现了关注点分离。

### 0.4.3 认证流程

```
启动 → fetchCapabilities() 
     → authRequired?
         ├─ 是 + 无存储用户 → 重定向到 /login
         └─ 否 / 有存储用户 → 正常渲染路由
```

## 0.5 布局层

### 0.5.1 Layout.tsx 核心结构

布局层提供全局 UI 骨架：可折叠侧边栏、主题切换、用户信息展示。

```tsx
// core-ai-frontend/src/components/Layout.tsx (简化)
import { useState } from 'react'
import { Outlet, useLocation, Link } from 'react-router-dom'
import { useTheme } from '../hooks/useTheme'
import { useAuth } from '../hooks/useAuth'

const SIDEBAR_WIDTH = { collapsed: 60, expanded: 224 }

export default function Layout() {
  const [collapsed, setCollapsed] = useState(false)
  const { theme, toggleTheme } = useTheme()
  const { user, logout } = useAuth()
  const location = useLocation()

  // 根据当前路由动态设置页面标题
  useEffect(() => {
    const title = getPageTitle(location.pathname)
    document.title = `${title} - Core AI`
  }, [location.pathname])

  return (
    <div className="flex h-screen">
      {/* 侧边栏 */}
      <aside style={{ width: collapsed ? 60 : 224 }}>
        <nav>
          {navItems.map(item => (
            <NavItem key={item.path} item={item} collapsed={collapsed} />
          ))}
        </nav>
        <footer>
          <UserDisplay user={user} />
          <ThemeToggle theme={theme} onClick={toggleTheme} />
          <button onClick={logout}>退出登录</button>
        </footer>
      </aside>

      {/* 主内容区 */}
      <main className="flex-1 overflow-auto">
        <Outlet />
      </main>
    </div>
  )
}
```

💡 **设计意图**：使用 `<Outlet />` 渲染子路由，实现布局与内容的解耦。侧边栏宽度通过 CSS 变量控制，折叠/展开动画流畅。动态 `document.title` 让多标签页切换时更易辨识。

## 0.6 API 层

### 0.6.1 api/client.ts — 核心封装

API 层是整个前端与后端通信的唯一出口：

```tsx
// core-ai-frontend/src/api/client.ts (简化)
const BASE_URL = '/api'

async function request(endpoint, options = {}) {
  const token = localStorage.getItem('token')
  const headers = {
    'Content-Type': 'application/json',
    ...(token && { Authorization: `Bearer ${token}` }),
    ...options.headers,
  }

  const response = await fetch(`${BASE_URL}${endpoint}`, {
    ...options,
    headers,
  })

  // 401 自动跳转到登录页
  if (response.status === 401) {
    localStorage.removeItem('token')
    localStorage.removeItem('user')
    window.location.href = '/login'
    throw new Error('Unauthorized')
  }

  if (!response.ok) {
    const error = await response.json().catch(() => ({}))
    throw new APIError(response.status, error.message || '请求失败')
  }

  return response.json()
}

// 导出命名空间化的 API 对象
export const api = {
  traces: {
    list: (params) => request('/traces', { params }),
    get: (id) => request(`/traces/${id}`),
  },
  agents: {
    list: () => request('/agents'),
    create: (data) => request('/agents', { method: 'POST', body: JSON.stringify(data) }),
    update: (id, data) => request(`/agents/${id}`, { method: 'PUT', body: JSON.stringify(data) }),
    delete: (id) => request(`/agents/${id}`, { method: 'DELETE' }),
  },
  workflows: { /* ... */ },
  skills: { /* ... */ },
  tools: { /* ... */ },
  // ... 更多命名空间
}

export const authApi = { /* 认证相关 */ }
export const adminApi = { /* 管理员相关 */ }
export const userApi = { /* 用户相关 */ }
export const rbacApi = { /* 权限管理相关 */ }
```

💡 **设计意图**：统一的 `request` 函数封装了认证头注入、401 自动跳转、错误解析等通用逻辑。命名空间化的导出（`api.agents.list()`）让调用代码语义清晰，也便于按模块维护。

### 0.6.2 Vite 代理配置

开发环境下，Vite 将 `/api` 请求代理到后端：

```ts
// core-ai-frontend/vite.config.ts (简化)
export default defineConfig({
  server: {
    port: 3000,
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        // SSE 需要特殊处理：不缓冲响应
        configure: (proxy) => {
          proxy.on('proxyRes', (proxyRes) => {
            if (proxyRes.headers['content-type']?.includes('text/event-stream')) {
              proxyRes.headers['cache-control'] = 'no-cache'
              proxyRes.headers['x-accel-buffering'] = 'no'
            }
          })
        },
      },
    },
  },
})
```

💡 **设计意图**：开发时前端 3000 端口、后端 8080 端口，通过代理解决跨域。SSE（Server-Sent Events）用于实时聊天流式输出，必须禁用缓冲才能逐 token 到达前端。

## 0.7 页面层与组件层

### 0.7.1 页面组织

页面按功能模块组织在 `pages/` 目录下：

```
pages/
├── chat/              # 对话页面 - SSE 流式聊天
├── agents/            # Agent 管理 - CRUD 操作
├── workflows/         # 工作流编辑器 - 基于 @xyflow/react
├── traces/            # Trace 查看器 - 调用链追踪
├── prompts/           # 系统提示词管理
├── skills/            # 技能管理
├── tools/             # 工具管理 (Builtin/MCP/API)
├── datasets/          # 数据集管理
├── projects/          # 项目管理
├── experiments/       # 实验系统 (Playground/Replay/Memory)
├── settings/          # 系统设置 (API Keys/Gateway/Users)
├── login/             # 登录注册
└── for-you/           # 个人仪表盘
```

💡 **设计意图**：每个功能模块独占一个目录，包含该模块的所有组件、子页面和局部工具。这种"功能内聚"的组织方式比"按类型分目录"更容易维护和导航。

### 0.7.2 组件层

`components/` 目录存放跨页面共享的通用组件：

- **Layout.tsx** — 全局布局骨架
- **ErrorBoundary.tsx** — 错误边界，防止局部崩溃影响全局
- **RequirePermission.tsx** — 权限守卫组件
- **CodeMirrorEditor.tsx** — 代码编辑器封装
- **PageFallback.tsx** — 懒加载的 Suspense 降级 UI

💡 **设计意图**：只有真正被多个页面使用的组件才放在 `components/`，页面内部组件留在各自目录。这避免了 `components/` 成为"垃圾桶"。

## 0.8 核心设计模式

### 0.8.1 代码分割与懒加载

```tsx
// 所有页面使用 React.lazy 懒加载
const Chat = lazy(() => import('./pages/chat/Chat'))
const Agents = lazy(() => import('./pages/agents/Agents'))
// ...

// 配合 Suspense 提供加载状态
<Suspense fallback={<PageFallback />}>
  <Routes>...</Routes>
</Suspense>
```

💡 **设计意图**：首屏只加载当前路由对应的代码，其他页面按需加载。Vite 会自动对每个 `import()` 生成独立 chunk，配合 `modulePreload` 预加载策略，平衡首屏速度和后续导航体验。

### 0.8.2 Context API 管理全局状态

```tsx
// AuthContext - 认证状态
<AuthContext.Provider value={{ user, setUser }}>
  ...
</AuthContext.Provider>

// CapabilitiesContext - 系统能力
<CapabilitiesContext.Provider value={caps}>
  ...
</CapabilitiesContext.Provider>
```

💡 **设计意图**：只将真正"全局"的状态放入 Context（认证、能力），页面级状态使用 `useState`，避免不必要的重渲染。

### 0.8.3 自动重载机制

```tsx
// 监听 Vite 预加载错误，服务器重新部署后自动刷新
window.addEventListener('vite:preloadError', (event) => {
  window.location.reload()
})
```

💡 **设计意图**：当后端重新部署导致前端 chunk 文件名变化时，用户导航会触发 `vite:preloadError`。自动刷新确保用户始终使用最新版本，避免白屏。

### 0.8.4 SSE 实时通信

Chat 页面使用 Server-Sent Events 实现流式输出：

```tsx
// 简化示意
const eventSource = new EventSource('/api/chat/stream')
eventSource.onmessage = (event) => {
  const token = JSON.parse(event.data)
  setMessages(prev => [...prev, token])
}
```

💡 **设计意图**：相比 WebSocket，SSE 更轻量且天然支持单向推送，完美适配 LLM 流式输出场景。Vite 代理配置中专门处理了 SSE 的缓冲问题。

## 0.9 数据流

### 0.9.1 请求-响应数据流

```
用户操作
  │
  ▼
Page Component (setState 触发重渲染)
  │
  ▼
api.client.request(endpoint, options)
  │  注入 Authorization header
  │  处理 401 自动跳转
  ▼
Vite Proxy (开发环境) → Backend API (http://localhost:8080)
  │
  ▼
Response JSON
  │
  ▼
setState → React 重渲染 → UI 更新
```

💡 **设计意图**：单向数据流让状态变化可预测。所有 API 调用走统一的 `request` 函数，认证、错误处理、日志等横切关注点集中管理。
