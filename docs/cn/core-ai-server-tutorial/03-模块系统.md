## 3.1 模块系统概述

### 3.1.1 什么是模块化架构

模块化架构是一种将系统分解为独立、可互换模块的设计方法。每个模块封装特定功能，通过清晰的接口与其他模块交互。

**核心优势**:

| 优势 | 说明 | 示例 |
|------|------|------|
| **高内聚** | 模块内部功能紧密相关 | SessionModule 只处理会话相关逻辑 |
| **低耦合** | 模块间依赖最小化 | WorkflowModule 通过接口依赖 AgentRunner |
| **可测试** | 模块可独立测试 | 可以单独测试 AuthModule |
| **可复用** | 模块可在多个项目中使用 | TraceModule 可用于其他 AI 项目 |
| **可维护** | 修改一个模块不影响其他模块 | 升级 GatewayModule 不影响 SessionModule |

### 3.2 core-ng 模块分类

core-ai-server 的模块分为三大类:

```
┌─────────────────────────────────────┐
│      基础设施模块 (Infrastructure)   │
│  Settings, Gateway, Trace, Auth...  │
├─────────────────────────────────────┤
│        领域模块 (Domain)            │
│  Session, Workflow, Agent, Skill... │
├─────────────────────────────────────┤
│        传输模块 (Transport)         │
│         WebModule                   │
└─────────────────────────────────────┘
```

#### 基础设施模块

负责提供底层能力，不包含业务逻辑:

- **SettingsModule** - 系统配置管理
- **ObjectStorageModule** - 对象存储（S3/MinIO）
- **SseTransportModule** - Server-Sent Events 传输
- **GatewayModule** - LLM 网关和路由
- **TraceModule** - 分布式追踪和可观测性
- **AuthModule** - 认证和授权
- **MongoModule** - MongoDB 访问
- **RedisModule** - Redis 缓存和消息

#### 领域模块

实现核心业务逻辑:

- **SessionModule** - Agent 会话管理
- **WorkflowModule** - 工作流编排引擎
- **AgentRunnerModule** - Agent 执行器
- **SkillModule** - 技能管理
- **A2AModule** - Agent-to-Agent 通信
- **MCPModule** - Model Context Protocol
- **DatasetModule** - 数据集管理
- **ToolRegistryModule** - 工具注册

#### 传输模块

处理 HTTP 请求和响应:

- **WebModule** - Web 静态资源和 API 路由

💡 **设计意图**: 分层架构确保职责清晰，便于维护和扩展。

## 3.2 core-ng 框架基础

### 3.2.1 core-ng 简介

core-ng 是一个轻量级的 Java 应用框架，提供了模块化、依赖注入、Web 服务等核心功能。

**核心特性**:

- ✅ 模块化架构
- ✅ 依赖注入（DI）
- ✅ 类型安全的配置
- ✅ 注解驱动的 Web 服务
- ✅ 集成的 MongoDB 和 Redis 支持
- ✅ 内置性能监控

### 3.2.2 核心组件

```java
// App 类 - 应用入口
public class ServerApp extends App {
    @Override
    protected void initialize() {
        // 加载模块
    }
}

// Module 类 - 模块基类
public class MyModule extends Module {
    @Override
    protected void initialize() {
        // 模块初始化
    }
}

// Service 类 - 服务组件
public class MyService {
    @Inject
    private DependencyService dependency;
    
    public void doWork() {
        // 业务逻辑
    }
}
```

### 3.2.3 启动流程

```
JVM 启动
    ↓
ServerApp 实例化
    ↓
App.initialize() 调用
    ↓
Module.initialize() 调用（按依赖顺序）
    ↓
依赖注入完成
    ↓
启动钩子执行（onStartup）
    ↓
应用就绪
```

## 3.3 Module 类详解

### 3.3.1 Module 基类

所有模块都继承自 `core.framework.module.Module` 类:

```java
public abstract class Module {
    // 模块初始化（必须实现）
    protected abstract void initialize();
    
    // 绑定服务到容器
    protected <T> T bind(Class<T> type);
    protected <T> T bind(T instance);
    
    // 获取已绑定的 Bean
    protected <T> T bean(Class<T> type);
    
    // 注册配置
    protected <T> T config(Class<T> type);
    
    // 读取配置属性
    protected String property(String key);
    protected String property(String key, String defaultValue);
    protected int intProperty(String key, int defaultValue);
    
    // 注册启动/关闭钩子
    protected void onStartup(Runnable task);
    protected void onShutdown(Runnable task);
    
    // 注册定时任务
    protected Schedule schedule();
    
    // 注册 HTTP 路由
    protected HTTP http();
    
    // 注册 API 服务
    protected API api();
}
```

### 3.3.2 Module 示例

```java
public class SessionModule extends Module {
    @Override
    protected void initialize() {
        // 1. 绑定服务
        bind(SessionService.class);
        bind(SessionRepository.class);
        
        // 2. 注册 HTTP 路由
        http().route(HTTPMethod.GET, "/api/sessions", 
            bean(SessionController.class)::list);
        
        // 3. 注册 API 服务
        api().service(SessionWebService.class, 
            bind(SessionWebServiceImpl.class));
        
        // 4. 注册定时任务
        schedule().fixedRate("session-cleanup",
            bind(SessionCleanupJob.class), Duration.ofMinutes(5));
        
        // 5. 注册启动钩子
        onStartup(() -> {
            logger.info("SessionModule started");
        });
        
        // 6. 注册关闭钩子
        onShutdown(() -> {
            logger.info("SessionModule shutdown");
        });
    }
}
```

💡 **设计意图**: Module 类提供了丰富的 API，让模块可以声明式地注册各种组件。

### 3.3.3 模块依赖

模块间可以声明依赖关系:

```java
public class WorkflowModule extends Module {
    @Override
    protected void initialize() {
        // 依赖其他模块的服务
        var agentRunner = bean(AgentRunner.class);
        var toolRegistry = bean(ToolRegistryService.class);
        
        // 绑定自己的服务
        bind(WorkflowService.class);
    }
}
```

⚠️ **注意**: 确保被依赖的模块先加载，否则会抛出 `BeanNotFoundException`。

## 3.4 依赖注入机制

### 3.4.1 依赖注入原理

依赖注入（DI）是一种设计模式，将对象的依赖关系从对象内部转移到外部容器管理。

**传统方式（紧耦合）**:

```java
public class OrderService {
    private PaymentService paymentService = new PaymentService();
    
    public void processOrder(Order order) {
        paymentService.pay(order);
    }
}
```

**依赖注入（松耦合）**:

```java
public class OrderService {
    @Inject
    private PaymentService paymentService;
    
    public void processOrder(Order order) {
        paymentService.pay(order);
    }
}
```

💡 **优势**: 
- 便于单元测试（可以 Mock 依赖）
- 降低耦合度
- 提高代码可维护性

### 3.4.2 注入方式

#### 字段注入（推荐）

```java
public class MyService {
    @Inject
    private DependencyService dependency;
}
```

#### 构造器注入

```java
public class MyService {
    private final DependencyService dependency;
    
    @Inject
    public MyService(DependencyService dependency) {
        this.dependency = dependency;
    }
}
```

#### Setter 注入

```java
public class MyService {
    private DependencyService dependency;
    
    @Inject
    public void setDependency(DependencyService dependency) {
        this.dependency = dependency;
    }
}
```

💡 **建议**: 优先使用字段注入，代码更简洁。

### 3.4.3 绑定方式

#### 绑定类（自动实例化）

```java
// 容器会自动创建实例
bind(MyService.class);

// 使用时注入
@Inject
private MyService myService;
```

#### 绑定实例（单例）

```java
// 绑定特定实例
var instance = new MyService();
bind(instance);

// 所有注入点都使用同一个实例
```

#### 绑定接口和实现

```java
// 绑定接口到实现类
bind(MyInterface.class).to(MyImplementation.class);

// 注入接口类型
@Inject
private MyInterface myService;  // 实际注入 MyImplementation
```

### 3.4.4 作用域

core-ng 默认使用**单例作用域**，所有注入点共享同一个实例。

```java
// 所有注入的 MyService 都是同一个实例
@Inject
private MyService service1;

@Inject
private MyService service2;

// service1 == service2
```

💡 **设计意图**: 单例作用域节省内存，适合无状态服务。

### 3.4.5 循环依赖

core-ng 不支持循环依赖，会导致启动失败:

```java
// ❌ 错误示例
public class ServiceA {
    @Inject
    private ServiceB serviceB;  // 依赖 B
}

public class ServiceB {
    @Inject
    private ServiceA serviceA;  // 依赖 A
}
```

**解决方案**: 重构设计，引入中间服务或事件机制。

## 3.5 模块生命周期

### 3.5.1 生命周期阶段

```
加载阶段
    ↓
bind() 调用 - 注册服务
    ↓
依赖注入 - 解析依赖关系
    ↓
初始化阶段
    ↓
onStartup() - 启动钩子
    ↓
运行阶段
    ↓
正常服务
    ↓
关闭阶段
    ↓
onShutdown() - 关闭钩子
```

### 3.5.2 启动钩子

```java
public class MyModule extends Module {
    @Override
    protected void initialize() {
        bind(MyService.class);
        
        // 注册启动钩子
        onStartup(() -> {
            var service = bean(MyService.class);
            service.initialize();
        });
    }
}
```

💡 **使用场景**: 
- 初始化缓存
- 加载配置
- 建立连接
- 启动后台任务

### 3.5.3 关闭钩子

```java
public class MyModule extends Module {
    @Override
    protected void initialize() {
        bind(ConnectionPool.class);
        
        // 注册关闭钩子
        onShutdown(() -> {
            var pool = bean(ConnectionPool.class);
            pool.close();
        });
    }
}
```

💡 **使用场景**:
- 关闭连接池
- 清理临时文件
- 保存状态
- 停止后台任务

### 3.5.4 生命周期示例

```java
public class CacheModule extends Module {
    @Override
    protected void initialize() {
        bind(CacheService.class);
        
        // 启动时加载缓存
        onStartup(() -> {
            var cache = bean(CacheService.class);
            cache.loadFromDatabase();
            logger.info("Cache loaded: {} entries", cache.size());
        });
        
        // 关闭时保存缓存
        onShutdown(() -> {
            var cache = bean(CacheService.class);
            cache.saveToDatabase();
            logger.info("Cache saved");
        });
    }
}
```

## 3.6 模块间通信

### 3.6.1 直接调用

最简单的方式是直接注入其他模块的服务:

```java
public class WorkflowService {
    @Inject
    private AgentRunner agentRunner;  // 来自 AgentRunnerModule
    
    public void executeWorkflow(Workflow workflow) {
        for (var step : workflow.getSteps()) {
            agentRunner.run(step.getAgent());
        }
    }
}
```

💡 **适用场景**: 强依赖关系，必须等待结果。

### 3.6.2 事件机制

使用事件实现松耦合通信:

```java
// 定义事件
public class SessionCreatedEvent {
    private final String sessionId;
    private final String userId;
    
    public SessionCreatedEvent(String sessionId, String userId) {
        this.sessionId = sessionId;
        this.userId = userId;
    }
    
    // getters
}

// 发布事件
public class SessionService {
    @Inject
    private EventBus eventBus;
    
    public Session createSession(String userId) {
        var session = new Session(userId);
        // ... 创建逻辑
        
        // 发布事件
        eventBus.publish(new SessionCreatedEvent(session.getId(), userId));
        
        return session;
    }
}

// 订阅事件
public class NotificationService {
    @Subscribe
    public void onSessionCreated(SessionCreatedEvent event) {
        // 发送通知
        sendNotification(event.getUserId(), "Session created");
    }
}
```

💡 **适用场景**: 
- 松耦合
- 多个订阅者
- 不需要等待结果

### 3.6.3 消息队列

使用 Redis Pub/Sub 实现跨进程通信:

```java
// 发布消息
public class SessionService {
    @Inject
    private RedisClient redis;
    
    public void notifySessionUpdate(Session session) {
        redis.publish("session:updates", JsonUtil.toJson(session));
    }
}

// 订阅消息
public class CacheService {
    @Inject
    private RedisClient redis;
    
    @PostConstruct
    public void init() {
        redis.subscribe("session:updates", message -> {
            var session = JsonUtil.fromJson(message, Session.class);
            updateCache(session);
        });
    }
}
```

💡 **适用场景**:
- 跨进程通信
- 分布式系统
- 需要持久化的消息

## 3.9 实战: 开发自定义模块

### 3.9.1 需求

开发一个 **NotificationModule**，实现:
- 邮件通知服务
- 短信通知服务
- 通知模板管理
- 通知历史记录

### 3.9.2 模块结构

```
notification/
├── NotificationModule.java
├── domain/
│   ├── Notification.java
│   ├── NotificationType.java
│   └── NotificationTemplate.java
├── service/
│   ├── NotificationService.java
│   ├── EmailNotificationService.java
│   └── SmsNotificationService.java
├── repository/
│   └── NotificationRepository.java
├── web/
│   └── NotificationController.java
└── config/
    └── NotificationConfig.java
```

### 3.9.3 实现代码

#### 1. 领域模型

```java
// Notification.java
public class Notification {
    private String id;
    private String userId;
    private NotificationType type;
    private String title;
    private String content;
    private NotificationStatus status;
    private LocalDateTime createdAt;
    private LocalDateTime sentAt;
    
    // getters and setters
}

// NotificationType.java
public enum NotificationType {
    EMAIL,
    SMS,
    PUSH
}
```

#### 2. 服务层

```java
// NotificationService.java
public class NotificationService {
    @Inject
    private NotificationRepository repository;
    
    @Inject
    private EmailNotificationService emailService;
    
    @Inject
    private SmsNotificationService smsService;
    
    public Notification send(String userId, NotificationType type, 
                            String title, String content) {
        var notification = new Notification();
        notification.setId(UUID.randomUUID().toString());
        notification.setUserId(userId);
        notification.setType(type);
        notification.setTitle(title);
        notification.setContent(content);
        notification.setStatus(NotificationStatus.PENDING);
        notification.setCreatedAt(LocalDateTime.now());
        
        repository.save(notification);
        
        try {
            switch (type) {
                case EMAIL -> emailService.send(notification);
                case SMS -> smsService.send(notification);
                case PUSH -> sendPush(notification);
            }
            notification.setStatus(NotificationStatus.SENT);
            notification.setSentAt(LocalDateTime.now());
        } catch (Exception e) {
            notification.setStatus(NotificationStatus.FAILED);
            logger.error("Failed to send notification", e);
        }
        
        repository.update(notification);
        return notification;
    }
    
    public List<Notification> getUserNotifications(String userId) {
        return repository.findByUserId(userId);
    }
}
```

#### 3. 数据访问层

```java
// NotificationRepository.java
public class NotificationRepository {
    @Inject
    private MongoCollection<Notification> collection;
    
    public void save(Notification notification) {
        collection.insertOne(notification);
    }
    
    public void update(Notification notification) {
        collection.replaceOne(
            Filters.eq("_id", notification.getId()),
            notification
        );
    }
    
    public List<Notification> findByUserId(String userId) {
        return collection.find(Filters.eq("userId", userId))
            .sort(Sorts.descending("createdAt"))
            .into(new ArrayList<>());
    }
}
```

#### 4. Web 层

```java
// NotificationController.java
public class NotificationController {
    @Inject
    private NotificationService service;
    
    public List<Notification> list(String userId) {
        return service.getUserNotifications(userId);
    }
    
    public Notification send(SendNotificationRequest request) {
        return service.send(
            request.getUserId(),
            request.getType(),
            request.getTitle(),
            request.getContent()
        );
    }
}
```

#### 5. 模块定义

```java
// NotificationModule.java
public class NotificationModule extends Module {
    @Override
    protected void initialize() {
        // 绑定服务
        bind(NotificationService.class);
        bind(EmailNotificationService.class);
        bind(SmsNotificationService.class);
        bind(NotificationRepository.class);
        
        // 注册 HTTP 路由
        var controller = bean(NotificationController.class);
        http().route(HTTPMethod.GET, "/api/notifications", controller::list);
        http().route(HTTPMethod.POST, "/api/notifications", controller::send);
        
        // 注册启动钩子
        onStartup(() -> {
            logger.info("NotificationModule started");
        });
    }
}
```

### 3.9.4 测试

```java
public class NotificationServiceTest {
    @Test
    public void testSendEmail() {

        // 验证
        assertNotNull(notification);
        assertEquals(NotificationStatus.SENT, notification.getStatus());
        verify(emailService).send(notification);
    }
}
```

## 3.10 模块设计最佳实践

### 3.10.1 单一职责原则

每个模块只负责一个领域:

```java
// ❌ 错误示例
public class UserAndSessionModule extends Module {
    // 同时处理用户和会话
}

// ✅ 正确示例
public class UserModule extends Module {
    // 只处理用户相关
}

public class SessionModule extends Module {
    // 只处理会话相关
}
```

### 3.10.2 接口隔离

定义清晰的接口:

```java
// ✅ 定义接口
public interface SessionService {
    Session create(String userId);
    Session get(String id);
    void delete(String id);
}

// 实现类
public class SessionServiceImpl implements SessionService {
    // 实现细节
}

// 绑定
bind(SessionService.class).to(SessionServiceImpl.class);
```

💡 **优势**: 
- 降低耦合
- 便于测试
- 支持多实现

### 3.10.3 依赖倒置

依赖抽象而非具体实现:

```java
// ❌ 依赖具体实现
public class WorkflowService {
    @Inject
    private MongoSessionRepository repository;  // 具体实现
}

// ✅ 依赖抽象接口
public class WorkflowService {
    @Inject
    private SessionRepository repository;  // 接口
}
```

### 3.10.4 避免循环依赖

重构设计，消除循环依赖:

```java
// ❌ 循环依赖
public class ServiceA {
    @Inject
    private ServiceB b;
}

public class ServiceB {
    @Inject
    private ServiceA a;
}

// ✅ 引入中间服务
public class ServiceA {
    @Inject
    private MediatorService mediator;
}

public class ServiceB {
    @Inject
    private MediatorService mediator;
}

public class MediatorService {
    // 协调 A 和 B
}
```

### 3.10.5 配置外部化

不要硬编码配置:

```java
// ❌ 硬编码
public class MyService {
    private int timeout = 30000;  // 硬编码
}

// ✅ 外部化配置
public class MyService {
    @Inject
    private MyConfig config;
    
    public void doWork() {
        int timeout = config.getTimeout();  // 从配置读取
    }
}
```

### 3.10.6 错误处理

统一错误处理策略:

```java
// 定义业务异常
public class SessionNotFoundException extends BusinessException {
    public SessionNotFoundException(String id) {
        super("Session not found: " + id);
    }
}

// 在服务中抛出
public Session get(String id) {
    var session = repository.findById(id);
    if (session == null) {
        throw new SessionNotFoundException(id);
    }
    return session;
}

// 在 Web 层统一处理
public class ErrorHandler {
    @ExceptionHandler(SessionNotFoundException.class)
    public Response handleNotFound(SessionNotFoundException e) {
        return Response.status(404).entity(e.getMessage()).build();
    }
}
```
