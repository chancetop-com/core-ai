| **响应时间** | 请求处理时间 | < 200ms (P95) |

```java
// ❌ 避免：全表扫描
public List<Agent> findAllAgents() {

// ✅ 好的实践：使用分页
public Page<Agent> findAgents(int page, int size) {
    var skip = (page - 1) * size;
    
    var agents = agentCollection.find()
        .skip(skip)
        .limit(size)
        .sort(Sorts.descending("created_at"))

    var total = agentCollection.countDocuments();
    
    return new Page<>(agents, total, page, size);

public List<AgentDTO> findAgentDTOs() {

        ))
```

### 13.3.3 批量操作

```java
// ❌ 避免：逐条插入
public void insertAgents(List<Agent> agents) {
    for (var agent : agents) {
        agentCollection.insertOne(agent);
    }
}

// ✅ 好的实践：批量插入
public void insertAgents(List<Agent> agents) {
    agentCollection.insertMany(agents);
}

// ✅ 好的实践：批量更新
public void updateAgents(List<Agent> agents) {
    var bulkOps = agents.stream()
        .map(agent -> BulkOps.updateOne(
            Filters.eq("_id", agent.getId()),
            Updates.combine(
                Updates.set("name", agent.getName()),
                Updates.set("updated_at", Instant.now())
            )
        ))
        .toList();
    
    agentCollection.bulkWrite(bulkOps);
}
```

💡 **数据库优化原则**:
- 创建合适的索引
- 使用分页避免全表扫描
- 使用投影减少数据传输
- 使用批量操作提高效率
- 定期分析和优化慢查询

## 13.4 缓存策略

### 13.4.1 本地缓存

```java
@Service
public class AgentService {
    
    // Caffeine 缓存
    private final Cache<String, Agent> agentCache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(Duration.ofMinutes(10))
        .recordStats()
        .build();
    
    public Agent getAgent(String id) {
        return agentCache.get(id, key -> {
            return agentRepository.findById(key);
        });
    }
    
    public void updateAgent(Agent agent) {
        agentRepository.save(agent);
        agentCache.put(agent.getId(), agent);
    }
    
    public void deleteAgent(String id) {
        agentRepository.delete(id);
        agentCache.invalidate(id);
    }
}
```

### 13.4.2 分布式缓存

```java
@Service
public class SessionService {
    
    @Inject
    private RedisClient redisClient;
    
    private static final Duration SESSION_TTL = Duration.ofHours(1);
    
    public Session getSession(String sessionId) {
        var key = "session:" + sessionId;
        var json = redisClient.get(key);
        
        if (json == null) {
            var session = sessionRepository.findById(sessionId);
            if (session != null) {
                redisClient.setex(key, SESSION_TTL.getSeconds(), 
                    JsonUtil.toJson(session));
            }
            return session;
        }
        
        return JsonUtil.fromJson(json, Session.class);
    }
    
    public void updateSession(Session session) {
        sessionRepository.save(session);
        
        var key = "session:" + session.getId();
        redisClient.setex(key, SESSION_TTL.getSeconds(), 
            JsonUtil.toJson(session));
    }
}
```

### 13.4.3 多级缓存

```java
@Service
public class ConfigService {
    
    // L1: 本地缓存（最快，容量小）
    private final Cache<String, Config> l1Cache = Caffeine.newBuilder()
        .maximumSize(100)
        .expireAfterWrite(Duration.ofMinutes(1))
        .build();
    
    // L2: 分布式缓存（较快，容量中等）
    @Inject
    private RedisClient redisClient;
    
    // L3: 数据库（最慢，容量大）
    @Inject
    private ConfigRepository configRepository;
    
    public Config getConfig(String key) {
        // L1 缓存
        var config = l1Cache.getIfPresent(key);
        if (config != null) {
            return config;
        }
        
        // L2 缓存
        var json = redisClient.get("config:" + key);
        if (json != null) {
            config = JsonUtil.fromJson(json, Config.class);
            l1Cache.put(key, config);
            return config;
        }
        
        // L3 数据库
        config = configRepository.findByKey(key);
        if (config != null) {
            redisClient.setex("config:" + key, 3600, 
                JsonUtil.toJson(config));
            l1Cache.put(key, config);
        }
        
        return config;
    }
}
```

💡 **缓存策略选择**:
- **本地缓存**: 高频访问、小容量数据
- **分布式缓存**: 共享数据、中等容量
- **多级缓存**: 结合两者优势
- **缓存更新**: 主动更新或过期淘汰

## 13.6 JVM 优化

### 13.6.1 内存配置

```bash
# 生产环境 JVM 参数
java -Xms2g -Xmx4g \
     -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:+ParallelRefProcEnabled \
     -XX:+UseStringDeduplication \
     -jar core-ai-server.jar
```

**参数说明**:
- `-Xms2g -Xmx4g`: 堆内存初始 2GB，最大 4GB
- `-XX:+UseG1GC`: 使用 G1 垃圾收集器
- `-XX:MaxGCPauseMillis=200`: 最大 GC 暂停时间 200ms
- `-XX:+ParallelRefProcEnabled`: 并行引用处理
- `-XX:+UseStringDeduplication`: 字符串去重

### 13.6.2 GC 调优

```bash
# G1 GC 配置
java -XX:+UseG1GC \
     -XX:MaxGCPauseMillis=200 \
     -XX:G1HeapRegionSize=8m \
     -XX:InitiatingHeapOccupancyPercent=45 \
     -jar core-ai-server.jar

# ZGC 配置（低延迟）
java -XX:+UseZGC \
     -XX:+ZGenerational \
     -jar core-ai-server.jar
```

### 13.6.3 JIT 编译优化

```bash
# 启用分层编译
java -XX:+TieredCompilation \
```

## 13.8 性能监控

### 13.8.1 应用指标

```java
@Component
public class PerformanceMetrics {
    
    private final MeterRegistry meterRegistry;
    
    // 请求计数器
    private final Counter requestCounter;
    
    // 响应时间计时器
    private final Timer responseTimer;
    
    // 活跃请求数
    private final AtomicInteger activeRequests = new AtomicInteger(0);
    
    public PerformanceMetrics(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
        
        this.requestCounter = Counter.builder("http_requests_total")
            .description("Total HTTP requests")
            .register(meterRegistry);
        
        this.responseTimer = Timer.builder("http_response_time")
            .description("HTTP response time")
            .register(meterRegistry);
        
        Gauge.builder("http_active_requests", activeRequests, AtomicInteger::get)
            .description("Active HTTP requests")
            .register(meterRegistry);
    }
    
    public void recordRequest(String method, String path, int status, long duration) {
        requestCounter.increment();
        responseTimer.record(duration, TimeUnit.MILLISECONDS);
    }
}
```

```java
// 添加索引
agentCollection.createIndex(

    )

// 优化查询
public List<Agent> findAgentsByOwner(String ownerId) {
```

**效果**: 响应时间从 2s 降低到 50ms

## 13.11 常见问题

### 13.11.1 内存泄漏

**症状**: 内存使用持续增长，最终 OOM

**排查**:
```bash
# 生成堆转储
jmap -dump:format=b,file=heap_dump.hprof <pid>

# 使用 MAT 分析
mat heap_dump.hprof
```

**解决方案**:
```java
// ❌ 错误：静态集合导致内存泄漏
public class BadCache {
    private static final Map<String, Object> cache = new HashMap<>();
    
    public void add(String key, Object value) {
        cache.put(key, value);  // 永远不会释放
    }
}

// ✅ 正确：使用弱引用或设置过期时间
public class GoodCache {
    private final Cache<String, Object> cache = Caffeine.newBuilder()
        .maximumSize(1000)
        .expireAfterWrite(Duration.ofHours(1))
        .build();
    
    public void add(String key, Object value) {
        cache.put(key, value);
    }
}
```

### 13.11.2 死锁

**症状**: 应用挂起，CPU 使用率低

**排查**:
```bash
# 生成线程转储
jstack <pid> > thread_dump.txt

# 查找死锁
grep -A 10 "Found one Java-level deadlock" thread_dump.txt
```

**解决方案**:
```java
// ❌ 错误：锁顺序不一致导致死锁
public class DeadlockExample {
    private final Object lock1 = new Object();
    private final Object lock2 = new Object();
    
    public void method1() {
        synchronized (lock1) {
            synchronized (lock2) {  // 死锁风险
                // ...
            }
        }
    }
    
    public void method2() {
        synchronized (lock2) {
            synchronized (lock1) {  // 死锁风险
                // ...
            }
        }
    }
}

// ✅ 正确：保持锁顺序一致
public class NoDeadlockExample {
    private final Object lock1 = new Object();
    private final Object lock2 = new Object();
    
    public void method1() {
        synchronized (lock1) {
            synchronized (lock2) {
                // ...
            }
        }
    }
    
    public void method2() {
        synchronized (lock1) {  // 保持相同的锁顺序
            synchronized (lock2) {
                // ...
            }
        }
    }
}
```

### 13.11.3 线程池耗尽

**症状**: 请求等待时间长，最终超时

**排查**:
```bash
# 查看线程状态
jstack <pid> | grep -A 5 "ThreadPoolExecutor"
```

**解决方案**:
```java
// 优化线程池配置
@Configuration
public class ThreadPoolConfig {
    
    @Bean
    public ExecutorService taskExecutor() {
        return new ThreadPoolExecutor(
            10,  // 核心线程数
            50,  // 最大线程数
            60L, TimeUnit.SECONDS,  // 空闲线程存活时间
            new LinkedBlockingQueue<>(100),  // 队列大小
            new ThreadFactoryBuilder()
                .setNameFormat("task-executor-%d")
                .build(),
            new ThreadPoolExecutor.CallerRunsPolicy()  // 拒绝策略
        );
    }
}
```

💡 **常见问题解决思路**:
- 分析症状，定位问题
- 使用工具排查
- 找出根因
- 实施解决方案
- 验证效果
