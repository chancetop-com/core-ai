## 11.1 部署架构

### 11.1.1 单节点部署

```
┌─────────────────────────────────────┐
│         Docker Host                  │
│  ┌───────────────────────────────┐  │
│  │  sandbox-runtime Container    │  │
│  │  - Port: 8080                 │  │
│  │  - CPU: 2 cores               │  │
│  │  - Memory: 2GB                │  │
│  │  - Disk: 10GB                 │  │
│  └───────────────────────────────┘  │
└─────────────────────────────────────┘
```

**适用场景**: 开发、测试、小规模生产

### 11.1.2 多节点部署

```
┌─────────────────────────────────────────────┐
│           Load Balancer                      │
└────────────┬────────────────────────────────┘
             │
    ┌────────┼────────┐
    │        │        │
┌───▼───┐ ┌──▼───┐ ┌──▼───┐
│Node 1 │ │Node 2│ │Node 3│
│Docker │ │Docker│ │Docker│
└───────┘ └──────┘ └──────┘
```

**适用场景**: 中大规模生产，高可用需求

### 11.1.3 Kubernetes 部署

```
┌─────────────────────────────────────────────┐
│        Kubernetes Cluster                   │
│  ┌─────────────────────────────────────┐   │
│  │       Ingress Controller            │   │
│  └──────────────┬──────────────────────┘   │
│                 │                          │
│  ┌──────────────▼──────────────────────┐   │
│  │       Service (ClusterIP)           │   │
│  └──────────────┬──────────────────────┘   │
│                 │                          │
│  ┌──────────────▼──────────────────────┐   │
│  │    Deployment (3 Replicas)          │   │
│  │  ┌─────┐ ┌─────┐ ┌─────┐          │   │
│  │  │Pod 1│ │Pod 2│ │Pod 3│          │   │
│  │  └─────┘ └─────┘ └─────┘          │   │
│  └─────────────────────────────────────┘   │
└─────────────────────────────────────────────┘
```

**适用场景**: 大规模生产，弹性伸缩需求

## 11.2 Docker 部署

### 11.2.1 构建镜像

```bash
# 构建生产镜像
docker build -t core-ai-sandbox:1.0.0 .

# 推送到镜像仓库
docker tag core-ai-sandbox:1.0.0 registry.example.com/core-ai/sandbox:1.0.0
docker push registry.example.com/core-ai/sandbox:1.0.0
```

### 11.2.2 运行容器

```bash
docker run -d \
  --name sandbox \
  --restart unless-stopped \
  -p 8080:8080 \
  -e MAX_CONCURRENT=10 \
  -e MAX_OUTPUT_SIZE=30 \
  -e LOG_LEVEL=info \
  --memory=2g \
  --cpus=2 \
  --read-only \
  --tmpfs /workspace:size=1G \
  --tmpfs /tmp:size=500M \
  --security-opt=no-new-privileges \
  core-ai-sandbox:1.0.0
```

### 11.2.3 Docker Compose

```yaml
# docker-compose.yml
version: '3.8'

services:
  sandbox:
    image: core-ai-sandbox:1.0.0
    container_name: sandbox-runtime
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      - MAX_CONCURRENT=10
      - MAX_OUTPUT_SIZE=30
      - LOG_LEVEL=info
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
        reservations:
          cpus: '1'
          memory: 1G
    security_opt:
      - no-new-privileges:true
    read_only: true
    tmpfs:
      - /workspace:size=1G,mode=1777
      - /tmp:size=500M,mode=1777
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8080/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 10s
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"

  # 可选：Prometheus 监控
  prometheus:
    image: prom/prometheus:latest
    container_name: prometheus
    ports:
      - "9090:9090"
    volumes:
      - ./prometheus.yml:/etc/prometheus/prometheus.yml
    command:
      - '--config.file=/etc/prometheus/prometheus.yml'

  # 可选：Grafana 可视化
  grafana:
    image: grafana/grafana:latest
    container_name: grafana
    ports:
      - "3000:3000"
    environment:
      - GF_SECURITY_ADMIN_PASSWORD=admin
    volumes:
      - grafana-data:/var/lib/grafana

volumes:
  grafana-data:
```

### 11.2.4 启动服务

```bash
# 启动所有服务
docker-compose up -d

# 查看状态
docker-compose ps

# 查看日志
docker-compose logs -f sandbox

# 停止服务
docker-compose down
```

## 11.3 Kubernetes 部署

### 11.3.1 Deployment

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: sandbox-runtime
  labels:
    app: sandbox-runtime
spec:
  replicas: 3
  selector:
    matchLabels:
      app: sandbox-runtime
  template:
    metadata:
      labels:
        app: sandbox-runtime
      annotations:
        prometheus.io/scrape: "true"
        prometheus.io/port: "8080"
        prometheus.io/path: "/metrics"
    spec:
      containers:
      - name: sandbox
        image: registry.example.com/core-ai/sandbox:1.0.0
        ports:
        - containerPort: 8080
          name: http
        env:
        - name: MAX_CONCURRENT
          value: "10"
        - name: MAX_OUTPUT_SIZE
          value: "30"
        - name: LOG_LEVEL
          value: "info"
        resources:
          requests:
            cpu: "1"
            memory: "1Gi"
          limits:
            cpu: "2"
            memory: "2Gi"
        securityContext:
          runAsNonRoot: true
          runAsUser: 1001
          readOnlyRootFilesystem: true
          allowPrivilegeEscalation: false
          capabilities:
            drop:
            - ALL
        volumeMounts:
        - name: workspace
          mountPath: /workspace
        - name: tmp
          mountPath: /tmp
        livenessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 10
          periodSeconds: 30
          timeoutSeconds: 5
          failureThreshold: 3
        readinessProbe:
          httpGet:
            path: /health
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 10
          timeoutSeconds: 3
          failureThreshold: 3
      volumes:
      - name: workspace
        emptyDir:
          sizeLimit: 1Gi
      - name: tmp
        emptyDir:
          sizeLimit: 500Mi
```

```yaml
# ingress.yaml

kind: Ingress
metadata:
  name: sandbox-runtime
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"

  ingressClassName: nginx
  rules:
  - host: sandbox.example.com
    http:
      paths:
      - path: /
        pathType: Prefix
        backend:
          service:
            name: sandbox-runtime
            port:
              number: 8080
```

### 11.3.4 HPA (自动伸缩)

```yaml
# hpa.yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: sandbox-runtime
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: sandbox-runtime
  minReplicas: 3
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 70
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
```

## 11.4 配置管理

### 11.4.1 环境变量配置

```bash
# 基础配置
MAX_CONCURRENT=10          # 最大并发任务数
MAX_OUTPUT_SIZE=30         # 最大输出大小 (KB)
LOG_LEVEL=info             # 日志级别 (debug/info/warn/error)
WORKSPACE_DIR=/workspace   # 工作目录

# 超时配置
DEFAULT_TIMEOUT=120        # 默认超时时间 (秒)
MAX_TIMEOUT=600            # 最大超时时间 (秒)

# 资源限制
MAX_FILE_SIZE=100          # 最大文件大小 (MB)
MAX_SNAPSHOT_SIZE=200      # 最大快照大小 (MB)

# 安全配置
ENABLE_NETWORK=false       # 是否启用网络
ALLOWED_PATHS=/workspace,/tmp  # 允许访问的路径
```

```yaml

apiVersion: v1
kind: ConfigMap
```

### 11.5.4 告警规则

```yaml
# alerting-rules.yml
groups:
- name: sandbox-alerts
  rules:
  
  # 高错误率告警
  - alert: HighErrorRate
    expr: rate(http_requests_total{status=~"5.."}[5m]) / rate(http_requests_total[5m]) > 0.05
    for: 5m
    labels:
      severity: critical
    annotations:
      summary: "高错误率: {{ $value | humanizePercentage }}"
  
  # 高延迟告警
  - alert: HighLatency
    expr: histogram_quantile(0.95, rate(http_request_duration_seconds_bucket[5m])) > 2
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "高延迟: {{ $value }}s"
  
  # 磁盘空间告警
  - alert: DiskSpaceLow
    expr: sandbox_workspace_disk_usage_bytes / 1073741824 > 0.8
    for: 5m
    labels:
      severity: warning
    annotations:
      summary: "磁盘空间不足: {{ $value | humanize1024 }}iB"
  
  # 并发任务告警
  - alert: TooManyConcurrentTasks
    expr: sandbox_tasks_concurrent > 8
    for: 2m
    labels:
      severity: warning
    annotations:
      summary: "并发任务过多: {{ $value }}"
```

## 11.7 备份恢复

### 11.7.1 工作区备份

```bash
# 备份工作区
kubectl exec -it deployment/sandbox-runtime -- \
  tar -czf /tmp/workspace-backup.tar.gz /workspace

# 复制到本地
kubectl cp sandbox-runtime-xxx-yyy:/tmp/workspace-backup.tar.gz ./workspace-backup.tar.gz

# 定时备份 (CronJob)
```

```yaml
# backup-cronjob.yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: sandbox-backup
spec:
  schedule: "0 2 * * *"  # 每天凌晨 2 点
  jobTemplate:
    spec:
      template:
        spec:
          containers:
          - name: backup
            image: busybox
            command:
            - /bin/sh
            - -c
            - |
              kubectl exec deployment/sandbox-runtime -- \
                tar -czf /tmp/backup-$(date +%Y%m%d).tar.gz /workspace
              kubectl cp sandbox-runtime-xxx:/tmp/backup-*.tar.gz /backup/
            volumeMounts:
            - name: backup
              mountPath: /backup
          volumes:
          - name: backup
            persistentVolumeClaim:
              claimName: backup-pvc
          restartPolicy: OnFailure
```

### 11.7.2 恢复工作区

```bash
# 上传备份文件
kubectl cp ./workspace-backup.tar.gz sandbox-runtime-xxx:/tmp/

# 解压恢复
kubectl exec -it deployment/sandbox-runtime -- \
  tar -xzf /tmp/workspace-backup.tar.gz -C /

# 验证恢复
kubectl exec -it deployment/sandbox-runtime -- ls -la /workspace
```

## 11.11 最佳实践
