## 2.2 构建 Docker 镜像

### 2.2.1 查看 Dockerfile

```dockerfile
# 核心构建步骤
FROM golang:1.22-alpine AS builder

WORKDIR /build
COPY . .
RUN go build -o sandbox-runtime

FROM alpine:3.19

# 安装必要工具
RUN apk add --no-cache \
    bash python3 nodejs npm

# 创建非 root 用户
RUN adduser -D -u 1001 sandbox

# 创建工作目录
RUN mkdir -p /workspace /skill && \
    chown sandbox:sandbox /workspace /skill

# 复制可执行文件
COPY --from=builder /build/sandbox-runtime /usr/local/bin/

# 切换到非 root 用户
USER sandbox

# 暴露端口
EXPOSE 8080

# 启动服务
CMD ["sandbox-runtime"]
```

💡 **设计要点**:
- 多阶段构建，减小镜像大小
- 安装 bash、python3、nodejs
- 非 root 用户运行 (UID 1001)
- 创建 `/workspace` 和 `/skill` 目录

### 2.2.2 构建镜像

```bash
# 构建镜像
docker build -t core-ai-sandbox:latest .

# 查看镜像
docker images | grep core-ai-sandbox
# 应看到:
# core-ai-sandbox    latest    abc123def456    1 minute ago    245MB
```

💡 **说明**:
- 镜像大小约 245MB
- 包含 Go 程序 + bash + python3 + nodejs
- 可直接运行

### 2.2.3 标记版本（可选）

```bash
# 标记版本
docker tag core-ai-sandbox:latest core-ai-sandbox:v1.0.0

# 查看所有版本
docker images | grep core-ai-sandbox
# core-ai-sandbox    latest    abc123    2 minutes ago    245MB
# core-ai-sandbox    v1.0.0    abc123    2 minutes ago    245MB
```

## 2.3 运行容器

### 2.3.1 基础运行

```bash
# 运行容器
docker run -d \
  --name sandbox \
  -p 8080:8080 \
  core-ai-sandbox:latest

# 查看容器状态
docker ps | grep sandbox
# 应看到: abc123  core-ai-sandbox:latest  "/usr/local/bin/sand…"  1 second ago  Up 1 second  0.0.0.0:8080->8080/tcp  sandbox
```

💡 **参数说明**:
- `-d`: 后台运行
- `--name sandbox`: 容器名称
- `-p 8080:8080`: 端口映射

### 2.3.2 查看日志

```bash
# 查看容器日志
docker logs sandbox

# 应看到:
# runtime version: dev
# core-ai-sandbox-runtime starting on :8080, workspace=/workspace, maxAsync=5
```

💡 **日志内容**:
- 运行时版本
- 监听端口
- 工作目录
- 最大并发数

### 2.3.3 带挂载运行

```bash
# 创建本地工作目录
mkdir -p /tmp/sandbox-workspace

# 挂载工作目录
docker run -d \
  --name sandbox \
  -p 8080:8080 \
  -v /tmp/sandbox-workspace:/workspace \
  core-ai-sandbox:latest

# 查看挂载
docker inspect sandbox | grep -A 5 "Mounts"
```

💡 **说明**: 
- 挂载 `/workspace` 可持久化文件
- 容器停止后文件保留
- 便于调试和查看

### 2.3.4 带资源限制运行

```bash
# 限制 CPU 和内存
docker run -d \
  --name sandbox \
  -p 8080:8080 \
  --cpus="2.0" \
  --memory="1g" \
  --memory-swap="1g" \
  core-ai-sandbox:latest

# 查看资源使用
docker stats sandbox
```

💡 **生产建议**:
- 限制 CPU: `--cpus="2.0"`
- 限制内存: `--memory="1g"`
- 禁止网络: `--network=none`

### 2.3.5 进入容器（调试用）

```bash
# 进入容器 shell
docker exec -it sandbox /bin/bash

# 在容器内执行命令
whoami
# sandbox

pwd
# /

ls -la /workspace
# total 8
# drwxr-xr-x    2 sandbox  sandbox     4096  ...  .
# drwxr-xr-x    1 root     root        4096  ...  ..

# 退出容器
exit
```

### 2.4.6 异步任务

```bash
# 提交异步任务
curl -X POST http://localhost:8080/execute \
  -H "Content-Type: application/json" \
  -d '{
    "tool": "run_bash_command",
    "arguments": "{\"command\": \"sleep 5 && echo Done\", \"run_in_background\": true}"
  }'

# 应返回:
# {
#   "status": "pending",
#   "result": "task submitted: task-1",
#   "task_id": "task-1"
# }

# 应返回:
# {
#   "status": "pending",
#   "result": "",
#   "task_id": "task-1"
# }

curl http://localhost:8080/tasks/task-1

# 应返回:
# {
#   "status": "completed",
#   "result": "Done\n",
#   "task_id": "task-1",
#   "duration_ms": 5012
# }
```

💡 **说明**:
- `run_in_background: true` 触发异步执行
- 立即返回 `task_id`
- 通过 `/tasks/{id}` 轮询状态

### 2.4.8 快照系统

#### 捕获快照

```bash
# 捕获快照
curl -X POST http://localhost:8080/snapshot \
  -o snapshot.tar.gz

# 查看快照文件
ls -lh snapshot.tar.gz
# 应看到: -rw-r--r--  1 user  staff   1.2K  ...  snapshot.tar.gz

# 查看快照内容
tar -tzf snapshot.tar.gz | head -10
# 应看到:
# manifest.json
# roots/tmp/...
# roots/workspace/test.txt
```

💡 **说明**:
- 返回 tar.gz 格式
- 包含 manifest.json
- 包含 `/tmp`、`/skill`、`/workspace` 的文件

#### 恢复快照

```bash
# 计算 SHA256
SHA=$(shasum -a 256 snapshot.tar.gz | cut -d' ' -f1)

# 恢复快照
curl -X POST http://localhost:8080/snapshot/restore \
  -H "X-Snapshot-Sha256: $SHA" \
  -H "Content-Type: application/gzip" \
  --data-binary @snapshot.tar.gz

# 应返回:
# {
#   "status": "ok",
#   "files": 5
# }
```

💡 **说明**:
- 必须提供 SHA256 校验和
- 防止篡改
- 返回恢复的文件数量

## 2.5 常见问题排查

### 2.5.1 容器启动失败

**症状**:
```bash
docker ps
# 看不到 sandbox 容器
```

**排查步骤**:
```bash
# 1. 查看容器日志
docker logs sandbox

# 2. 查看容器状态
docker inspect sandbox | grep -A 5 "State"

# 3. 检查端口占用
lsof -i :8080
```

**解决方案**:
```bash
# 如果端口被占用，使用其他端口
docker run -d -p 8081:8080 --name sandbox core-ai-sandbox:latest

# 如果容器崩溃，查看详细日志
docker logs sandbox 2>&1 | tail -50
```

### 2.5.2 工具执行失败

**症状**:
```json
{
  "status": "failed",
  "result": "command not found"
}
```

**排查步骤**:
```bash
# 1. 进入容器检查工具
docker exec -it sandbox /bin/bash

# 2. 检查 bash 是否安装
which bash
# /bin/bash

# 3. 检查 python 是否安装
which python3
# /usr/bin/python3

# 4. 检查 PATH
echo $PATH
# /usr/local/bin:/usr/bin:/bin
```

**解决方案**:
```bash
# 如果工具缺失，需要重新构建镜像
# 修改 Dockerfile 添加缺失的工具
# 然后重新构建
docker build -t core-ai-sandbox:latest .
```

### 2.5.3 文件权限错误

**症状**:
```json
{
  "status": "failed",
  "result": "permission denied"
}
```

**排查步骤**:
```bash
# 1. 检查容器用户
docker exec sandbox whoami
# sandbox

# 2. 检查文件权限
docker exec sandbox ls -la /workspace
# 应看到: drwxr-xr-x  2 sandbox  sandbox  ...

# 3. 检查挂载目录权限
ls -la /tmp/sandbox-workspace
```

**解决方案**:
```bash
# 确保挂载目录属于 UID 1001
sudo chown -R 1001:1001 /tmp/sandbox-workspace

# 或者不挂载，使用容器内目录
docker run -d --name sandbox -p 8080:8080 core-ai-sandbox:latest
```

### 2.5.4 内存不足

**症状**:
```bash
docker ps
# 容器不断重启
```

**排查步骤**:
```bash
# 1. 查看 OOM 日志
dmesg | grep -i oom

# 2. 查看容器资源使用
docker stats sandbox
```

**解决方案**:
```bash
# 增加内存限制
docker run -d \
  --name sandbox \
  -p 8080:8080 \
  --memory="2g" \
  core-ai-sandbox:latest
```

### 2.5.5 MCP 服务器启动失败

**症状**:
```json
{
  "status": "error",
  "error": "mcp server not ready within 120s"
}
```

**排查步骤**:
```bash
# 1. 查看容器日志
docker logs sandbox | grep mcp

# 2. 检查命令是否存在
docker exec sandbox which npx
# /usr/bin/npx

# 3. 手动测试命令
docker exec sandbox npx -y @modelcontextprotocol/server-filesystem --help
```

**解决方案**:
```bash
# 如果命令执行慢，增加超时时间
# 修改 mcp.go: const mcpStartupTimeout = 180 * time.Second

# 重新构建镜像
docker build -t core-ai-sandbox:latest .
```
