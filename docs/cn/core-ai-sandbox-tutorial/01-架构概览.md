### 1.1.2 分层架构

sandbox-runtime 采用**单体架构**，但内部按功能清晰分层：

```
┌─────────────────────────────────────────┐
│         HTTP 层 (HTTP Layer)            │
│  - 路由分发                             │
│  - 请求解析                             │
│  - 响应序列化                           │
│  - 日志记录                             │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│        业务层 (Business Layer)          │
│  - 工具执行器 (Tool Executor)           │
│  - MCP 进程管理器 (MCP Process Manager) │
│  - 快照管理器 (Snapshot Manager)        │
│  - 异步任务注册表 (Task Registry)       │
└─────────────────────────────────────────┘
                  ↓
┌─────────────────────────────────────────┐
│        系统层 (System Layer)            │
│  - 进程管理 (Process Management)        │
│  - 文件系统 (File System)               │
│  - 网络通信 (Network I/O)               │
│  - 环境变量 (Environment Variables)     │
└─────────────────────────────────────────┘
```

💡 **设计意图**: 
- **简单直接**: 单体架构，无需分布式协调
- **功能清晰**: 按职责分层，易于维护
- **性能优异**: 无网络开销，本地调用

## 1.2 核心组件

### 1.2.1 HTTP Server

**位置**: `main.go:155-198`

**职责**:
- 接收和路由 HTTP 请求
- 解析请求参数
- 调用对应的处理器
- 返回响应结果
- 记录请求日志

**核心代码**:
```go
func main() {
    // 配置路由
    http.HandleFunc("/health", handleHealth)
    http.HandleFunc("/execute", handleExecute)
    http.HandleFunc("/tasks/", handleTaskPoll)
    http.HandleFunc("/files/content", handleFileContent)
    http.HandleFunc("/files/upload", handleFileUpload)
    http.HandleFunc("/skills/", handleSkillMaterialize)
    http.HandleFunc("/mcp/start", handleMcpStart)
    http.HandleFunc("/mcp/stop", handleMcpStop)
    http.HandleFunc("/mcp", handleMcp)
    http.HandleFunc("/snapshot", handleSnapshot)

```

💡 **设计要点**:
- 使用标准库 `net/http`，无第三方依赖
- 中间件模式记录日志
- 支持并发请求处理

### 1.2.2 Tool Executor

**位置**: `main.go:143-151, 523-875`

**职责**:
- 执行 bash 命令
- 执行 Python 脚本
- 文件读取/写入/编辑
- 文件搜索 (glob/grep)

**工具映射表**:
```go
var toolMap = map[string]toolExecutor{
    "run_bash_command":  executeBash,
    "run_python_script": executePython,
    "read_file":         executeReadFile,
    "write_file":        executeWriteFile,
    "edit_file":         executeEditFile,
    "glob_file":         executeGlob,
    "grep_file":         executeGrep,
}
```

**核心函数**:
```go
// Bash 命令执行
func executeBash(args string) (string, string) {
    var parsed struct {
        Command string `json:"command"`
        Timeout int    `json:"timeout"`
    }
    json.Unmarshal([]byte(args), &parsed)
    
    // 设置超时
    ctx, cancel := context.WithTimeout(context.Background(), timeout)
    defer cancel()
    
    // 执行命令
    cmd := exec.CommandContext(ctx, "bash", "-c", parsed.Command)
    cmd.Dir = workspaceDir
    cmd.Env = minimalEnv()
    output, err := cmd.CombinedOutput()
    
    return string(output), "completed"
}
```

💡 **设计要点**:
- 统一的工具接口 `func(args string) (string, string)`
- 支持超时控制
- 输出截断 (30KB)
- 安全的环境变量

### 1.2.3 MCP Process Manager

**位置**: `mcp.go:44-235`

**职责**:
- 启动 MCP 服务器进程
- 管理进程生命周期
- JSON-RPC 通信
- 健康检查

**核心结构**:
```go
type McpProcessManager struct {
    mu      sync.RWMutex
    servers map[string]*McpServerProcess
}

type McpServerProcess struct {
    ID      string
    Cmd     *exec.Cmd
    stdin   io.WriteCloser
    stdout  *bufio.Reader
    mu      sync.Mutex
}
```

**核心流程**:
```
1. 接收启动请求
   ↓
2. 创建子进程 (exec.Command)
   ↓
3. 等待进程就绪 (crash detection + readiness probe)
   ↓
4. 返回进程 ID
   ↓
5. 处理 JSON-RPC 请求 (stdin/stdout)
   ↓
6. 监控进程退出
```

💡 **设计要点**:
- 两阶段启动：崩溃检测 + 就绪探测
- 支持并发 JSON-RPC 请求
- 自动清理退出进程
- 超时控制 (120s)

### 1.2.4 Snapshot Manager

**位置**: `snapshot.go:1-367`

**职责**:
- 捕获沙箱状态
- 恢复沙箱状态
- 管理快照文件

**核心功能**:
```go
// 捕获快照
```

💡 **设计要点**:

### 1.2.5 Task Registry

**位置**: `main.go:62-124`

**职责**:
- 管理异步任务
- 控制并发数量
- 任务状态查询
- 自动清理完成的任务

**核心结构**:
```go
type TaskRegistry struct {
    mu            sync.Mutex
    tasks         map[string]*AsyncTask
    running       int32
    maxConcurrent int32
    nextID        atomic.Int64
}

type AsyncTask struct {
    ID         string
    Tool       string
    Status     string  // pending, completed, failed, timeout
    Result     string
    DurationMs int64
    CreatedAt  time.Time
    DoneAt     time.Time
}
```

💡 **设计要点**:
- 并发安全 (sync.Mutex + atomic)
- 限制最大并发数 (默认 5)
- 自动清理 (5 分钟清理一次，保留 30 分钟)
- 支持轮询查询

```

    ↓

  "tool": "run_bash_command",

    ↓
handleExecute()
    ↓
解析 ExecuteRequest
    ↓

    ↓
检查是否异步执行
    ├─ 是 → taskRegistry.Submit()
    │       ↓
    │       返回 task_id
    │       ↓
    │       客户端轮询 GET /tasks/{id}
    │
    └─ 否 → executor(args)
            ↓
            执行工具
            ↓
            截断输出 (30KB)
            ↓
            返回结果
```

```
客户端请求
    ↓

  "id": "server-1",

  "args": ["-y", "@modelcontextprotocol/server-filesystem"]
}
    ↓

    ↓

    ↓

  "id": "server-1",
  "status": "running",
  "pid": 12345
}
```

## 1.5 设计原则

### 1.5.1 安全性优先

```go
// 1. 路径安全
func resolvePath(requested string) string {
    if !filepath.IsAbs(requested) {
        requested = filepath.Join(workspaceDir, requested)
    }
    return filepath.Clean(requested)
}

// 2. 环境变量限制
func minimalEnv() []string {
    return []string{
        "PATH=/usr/local/bin:/usr/bin:/bin",
        "HOME=/tmp",
        "LANG=en_US.UTF-8",
    }
}

// 3. 输出截断
func truncateOutput(output string) string {
    if len(output) > maxOutputSize {
        return output[:maxOutputSize] + "\n... [truncated]"
    }
    return output
}
```

💡 **原则**: 
- 所有文件操作限制在 `/workspace` 内
- 最小化环境变量
- 防止内存溢出 (输出截断)

### 1.5.2 资源限制

```go
// 1. 命令超时
const defaultBashTimeoutMs = 120_000  // 2 分钟
const maxBashTimeoutMs = 600_000      // 10 分钟

// 2. 文件大小
const maxDownloadFileSize = 100 << 20  // 100 MB
const maxUploadFileSize = 20 << 20     // 20 MB

// 3. 并发控制
var maxConcurrent int32 = 5  // 最大并发任务数

// 4. 快照大小
var maxSnapshotTotalSize = int64(2 << 30)  // 2 GB
```

💡 **原则**:
- 防止长时间运行
- 防止大文件占用资源
- 防止并发过高
- 防止快照过大

### 1.5.3 错误处理

```go
// 1. 进程启动失败
if err := cmd.Start(); err != nil {
    return nil, fmt.Errorf("start command: %w", err)
}

// 2. 超时处理
if ctx.Err() == context.DeadlineExceeded {
    return result + "\n... timed out", "timeout"
}

// 3. 进程崩溃检测
select {
case waitErr := <-exitCh:
    return nil, fmt.Errorf("process exited: %w", waitErr)
case <-time.After(crashDetectWindow):
    // 继续
}
```

💡 **原则**:
- 明确的错误信息
- 区分错误类型 (超时/崩溃/其他)
- 优雅降级 (截断输出而非失败)

### 1.5.4 可观测性

```go
// 1. 请求日志
log.Printf("request started: method=%s path=%s", r.Method, path)

// 2. 工具执行日志
log.Printf("tool executed: tool=%s duration=%dms", tool, duration)

// 3. MCP 进程日志
log.Printf("[mcp:%s] started: command=%s pid=%d", id, command, pid)
log.Printf("[mcp:%s stderr] %s", id, line)

// 4. 快照日志
log.Printf("snapshot captured: files=%d", count)
```

💡 **原则**:
- 结构化日志
- 关键操作记录
- 便于问题排查
