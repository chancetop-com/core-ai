## 12.1 测试策略

### 12.1.1 测试金字塔

```
         ╱╲
        ╱  ╲
       ╱ E2E╲         ← 端到端测试 (10%)
      ╱──────╲
     ╱        ╲
    ╱ 集成测试  ╲      ← 集成测试 (20%)
   ╱────────────╲
  ╱              ╲
 ╱   单元测试     ╲   ← 单元测试 (70%)
╱──────────────────╲
```

### 12.1.2 测试类型

| 测试类型 | 测试对象 | 测试目标 | 执行频率 |
|---------|---------|---------|---------|
| **单元测试** | 函数/方法 | 验证逻辑正确性 | 每次提交 |
| **集成测试** | 模块交互 | 验证模块协作 | 每次提交 |
| **API 测试** | HTTP 接口 | 验证接口行为 | 每次提交 |
| **性能测试** | 系统整体 | 验证性能指标 | 每周/发版前 |
| **安全测试** | 安全机制 | 验证安全防护 | 每月/发版前 |
| **端到端测试** | 完整流程 | 验证用户场景 | 发版前 |

### 12.1.3 测试原则

✅ **必须遵循**:
- **独立性**: 测试之间互不依赖
- **可重复性**: 多次运行结果一致
- **快速反馈**: 单元测试 < 1秒
- **清晰命名**: 测试名称描述测试场景
- **单一职责**: 一个测试验证一个行为

❌ **避免**:
- 测试之间相互依赖
- 依赖外部环境（网络、数据库）
- 测试执行时间过长
- 测试逻辑过于复杂
- 一个测试验证多个行为

```go
func TestPerformance_HealthEndpoint(t *testing.T) {
    server := setupTestServer()
    defer server.Close()
    
    // 测试 100 次请求
    var totalDuration time.Duration
    iterations := 100
    
    for i := 0; i < iterations; i++ {
        start := time.Now()
        resp, err := http.Get(server.URL + "/health")
        duration := time.Since(start)
        
        if err != nil {
            t.Fatalf("Request failed: %v", err)
        }
        resp.Body.Close()
        
        totalDuration += duration
    }
    
    avgDuration := totalDuration / time.Duration(iterations)
    
    // 验证平均响应时间 < 10ms
    if avgDuration > 10*time.Millisecond {
        t.Errorf("Average response time too slow: %v", avgDuration)

}
```

```go
func TestPathTraversal_Attacks(t *testing.T) {

        "/etc/passwd",
        "/workspace/../etc/passwd",

            // 应该返回 400 Bad Request

            }
        })
    }
}
```

```bash
# 打开 HTML 报告
open coverage.html
```

### 12.8.2 覆盖率目标

```yaml

  unit:
    line: 80%      # 行覆盖率
    branch: 70%    # 分支覆盖率

    api: 100%      # API 覆盖率
```

## 12.10 测试最佳实践

### 12.10.1 测试命名

✅ **推荐**:
```go
// 格式: Test<函数名>_<场景>_<预期结果>
func TestExecuteBash_ValidCommand_ReturnsOutput(t *testing.T)
func TestExecuteBash_InvalidCommand_ReturnsError(t *testing.T)
func TestExecuteBash_Timeout_ReturnsTimeout(t *testing.T)
```

❌ **避免**:
```go
func Test1(t *testing.T)
func TestBash(t *testing.T)
func TestExecute(t *testing.T)
```

### 12.10.2 测试结构

✅ **推荐**: Given-When-Then 模式
```go
func TestExample(t *testing.T) {
    // Given (准备测试数据和环境)
    input := "test input"
    
    // When (执行被测试的代码)
    result := process(input)
    
    // Then (验证结果)
    assert.Equal(t, "expected", result)
}
```

### 12.10.3 测试隔离

✅ **推荐**:
```go
func TestExample(t *testing.T) {
    // 使用临时目录
    tempDir := t.TempDir()
    
    // 使用唯一的数据
    testID := fmt.Sprintf("test-%d", time.Now().UnixNano())
    
    // 清理资源
    t.Cleanup(func() {
        // 清理代码
    })
}
```

❌ **避免**:
```go
func TestExample(t *testing.T) {
    // 使用固定的临时文件
    testFile := "/tmp/test.txt"  // 可能与其他测试冲突
    
    // 依赖外部状态
    // ...
}
```

### 12.10.4 测试数据

✅ **推荐**:
```go
// 使用测试数据生成器
func generateTestAgent() Agent {
    return Agent{
        ID:   uuid.New().String(),
        Name: fmt.Sprintf("test-agent-%d", time.Now().UnixNano()),
    }
}

// 使用表驱动测试
tests := []struct {
    name     string
    input    string
    expected string
}{
    {"case1", "input1", "output1"},
    {"case2", "input2", "output2"},
}
```

## 12.11 常见问题

### 12.11.1 测试不稳定

**问题**: 测试有时通过，有时失败

**原因**:
- 依赖外部资源（网络、文件系统）
- 使用随机数据
- 竞态条件

**解决方案**:
```go
// 使用固定的种子
rand.Seed(42)

// 使用 mock 替代外部依赖
mockDB := NewMockDatabase()

// 使用同步机制
var wg sync.WaitGroup
wg.Add(1)
go func() {
    defer wg.Done()
    // ...
}()
wg.Wait()
```

### 12.11.2 测试执行慢

**问题**: 测试执行时间过长

**原因**:
- 测试之间有依赖
- 使用真实的数据库
- 测试数据量过大

**解决方案**:
```bash
# 并行执行测试
go test -parallel 4

# 只运行特定测试
go test -run TestExecuteBash

# 跳过慢速测试
go test -short
```

### 12.11.3 Mock 过度

**问题**: 过度使用 mock，测试没有实际价值

**原因**:
- 所有依赖都被 mock
- 测试只验证 mock 调用

**解决方案**:
- 只 mock 外部依赖（数据库、网络）
- 内部逻辑使用真实实现
- 集成测试验证模块协作
