## 10.1 性能指标

### 10.1.1 关键性能指标（KPI）

| 指标 | 说明 | 目标值 |
|------|------|--------|
| **响应时间（RT）** | 请求处理时间 | < 100ms (P95) |
| **吞吐量（QPS）** | 每秒处理请求数 | > 1000 QPS |
| **并发数** | 同时处理的请求数 | > 100 |
| **错误率** | 失败请求比例 | < 0.1% |
| **资源使用率** | CPU/内存使用率 | < 70% |

### 10.1.2 性能基准测试


```go
// 自定义 goroutine 池
type WorkerPool struct {
    tasks chan func()
    wg    sync.WaitGroup
}

func NewWorkerPool(size int) *WorkerPool {
    pool := &WorkerPool{
        tasks: make(chan func(), 100),
    }
    
    // 启动固定数量的 worker
    for i := 0; i < size; i++ {
        pool.wg.Add(1)
        go func() {
            defer pool.wg.Done()
            for task := range pool.tasks {
                task()
            }
        }()
    }
    
    return pool
}

func (p *WorkerPool) Submit(task func()) {
    p.tasks <- task
}

func (p *WorkerPool) Shutdown() {
    close(p.tasks)
    p.wg.Wait()
}

// 使用
pool := NewWorkerPool(10)  // 10 个 worker
defer pool.Shutdown()

pool.Submit(func() {
    // 执行任务
})
```

💡 **Goroutine 池优势**:

### 10.6.3 自定义缓存

```go
// 简单的 LRU 缓存
type Cache struct {
    mu       sync.RWMutex
    items    map[string]*CacheItem
    maxSize  int
}

type CacheItem struct {
    Value     interface{}
    ExpiresAt time.Time
}

func NewCache(maxSize int) *Cache {
    return &Cache{
        items:   make(map[string]*CacheItem),
        maxSize: maxSize,
    }
}

func (c *Cache) Get(key string) (interface{}, bool) {
    c.mu.RLock()
    defer c.mu.RUnlock()
    
    item, exists := c.items[key]
    if !exists || time.Now().After(item.ExpiresAt) {
        return nil, false
    }
    
    return item.Value, true
}

func (c *Cache) Set(key string, value interface{}, ttl time.Duration) {
    c.mu.Lock()
    defer c.mu.Unlock()
    
    // 清理过期项
    if len(c.items) >= c.maxSize {
        c.evict()
    }
    
    c.items[key] = &CacheItem{
        Value:     value,
        ExpiresAt: time.Now().Add(ttl),
    }
}

func (c *Cache) evict() {
    now := time.Now()
    for key, item := range c.items {
        if now.After(item.ExpiresAt) {
            delete(c.items, key)
        }
    }
}
```

💡 **自定义缓存优势**:
- 灵活控制缓存策略
- 支持 TTL 过期
- 自动清理过期项

## 10.11 性能调优案例

### 10.11.1 案例 1: 高延迟问题

**问题**: 文件下载延迟高（P95 > 1s）

**分析**:
```bash
# 使用 pprof 分析
curl -o cpu.prof http://localhost:6060/debug/pprof/profile?seconds=30
go tool pprof cpu.prof

# 发现热点：大量内存分配
(pprof) top 10
```

**根因**: 每次下载都分配新的缓冲区

**优化**:
```go
// 优化前
func handleFileContent(w http.ResponseWriter, r *http.Request) {
    data, err := ioutil.ReadFile(path)  // 一次性读取整个文件
    w.Write(data)
}

// 优化后
func handleFileContent(w http.ResponseWriter, r *http.Request) {
    file, err := os.Open(path)
    defer file.Close()
    
    // 流式传输
    io.Copy(w, file)
}
```

**效果**: P95 延迟从 1.2s 降低到 0.15s（降低 87%）

### 10.11.2 案例 2: 内存泄漏

**问题**: 容器内存持续增长，最终 OOM

**分析**:
```bash
# 生成内存快照
curl -o mem.prof http://localhost:6060/debug/pprof/heap
go tool pprof mem.prof

# 发现泄漏：AsyncTask 未被清理
(pprof) list TaskRegistry
```

**根因**: 完成的任务未被清理，累积在内存中

**优化**:
```go
// 添加定期清理
go func() {
    ticker := time.NewTicker(5 * time.Minute)
    for range ticker.C {
        taskRegistry.Cleanup(30 * time.Minute)
    }
}()
```

**效果**: 内存使用稳定在 200MB，不再增长

### 10.11.3 案例 3: 并发瓶颈

**问题**: QPS 无法超过 500

**分析**:
```bash
# 使用 wrk 压测
wrk -t4 -c100 -d60s http://localhost:8080/health

# 发现 CPU 使用率只有 25%（单核）
```

**根因**: Go 默认使用单核

**优化**:
```bash
# 设置 GOMAXPROCS
export GOMAXPROCS=4

# 或在代码中设置
runtime.GOMAXPROCS(4)
```

**效果**: QPS 从 500 提升到 1800（提升 260%）
