## 18.1 设计模式总览

### 18.1.1 4 个核心设计模式

core-ai 内核采用了 4 个核心设计模式，贯穿整个架构：

1. **Provider SPI 模式**：插件化扩展，统一接口
2. **Lifecycle 钩子链模式**：横切关注点，灵活扩展
3. **Builder + Assembler 模式**：复杂对象构建，关注点分离
4. **三层编排模式**：多层级任务编排，从简单到复杂

💡 **设计意图**：
- **可扩展性**：通过 SPI 和 Lifecycle，可以灵活扩展系统功能
- **可维护性**：通过 Builder + Assembler，分离构建和组装逻辑
- **可组合性**：通过三层编排，支持从简单到复杂的任务编排

### 18.1.2 设计模式应用分布

```

│                                                             │
```

## 18.2 Provider SPI 模式

### 18.2.1 模式定义

**Provider SPI（Service Provider Interface）模式**是一种插件化扩展模式，通过统一的接口定义，允许不同的实现替换默认行为。

**核心组件**：
- **Registry**：注册表，管理所有 Provider
- **Provider**：提供者接口，定义统一的行为
- **ConcreteProvider**：具体实现，提供特定功能

### 18.2.2 应用场景

| 子系统 | Registry | Provider | 具体实现 |
|---|---|---|---|
| LLM | LLMProviders | LLMProvider | LiteLLMProvider |
| 持久化 | PersistenceProviders | PersistenceProvider | FilePersistenceProvider / RedisPersistenceProvider |
| 向量库 | VectorStores | VectorStore | HnswLibVectorStore / MilvusVectorStore |
| 工具 | ToolRegistry | ToolProvider | BuiltinToolProvider / McpToolProvider |
| 技能 | SkillRegistry | SkillProvider | FileSkillProvider |
| 追踪 | TracerRegistry | Tracer | LLMTracer / AgentTracer |

### 18.2.3 代码示例

```java
// 1. 定义 Provider 接口
public interface LLMProvider {
    CompletionResponse completion(CompletionRequest request);
    EmbeddingResponse embedding(EmbeddingRequest request);
}

// 2. 定义 Registry
public class LLMProviders {
    private final Map<String, LLMProvider> providers = new ConcurrentHashMap<>();
    
    public void register(String id, LLMProvider provider) {
        providers.put(id, provider);
    }
    
    public LLMProvider get(String id) {
        return providers.get(id);
    }
    
    public LLMProvider getDefault() {
        return providers.values().iterator().next();
    }
}

// 3. 实现具体 Provider
public class LiteLLMProvider implements LLMProvider {
    @Override
    public CompletionResponse completion(CompletionRequest request) {
        // 调用 LiteLLM API
        return httpClient.post("/chat/completions", request);
    }
    
    @Override
    public EmbeddingResponse embedding(EmbeddingRequest request) {
        // 调用 embedding API
        return httpClient.post("/embeddings", request);
    }
}

// 4. 使用
var providers = new LLMProviders();
providers.register("openai", new LiteLLMProvider("openai"));
providers.register("deepseek", new LiteLLMProvider("deepseek"));

var defaultProvider = providers.getDefault();
var openaiProvider = providers.get("openai");
```

💡 **设计优势**：
- **可替换**：可以轻松替换不同的实现（如切换 LLM 供应商）
- **可扩展**：可以添加新的实现，无需修改现有代码
- **可测试**：可以用 Mock 实现进行单元测试
- **优先级**：支持多 Provider 共存，按优先级选择

💡 **使用建议**：
- 当系统需要支持多种实现时，使用 Provider SPI 模式
- 为每个 Provider 定义清晰的接口
- 使用 Registry 管理 Provider 的生命周期
- 支持优先级，允许覆盖默认实现

## 18.3 Lifecycle 钩子链模式

### 18.3.1 模式定义

**Lifecycle 钩子链模式**是一种横切关注点管理模式，通过定义一系列钩子方法，允许在关键执行点插入自定义逻辑。

**核心组件**：
- **Lifecycle**：生命周期钩子基类，定义所有钩子方法
- **ConcreteLifecycle**：具体实现，实现特定的横切逻辑
- **HookChain**：钩子链，按顺序调用所有 Lifecycle

### 18.3.2 应用场景

| Lifecycle | 作用 | 钩子方法 |
|---|---|---|
| CompressionLifecycle | 上下文压缩 | beforeModel / afterModel |
| DoomLoopLifecycle | 死循环检测 | beforeTool / afterTool |
| ReflectionLifecycle | 自我反思 | onModelResponse |
| PermissionLifecycle | 权限审批 | beforeTool |
| PlanUpdateLifecycle | 计划更新 | afterAgentRun |

### 18.3.3 代码示例

```java
// 1. 定义 Lifecycle 基类
public abstract class AbstractLifecycle {
    public void beforeAgentBuild(AgentBuilder builder) {}
    public void afterAgentBuild(Agent agent) {}
    public void beforeModel(CompletionRequest request, ExecutionContext context) {}
    public void afterModel(CompletionRequest request, CompletionResponse response, ExecutionContext context) {}
    public void beforeTool(FunctionCall call, ExecutionContext context) {}
    public void afterTool(FunctionCall call, ExecutionContext context, ToolCallResult result) {}
    public void beforeAgentRun(AtomicReference<String> query, ExecutionContext context) {}
    public void afterAgentRun(String query, AtomicReference<String> result, ExecutionContext context) {}
    public List<Message> onModelResponse(CompletionRequest request, CompletionResponse response, ExecutionContext context) {
        return null;  // 返回 null 表示接受，返回消息列表表示重试
    }
}

// 2. 实现具体 Lifecycle
public class CompressionLifecycle extends AbstractLifecycle {
    @Override
    public void beforeModel(CompletionRequest request, ExecutionContext context) {
        // 压缩消息历史
        if (request.messages.size() > 50) {
            var compressed = compressMessages(request.messages);
            request.messages = compressed;
        }
    }
}

public class DoomLoopLifecycle extends AbstractLifecycle {
    private final List<String> recentToolCalls = new ArrayList<>();
    
    @Override
    public void beforeTool(FunctionCall call, ExecutionContext context) {
        recentToolCalls.add(call.name + ":" + call.arguments);
        if (recentToolCalls.size() > 10) {
            recentToolCalls.remove(0);
        }
        
        // 检测重复模式
        if (isDoomLoop()) {
            context.injectSystemMessage("注意：你似乎陷入了重复的工具调用模式。");
        }
    }
}

// 3. 注册到 Agent
var agent = Agent.builder()
    .name("assistant")
    .systemPrompt("你是一个助手")
    .llmProvider(llmProvider)
    .lifecycle(new CompressionLifecycle())
    .lifecycle(new DoomLoopLifecycle())
    .build();

// 4. 执行时自动调用钩子
agent.execute("你好", null);
// 执行流程：
// 1. beforeAgentRun
// 2. beforeModel → CompressionLifecycle.beforeModel() 压缩消息
// 3. LLM 调用
// 4. afterModel
// 5. onModelResponse
// 6. beforeTool → DoomLoopLifecycle.beforeTool() 检测死循环
// 7. 工具执行
// 8. afterTool
// 9. afterAgentRun
```

💡 **设计优势**：
- **解耦**：横切逻辑与主逻辑分离
- **可组合**：可以组合多个 Lifecycle
- **可扩展**：可以轻松添加新的 Lifecycle
- **可测试**：每个 Lifecycle 可以独立测试

💡 **使用建议**：
- 当需要在多个执行点插入逻辑时，使用 Lifecycle 模式
- 为每个钩子方法定义清晰的语义
- 使用钩子链管理多个 Lifecycle
- 避免在钩子中执行耗时操作

## 18.4 Builder + Assembler 模式

### 18.4.1 模式定义

**Builder + Assembler 模式**是一种复杂对象构建模式，通过 Builder 收集用户配置，通过 Assembler 应用默认值和横切逻辑。

**核心组件**：
- **Builder**：构建器，收集用户配置
- **Assembler**：组装器，应用默认值和横切逻辑
- **Product**：最终产品，构建完成的对象

### 18.4.2 应用场景

| Builder | Assembler | 产品 |
|---|---|---|
| AgentBuilder | AgentAssembler | Agent |
| FlowBuilder | FlowAssembler | Flow |
| SkillBuilder | SkillAssembler | Skill |

### 18.4.3 代码示例

```java
// 1. 定义 Builder
public class AgentBuilder {
    String name;
    String systemPrompt;
    LLMProvider llmProvider;
    ToolRegistry toolRegistry;
    List<AbstractLifecycle> lifecycles = new ArrayList<>();
    
    public AgentBuilder name(String name) {
        this.name = name;
        return this;
    }
    
    public AgentBuilder systemPrompt(String systemPrompt) {
        this.systemPrompt = systemPrompt;
        return this;
    }
    
    public AgentBuilder llmProvider(LLMProvider llmProvider) {
        this.llmProvider = llmProvider;
        return this;
    }
    
    public AgentBuilder tool(ToolCall tool) {
        if (toolRegistry == null) {
            toolRegistry = new ToolRegistry();
        }
        toolRegistry.registerProvider(new ListToolProvider(List.of(tool)));
        return this;
    }
    
    public AgentBuilder lifecycle(AbstractLifecycle lifecycle) {
        lifecycles.add(lifecycle);
        return this;
    }
    
    public Agent build() {
        // 调用 Assembler 应用默认值和横切逻辑
        return AgentAssembler.assemble(this);
    }
}

// 2. 定义 Assembler
public class AgentAssembler {
    public static Agent assemble(AgentBuilder builder) {
        var agent = new Agent();
        
        // 1. 应用用户配置
        agent.setName(builder.name);
        agent.setSystemPrompt(builder.systemPrompt);
        agent.setLlmProvider(builder.llmProvider);
        agent.setToolRegistry(builder.toolRegistry);
        
        // 2. 应用默认值
        if (agent.getToolRegistry() == null) {
            agent.setToolRegistry(new ToolRegistry());
        }
        
        // 3. 应用横切逻辑
        if (builder.compressionEnabled) {
            builder.lifecycles.add(new CompressionLifecycle());
        }
        if (builder.doomLoopEnabled) {
            builder.lifecycles.add(new DoomLoopLifecycle());
        }
        
        // 4. 触发 Lifecycle 钩子
        for (var lifecycle : builder.lifecycles) {
            lifecycle.beforeAgentBuild(builder);
        }
        
        agent.setLifecycles(builder.lifecycles);
        
        for (var lifecycle : builder.lifecycles) {
            lifecycle.afterAgentBuild(agent);
        }
        
        return agent;
    }
}

// 3. 使用
var agent = Agent.builder()
    .name("assistant")
    .systemPrompt("你是一个助手")
    .llmProvider(llmProvider)
    .tool(new BashTool())
    .lifecycle(new ReflectionLifecycle())
    .build();
```

💡 **设计优势**：
- **关注点分离**：Builder 负责收集配置，Assembler 负责组装逻辑
- **默认值管理**：Assembler 统一管理默认值
- **横切逻辑**：Assembler 统一应用横切逻辑（如 Compression、DoomLoop）
- **可扩展**：可以轻松添加新的配置项和组装逻辑

💡 **使用建议**：
- 当对象构建复杂时，使用 Builder + Assembler 模式
- Builder 提供流式 API，简化使用
- Assembler 集中管理默认值和横切逻辑
- 使用 Lifecycle 钩子扩展组装逻辑

## 18.5 三层编排模式

### 18.5.1 模式定义

**三层编排模式**是一种多层级任务编排模式，从单 Agent 循环到多节点 DAG，再到跨 Agent 协作，支持从简单到复杂的任务编排。

**三层结构**：
1. **单 Agent 循环**：一个 Agent 独立运行，turn-by-turn 与 LLM 交互
2. **多节点 DAG**：多个 Agent 通过 Flow 编排成 DAG
3. **跨 Agent**：多个 Agent 通过 A2A 协议跨服务协作

### 18.5.2 应用场景

| 层级 | 组件 | 适用场景 |
|---|---|---|
| 单 Agent | Agent + ModelGateway | 简单对话、单任务 |
| 多节点 DAG | Flow + FlowNode + FlowEdge | 复杂工作流、多步骤任务 |
| 跨 Agent | A2A + RemoteAgentClient | 跨服务协作、分布式任务 |

### 18.5.3 代码示例

**第一层：单 Agent 循环**

```java
var agent = Agent.builder()
    .name("assistant")
    .systemPrompt("你是一个助手")
    .llmProvider(llmProvider)
    .tool(new BashTool())
    .build();

var result = agent.execute("请帮我写一个 Java 程序", null);
// Agent 内部循环：
// 1. 调 LLM → 生成回答
// 2. 如果需要工具 → 执行工具
// 3. 把工具结果返回给 LLM
// 4. 重复直到完成
```

**第二层：多节点 DAG**

```java
// 1. 定义节点
var classifyNode = new AgentFlowNode(classifyAgent);
var codeNode = new AgentFlowNode(codeAgent);
var testNode = new AgentFlowNode(testAgent);

// 2. 定义边
var codeEdge = new ConditionalEdge("classify", "code", 
    output -> output.contains("code"));
var testEdge = new DirectEdge("code", "test");

// 3. 构建 Flow
var flow = Flow.builder()
    .nodes(List.of(classifyNode, codeNode, testNode))
    .edges(List.of(codeEdge, testEdge))
    .build();

// 4. 执行
var result = flow.run("classify", "请帮我写一个排序算法", null);
// Flow 执行：
// 1. classifyNode 判断任务类型
// 2. 根据结果路由到 codeNode
// 3. codeNode 生成代码
// 4. 路由到 testNode
// 5. testNode 测试代码
```

**第三层：跨 Agent**

```java
// 1. 创建远程客户端
var client = HttpA2AClient.builder()
    .baseUrl("http://remote-agent:8080")
    .bearerToken("api-key")
    .build();

// 2. 发送消息
var request = new SendMessageRequest();
request.message = new Message();
request.message.role = "user";
request.message.parts = List.of(Part.text("请帮我分析这段代码"));

var result = client.send(request);

// 3. 获取结果
var task = client.getTask(new GetTaskRequest(result.task.id));
// A2A 执行：
// 1. 本地 Agent 发送消息到远程 Agent
// 2. 远程 Agent 执行任务
// 3. 本地 Agent 查询任务状态
// 4. 获取最终结果
```

💡 **设计优势**：
- **渐进式复杂度**：从简单到复杂，按需选择
- **可组合**：可以组合不同层级的编排
- **可分布式**：支持跨服务、跨进程的 Agent 协作
- **可观测**：每层都有独立的追踪和监控

💡 **使用建议**：
- 简单任务使用单 Agent 循环
- 复杂工作流使用多节点 DAG
- 跨服务协作使用 A2A 协议
- 可以组合使用不同层级

## 18.6 设计模式对比

| 模式 | 解决的问题 | 核心思想 | 适用场景 |
|---|---|---|---|
| **Provider SPI** | 插件化扩展 | 统一接口，多种实现 | LLM / 持久化 / 向量库 / 工具 |
| **Lifecycle** | 横切关注点 | 钩子链，灵活扩展 | 压缩 / 死循环检测 / 权限 / 反思 |
| **Builder+Assembler** | 复杂对象构建 | 关注点分离 | Agent / Flow / Skill 构建 |
| **三层编排** | 多层级任务编排 | 渐进式复杂度 | 单 Agent / 多节点 DAG / 跨 Agent |

## 18.7 应用建议

### 18.7.1 选择合适的模式

| 需求 | 推荐模式 |
|---|---|
| 需要支持多种实现（如多种 LLM） | Provider SPI |
| 需要在多个执行点插入逻辑 | Lifecycle |
| 对象构建复杂，需要默认值管理 | Builder + Assembler |
| 需要从简单到复杂的任务编排 | 三层编排 |

### 18.7.2 组合使用模式

在实际开发中，通常需要组合使用多个模式：

```java
// 示例：组合使用 Provider SPI + Lifecycle + Builder+Assembler

// 1. 使用 Provider SPI 选择不同的 LLM
var llmProviders = new LLMProviders();
llmProviders.register("openai", new LiteLLMProvider("openai"));
llmProviders.register("deepseek", new LiteLLMProvider("deepseek"));

// 2. 使用 Lifecycle 添加横切逻辑
var agent = Agent.builder()
    .name("assistant")
    .systemPrompt("你是一个助手")
    .llmProvider(llmProviders.get("deepseek"))  // 选择 DeepSeek
    .lifecycle(new CompressionLifecycle())      // 添加压缩
    .lifecycle(new DoomLoopLifecycle())         // 添加死循环检测
    .lifecycle(new ReflectionLifecycle())       // 添加反思
    .build();  // Builder+Assembler 构建 Agent

// 3. 使用三层编排组合多个 Agent
var flow = Flow.builder()
    .nodes(List.of(
        new AgentFlowNode(agent),
        new AgentFlowNode(testAgent)
    ))
    .edges(List.of(new DirectEdge("agent", "test")))
    .build();
```

💡 **设计建议**：
- 不要过度设计，按需选择模式
- 组合使用时，确保模式之间的职责清晰
- 优先使用已有的模式，避免重复造轮子
