## 4.1 设计思想

### 4.1.1 为什么需要 Lifecycle

**问题**：Agent 主循环中有很多横切关注点（cross-cutting concerns）：
- **上下文压缩**：消息历史太长时，用 LLM 摘要压缩旧消息
- **死循环检测**：检测重复的工具调用模式，注入提示打破循环
- **自我反思**：在 turn 结束后，让 agent 反思自己的输出
- **权限检查**：在工具执行前，检查是否需要用户确认
- **日志记录**：记录每次 LLM 调用和工具执行

**传统做法**：把这些逻辑硬编码在 agent loop 里。

**core-ai 的做法**：用 **Lifecycle 钩子链**，把横切逻辑解耦。

💡 **设计意图**：Lifecycle 是**策略模式 + 责任链模式**的结合。每个 lifecycle 实现一个或多个钩子方法，agent loop 在执行过程中调用这些钩子。这样可以：
- **解耦**：压缩、死循环检测、反思等逻辑互不干扰
- **可扩展**：你可以写自己的 lifecycle，注册到 `AgentBuilder`
- **可测试**：每个 lifecycle 可以独立测试
- **可组合**：多个 lifecycle 可以组合使用

### 4.1.2 Lifecycle 钩子链

```
Agent/ToolExecutor/ModelGateway
  │
  │ 调用 lifecycle.beforeXxx() / afterXxx()
  ▼
┌─────────────────────────────────────────┐
│  Lifecycle 钩子链                        │
│                                         │
│  ┌──────────────┐                       │
│  │ Lifecycle 1  │  ← Compression        │
│  └──────┬───────┘                       │
│         │                               │
│         ▼                               │
│  ┌──────────────┐                       │
│  │ Lifecycle 2  │  ← DoomLoop           │
│  └──────┬───────┘                       │
│         │                               │
│         ▼                               │
│  ┌──────────────┐                       │
│  │ Lifecycle 3  │  ← Reflection         │
│  └──────┬───────┘                       │
│         │                               │
│         ▼                               │
│  ┌──────────────┐                       │
│  │ Lifecycle N  │  ← 自定义             │
│  └──────────────┘                       │
└─────────────────────────────────────────┘
```

💡 **设计意图**：Lifecycle 是**责任链**，按注册顺序依次调用。每个 lifecycle 可以修改请求/响应，或者注入额外的逻辑。

## 4.2 所有钩子方法

### 4.2.1 源码

```java
public abstract class AbstractLifecycle {
    // ========== Agent 构建阶段 ==========
    
    /**
     * Agent 构建前调用
     * 可以修改 AgentBuilder 的配置
     */
    public void beforeAgentBuild(AgentBuilder agentBuilder) {
    }

    /**
     * Agent 构建后调用
     * 可以访问已构建的 Agent 实例
     */
    public void afterAgentBuild(Agent agent) {
    }

    // ========== LLM 调用阶段 ==========
    
    /**
     * 调 LLM 前调用
     * 可以修改 CompletionRequest（如添加额外的消息）
     */
    public void beforeModel(CompletionRequest completionRequest, ExecutionContext executionContext) {
    }

    /**
     * 调 LLM 后调用
     * 可以访问 CompletionResponse（如记录日志）
     */
    public void afterModel(CompletionRequest completionRequest, CompletionResponse completionResponse, ExecutionContext executionContext) {
    }

    /**
     * LLM 响应后调用（用于 inline retry）
     * 返回 null 或空列表表示接受响应
     * 返回消息列表表示注入并重试 LLM 调用
     */
    public List<Message> onModelResponse(CompletionRequest completionRequest, CompletionResponse completionResponse, ExecutionContext executionContext) {
        return null;
    }

    // ========== Agent 运行阶段 ==========
    
    /**
     * Agent 运行前调用
     * 可以修改 query（如添加前缀）
     */
    public void beforeAgentRun(AtomicReference<String> query, ExecutionContext executionContext) {
    }

    /**
     * Agent 运行前调用（带节点信息）
     * 用于 Flow 中的节点
     */
    public void beforeAgentRun(Node<?> node, AtomicReference<String> query, ExecutionContext executionContext) {
        beforeAgentRun(query, executionContext);
    }

    /**
     * Agent 运行后调用
     * 可以修改 result（如添加后缀）
     */
    public void afterAgentRun(String query, AtomicReference<String> result, ExecutionContext executionContext) {
    }

    /**
     * Agent 运行失败后调用
     * 可以记录错误日志或发送告警
     */
    public void afterAgentFailed(String query, ExecutionContext executionContext, Exception exception) {
    }

    // ========== 工具执行阶段 ==========
    
    /**
     * 工具执行前调用
     * 可以修改 FunctionCall（如添加参数）
     * 可以用于 human-in-the-loop 权限检查
     */
    public void beforeTool(FunctionCall functionCall, ExecutionContext executionContext) {
        // todo human in loop
    }

    /**
     * 工具执行后调用
     * 可以访问 ToolCallResult（如记录日志）
     */
    public void afterTool(FunctionCall functionCall, ExecutionContext executionContext, ToolCallResult toolResult) {
    }

    // ========== 工具批次阶段 ==========
    
    /**
     * 工具批次执行前调用
     * group 是并发组名（同组工具可并发执行）
     */
    public void beforeBatch(String group, List<FunctionCall> tools, ExecutionContext context) {
    }

    /**
     * 工具批次执行后调用
     */
    public void afterBatch(String group, List<FunctionCall> tools, ExecutionContext context) {
    }
}
```

### 4.2.2 钩子方法表

| 钩子方法 | 调用时机 | 参数 | 返回值 | 用途 |
|---|---|---|---|---|
| `beforeAgentBuild(builder)` | Agent 构建前 | `AgentBuilder` | void | 修改配置 |
| `afterAgentBuild(agent)` | Agent 构建后 | `Agent` | void | 访问实例 |
| `beforeModel(request, context)` | 调 LLM 前 | `CompletionRequest`, `ExecutionContext` | void | 修改请求 |
| `afterModel(request, response, context)` | 调 LLM 后 | `CompletionRequest`, `CompletionResponse`, `ExecutionContext` | void | 记录日志 |
| `onModelResponse(request, response, context)` | LLM 响应后 | 同上 | `List<Message>` 或 null | inline retry |
| `beforeAgentRun(query, context)` | Agent 运行前 | `AtomicReference<String>`, `ExecutionContext` | void | 修改 query |
| `beforeAgentRun(node, query, context)` | Agent 运行前（带节点） | `Node<?>`, `AtomicReference<String>`, `ExecutionContext` | void | Flow 节点 |
| `afterAgentRun(query, result, context)` | Agent 运行后 | `String`, `AtomicReference<String>`, `ExecutionContext` | void | 修改 result |
| `afterAgentFailed(query, context, exception)` | Agent 失败后 | `String`, `ExecutionContext`, `Exception` | void | 错误处理 |
| `beforeTool(funcCall, context)` | 工具执行前 | `FunctionCall`, `ExecutionContext` | void | 权限检查 |
| `afterTool(funcCall, context, result)` | 工具执行后 | `FunctionCall`, `ExecutionContext`, `ToolCallResult` | void | 记录日志 |
| `beforeBatch(group, tools, context)` | 批次执行前 | `String`, `List<FunctionCall>`, `ExecutionContext` | void | 批次控制 |
| `afterBatch(group, tools, context)` | 批次执行后 | 同上 | void | 批次控制 |

💡 **设计意图**：
- **`AtomicReference<String>`**：允许 lifecycle 修改 query/result（引用传递）
- **`onModelResponse` 返回 `List<Message>`**：支持 inline retry（注入消息后重试 LLM）
- **`beforeTool` 有注释 `// todo human in loop`**：提示这里可以加 human-in-the-loop 权限检查

## 4.3 调用关系详解

### 4.3.1 Agent 构建阶段

```
AgentBuilder.build()
  │
  ├─ 1. 调用 lifecycle.beforeAgentBuild(builder)
  │      └─ 可以修改 builder 的配置
  │
  ├─ 2. 构建 Agent 实例
  │
  └─ 3. 调用 lifecycle.afterAgentBuild(agent)
         └─ 可以访问已构建的 Agent
```

**调用者**：`AgentAssembler.assemble()`

💡 **设计意图**：在 Agent 构建前后插入逻辑，如动态修改配置、注入依赖等。

### 4.3.2 Agent 运行阶段

```
Agent.execute(query, variables)
  │
  ├─ 1. 调用 lifecycle.beforeAgentRun(query, context)
  │      └─ 可以修改 query（如添加前缀）
  │
  ├─ 2. 执行主循环
  │      └─ doExecute() → commandOrLoops() → chatLoops() → ...
  │
  ├─ 3a. 成功：调用 lifecycle.afterAgentRun(query, result, context)
  │       └─ 可以修改 result（如添加后缀）
  │
  └─ 3b. 失败：调用 lifecycle.afterAgentFailed(query, context, exception)
         └─ 可以记录错误日志或发送告警
```

**调用者**：`Agent.doExecute()`（推断）

💡 **设计意图**：在 Agent 运行前后插入逻辑，如修改输入/输出、错误处理等。

### 4.3.3 LLM 调用阶段

```
ModelGateway.handLLM(agent, messages, tools)
  │
  ├─ 1. 调用 lifecycle.beforeModel(request, context)
  │      └─ 可以修改 request（如添加额外的消息）
  │
  ├─ 2. 调 LLM provider
  │      └─ llmProvider.completion(request)
  │
  ├─ 3. 调用 lifecycle.afterModel(request, response, context)
  │      └─ 可以访问 response（如记录日志）
  │
  └─ 4. 调用 lifecycle.onModelResponse(request, response, context)
         └─ 返回 null/空：接受响应
         └─ 返回消息列表：注入消息并重试 LLM 调用
```

**调用者**：`ModelGateway.handLLM()`（推断）

💡 **设计意图**：
- **`beforeModel`**：可以修改请求，如添加 system message、调整 temperature 等
- **`afterModel`**：可以记录日志，如 LLM 调用的输入/输出、token 使用量等
- **`onModelResponse`**：支持 inline retry，如格式校验失败时重试

### 4.3.4 工具执行阶段

```
ToolExecutor.execute(tool, arguments, context)
  │
  ├─ 1. 调用 lifecycle.beforeTool(funcCall, context)
  │      └─ 可以修改 funcCall（如添加参数）
  │      └─ 可以用于 human-in-the-loop 权限检查
  │
  ├─ 2. 执行工具
  │      └─ tool.execute(arguments)
  │
  └─ 3. 调用 lifecycle.afterTool(funcCall, context, result)
         └─ 可以访问 result（如记录日志）
```

**调用者**：`ToolExecutor.execute()`

💡 **设计意图**：
- **`beforeTool`**：可以用于权限检查（如要求用户确认）
- **`afterTool`**：可以记录日志，如工具执行的输入/输出、耗时等

### 4.3.5 工具批次阶段

```
ToolOrchestration.executeBatch(batch)
  │
  ├─ 1. 调用 lifecycle.beforeBatch(group, tools, context)
  │      └─ group 是并发组名
  │
  ├─ 2. 并发执行工具
  │      └─ CompletableFuture + Semaphore
  │
  └─ 3. 调用 lifecycle.afterBatch(group, tools, context)
```

**调用者**：`ToolOrchestration.executeBatch()`

💡 **设计意图**：批次级别的钩子，可以用于批次控制（如限流、日志等）。

## 4.4 具体实现类

### 4.4.1 CompressionLifecycle

**文件**：`core-ai/src/main/java/ai/core/context/CompressionLifecycle.java`

**作用**：上下文压缩。当消息历史太长时，用 LLM 摘要压缩旧消息。

**核心逻辑**：

```java
public class CompressionLifecycle extends AbstractLifecycle {
    private final Compression compression;
    
    @Override
    public void beforeModel(CompletionRequest request, ExecutionContext context) {
        // 1. 检查消息历史长度
        if (request.messages.size() > compression.threshold) {
            // 2. 用 LLM 摘要压缩旧消息
            var compressed = compressMessages(request.messages, compression);
            // 3. 替换请求中的消息
            request.messages = compressed;
        }
    }
    
    private List<Message> compressMessages(List<Message> messages, Compression config) {
        // 1. 保留最近的 N 条消息
        var recent = messages.subList(messages.size() - config.keepRecent, messages.size());
        var old = messages.subList(0, messages.size() - config.keepRecent);
        
        // 2. 用 LLM 摘要压缩旧消息
        var summary = llmProvider.completionFormat(
            "请总结以下对话：\n" + formatMessages(old),
            config.summaryPrompt,
            config.model,
            String.class
        );
        
        // 3. 返回压缩后的消息
        var result = new ArrayList<Message>();
        result.add(Message.of(RoleType.SYSTEM, "以下是之前的对话摘要：\n" + summary));
        result.addAll(recent);
        return result;
    }
}
```

💡 **设计意图**：
- **`beforeModel`**：在调 LLM 前压缩消息历史
- **阈值**：只有消息数超过阈值才压缩，避免不必要的 LLM 调用
- **保留最近**：保留最近的 N 条消息，确保上下文连贯

### 4.4.2 DoomLoopLifecycle

**文件**：`core-ai/src/main/java/ai/core/agent/doomloop/DoomLoopLifecycle.java`

**作用**：死循环检测。检测重复的工具调用模式，注入提示打破循环。

**核心逻辑**：

```java
public class DoomLoopLifecycle extends AbstractLifecycle {
    private final int windowSize;  // 滑动窗口大小
    private final int threshold;   // 重复阈值
    private final List<String> recentToolCalls = new ArrayList<>();
    
    @Override
    public void beforeTool(FunctionCall funcCall, ExecutionContext context) {
        // 1. 记录工具调用
        recentToolCalls.add(funcCall.name + ":" + funcCall.arguments);
        
        // 2. 保持滑动窗口
        if (recentToolCalls.size() > windowSize) {
            recentToolCalls.remove(0);
        }
        
        // 3. 检测重复模式
        if (isDoomLoop()) {
            // 4. 注入提示打破循环
            injectBreakingPrompt(context);
        }
    }
    
    private boolean isDoomLoop() {
        // 检查最近 N 次调用中，是否有超过阈值的重复
        var counts = new HashMap<String, Integer>();
        for (var call : recentToolCalls) {
            counts.merge(call, 1, Integer::sum);
        }
        return counts.values().stream().anyMatch(c -> c >= threshold);
    }
    
    private void injectBreakingPrompt(ExecutionContext context) {
        // 注入提示，让 agent 意识到自己在死循环
        var prompt = "注意：你似乎陷入了重复的工具调用模式。请尝试不同的方法，或者直接向用户说明情况。";
        context.addSystemMessage(prompt);
    }
}
```

💡 **设计意图**：
- **滑动窗口**：只检查最近 N 次调用，避免内存爆炸
- **阈值**：只有重复次数超过阈值才触发，避免误判
- **注入提示**：不直接中断执行，而是注入提示让 agent 自己意识到问题

### 4.4.3 ReflectionLifecycle

**文件**：`core-ai/src/main/java/ai/core/reflection/ReflectionLifecycle.java`

**作用**：自我反思。在 turn 结束后，让 agent 反思自己的输出。

**核心逻辑**：

```java
public class ReflectionLifecycle extends AbstractLifecycle {
    private final ReflectionConfig config;
    
    @Override
    public List<Message> onModelResponse(CompletionRequest request, CompletionResponse response, ExecutionContext context) {
        // 1. 检查是否需要反思
        if (!shouldReflect(response)) {
            return null;  // 不需要反思，接受响应
        }
        
        // 2. 生成反思提示
        var reflectionPrompt = generateReflectionPrompt(request, response);
        
        // 3. 返回反思消息（注入后重试 LLM）
        return List.of(
            Message.of(RoleType.USER, reflectionPrompt)
        );
    }
    
    private boolean shouldReflect(CompletionResponse response) {
        // 检查响应质量（如格式校验、内容检查等）
        return config.enabled && !isValid(response);
    }
    
    private String generateReflectionPrompt(CompletionRequest request, CompletionResponse response) {
        return "请反思你刚才的回答，是否有以下问题：\n" +
               "1. 是否回答了用户的问题？\n" +
               "2. 是否有事实错误？\n" +
               "3. 是否有遗漏的信息？\n" +
               "请重新回答。";
    }
}
```

💡 **设计意图**：
- **`onModelResponse`**：在 LLM 响应后触发反思
- **inline retry**：返回反思消息，注入后重试 LLM
- **自我纠错**：让 agent 意识到自己的错误，重新回答

### 4.4.4 ResponseValidationLifecycle

**文件**：`core-ai/src/main/java/ai/core/agent/lifecycle/ResponseValidationLifecycle.java`

**作用**：响应校验。校验 LLM 输出格式（如 JSON schema）。

**核心逻辑**：

```java
public class ResponseValidationLifecycle extends AbstractLifecycle {
    private final Class<?> expectedSchema;
    
    @Override
    public List<Message> onModelResponse(CompletionRequest request, CompletionResponse response, ExecutionContext context) {
        // 1. 解析响应
        var content = response.choices.get(0).message.content;
        
        // 2. 校验格式
        try {
            JsonUtil.fromJson(content, expectedSchema);
            return null;  // 格式正确，接受响应
        } catch (Exception e) {
            // 3. 格式错误，注入提示重试
            var prompt = "你的回答格式不正确，请按照以下 JSON schema 重新回答：\n" +
                         JsonSchemaUtil.generateSchema(expectedSchema);
            return List.of(Message.of(RoleType.USER, prompt));
        }
    }
}
```

💡 **设计意图**：
- **`onModelResponse`**：校验响应格式
- **inline retry**：格式错误时，注入 schema 提示重试
- **结构化输出**：确保 LLM 输出符合预期的 JSON schema

## 4.5 自定义 Lifecycle

### 4.5.1 示例：日志 Lifecycle

```java
public class LoggingLifecycle extends AbstractLifecycle {
    private static final Logger logger = LoggerFactory.getLogger(LoggingLifecycle.class);
    
    @Override
    public void beforeAgentRun(AtomicReference<String> query, ExecutionContext context) {
        logger.info("Agent 开始执行，query={}", query.get());
    }
    
    @Override
    public void afterAgentRun(String query, AtomicReference<String> result, ExecutionContext context) {
        logger.info("Agent 执行完成，result={}", result.get());
    }
    
    @Override
    public void beforeModel(CompletionRequest request, ExecutionContext context) {
        logger.debug("调 LLM，messages={}", request.messages.size());
    }
    
    @Override
    public void afterModel(CompletionRequest request, CompletionResponse response, ExecutionContext context) {
        logger.debug("LLM 响应，tokens={}", response.usage.totalTokens);
    }
    
    @Override
    public void beforeTool(FunctionCall funcCall, ExecutionContext context) {
        logger.info("执行工具，name={}, args={}", funcCall.name, funcCall.arguments);
    }
    
    @Override
    public void afterTool(FunctionCall funcCall, ExecutionContext context, ToolCallResult result) {
        logger.info("工具执行完成，result={}", result.content);
    }
}
```

**使用**：

```java
var agent = Agent.builder()
    .name("test-agent")
    .systemPrompt("你是一个助手")
    .llmProvider(llmProvider)
    .lifecycle(new LoggingLifecycle())  // 注册 lifecycle
    .build();
```

### 4.5.2 示例：权限检查 Lifecycle

```java
public class PermissionLifecycle extends AbstractLifecycle {
    private final PermissionChecker checker;
    
    @Override
    public void beforeTool(FunctionCall funcCall, ExecutionContext context) {
        // 检查是否需要权限
        if (requiresPermission(funcCall.name)) {
            // 检查用户是否已授权
            if (!checker.hasPermission(context.getUserId(), funcCall.name)) {
                // 抛出异常，中断执行
                throw new PermissionDeniedException("用户没有权限执行工具: " + funcCall.name);
            }
        }
    }
    
    private boolean requiresPermission(String toolName) {
        // 某些工具需要权限（如删除文件、发送邮件等）
        return List.of("delete_file", "send_email").contains(toolName);
    }
}
```

💡 **设计意图**：
- **`beforeTool`**：在工具执行前检查权限
- **抛出异常**：权限不足时，抛出异常中断执行
- **灵活配置**：可以配置哪些工具需要权限

### 4.5.3 示例：限流 Lifecycle

```java
public class RateLimitLifecycle extends AbstractLifecycle {
    private final RateLimiter rateLimiter;
    
    @Override
    public void beforeModel(CompletionRequest request, ExecutionContext context) {
        // 限流：每秒最多 10 次 LLM 调用
        if (!rateLimiter.tryAcquire()) {
            throw new RateLimitExceededException("LLM 调用频率超限");
        }
    }
    
    @Override
    public void beforeTool(FunctionCall funcCall, ExecutionContext context) {
        // 限流：每秒最多 100 次工具调用
        if (!rateLimiter.tryAcquire()) {
            throw new RateLimitExceededException("工具调用频率超限");
        }
    }
}
```

💡 **设计意图**：
- **`beforeModel` / `beforeTool`**：在调用前检查限流
- **抛出异常**：超限时，抛出异常中断执行
- **保护资源**：避免过度调用 LLM 或工具

### 4.5.4 示例：Metrics Lifecycle

```java
public class MetricsLifecycle extends AbstractLifecycle {
    private final MeterRegistry meterRegistry;
    private final Timer llmTimer;
    private final Counter toolCounter;
    
    public MetricsLifecycle(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
        this.llmTimer = Timer.builder("llm.call.duration").register(meterRegistry);
        this.toolCounter = Counter.builder("tool.call.count").register(meterRegistry);
    }
    
    @Override
    public void afterModel(CompletionRequest request, CompletionResponse response, ExecutionContext context) {
        // 记录 LLM 调用耗时
        llmTimer.record(response.durationMs, TimeUnit.MILLISECONDS);
    }
    
    @Override
    public void afterTool(FunctionCall funcCall, ExecutionContext context, ToolCallResult result) {
        // 记录工具调用次数
        toolCounter.increment();
    }
}
```

💡 **设计意图**：
- **`afterModel` / `afterTool`**：在调用后记录 metrics
- **Prometheus 集成**：可以接入 Prometheus 监控
- **可观测性**：了解 LLM 和工具的调用情况
