## 20.1 调试总览

### 20.1.1 调试方法论

调试 core-ai 应用时，遵循以下方法论：

1. **观察现象**：明确问题表现（错误消息、异常行为、性能问题）
2. **收集信息**：日志、追踪、指标、配置文件
3. **假设原因**：基于信息提出可能的原因
4. **验证假设**：通过实验验证假设
5. **修复问题**：实施修复
6. **验证修复**：确认问题已解决

💡 **调试原则**：
- **从简单到复杂**：先检查配置和环境，再深入代码
- **隔离问题**：通过最小化复现隔离问题
- **使用工具**：充分利用日志、追踪、性能分析工具
- **记录过程**：记录调试过程，便于复现和学习

### 20.1.2 调试工具概览

| 工具 | 用途 | 适用场景 |

| **日志系统** | 记录执行过程 | 所有场景 |

## 20.2 日志系统

### 20.2.1 日志配置

core-ai 使用 SLF4J + Logback 作为日志框架。

**logback.xml 配置示例**：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <!-- 控制台输出 -->
    <appender name="CONSOLE" class="ch.qos.logback.core.ConsoleAppender">
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>
    
    <!-- 文件输出（滚动） -->
    <appender name="FILE" class="ch.qos.logback.core.rolling.RollingFileAppender">
        <file>logs/core-ai.log</file>
        <rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
            <fileNamePattern>logs/core-ai.%d{yyyy-MM-dd}.log</fileNamePattern>
            <maxHistory>30</maxHistory>
        </rollingPolicy>
        <encoder>
            <pattern>%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n</pattern>
        </encoder>
    </appender>
    
    <!-- core-ai 内核日志级别 -->
    <logger name="ai.core" level="DEBUG"/>
    <logger name="ai.core.agent" level="DEBUG"/>
    <logger name="ai.core.tool" level="DEBUG"/>
    <logger name="ai.core.llm" level="DEBUG"/>
    
    <!-- 第三方库日志级别 -->
    <logger name="org.apache" level="WARN"/>
    <logger name="io.netty" level="WARN"/>
    
    <!-- 根日志级别 -->
    <root level="INFO">
        <appender-ref ref="CONSOLE"/>
        <appender-ref ref="FILE"/>
    </root>
</configuration>
```

💡 **日志级别建议**：
- **ERROR**：错误信息，必须立即处理
- **WARN**：警告信息，可能有问题
- **INFO**：关键流程信息（启动、停止、重要决策）
- **DEBUG**：调试信息（详细执行过程）
- **TRACE**：追踪信息（非常详细，仅开发时使用）

### 20.2.2 关键日志点

**Agent 执行日志**：

```java
// Agent.java
logger.info("Agent [{}] starting execution, query={}", name, truncate(query));
logger.debug("Agent [{}] turn {}, messages={}", name, turnCount, messages.size());
logger.debug("Agent [{}] calling tool {}, args={}", name, toolName, truncate(args));
logger.debug("Agent [{}] tool {} completed, result={}", name, toolName, truncate(result));
logger.info("Agent [{}] execution completed, turns={}, tokens={}", name, turnCount, totalTokens);
```

**LLM 调用日志**：

```java
// LLMProvider.java
logger.debug("LLM call, model={}, messages={}, tools={}", model, messages.size(), tools.size());
logger.debug("LLM response, tokens={}, finish_reason={}", usage.totalTokens, finishReason);
```

**工具执行日志**：

```java
// ToolExecutor.java
logger.debug("Executing tool {}, args={}", toolName, truncate(args));
logger.debug("Tool {} completed, result={}", toolName, truncate(result));
logger.error("Tool {} failed", toolName, exception);
```

💡 **日志最佳实践**：
- 使用 `truncate()` 截断长文本，避免日志过大
- 使用占位符 `{}`，避免字符串拼接
- 异常日志包含完整堆栈
- 敏感信息（API key、密码）不要记录

### 20.2.3 动态调整日志级别

运行时动态调整日志级别，无需重启：

```bash

```

## 20.3 追踪与可观测性

### 20.3.1 OpenTelemetry 配置

**配置 OpenTelemetry Exporter**：

```java
// 1. 配置 OTLP Exporter（发送到 Jaeger）
var exporter = OtlpGrpcSpanExporter.builder()
    .setEndpoint("http://localhost:4317")
    .build();

// 2. 配置 Span Processor
var processor = BatchSpanProcessor.builder(exporter)
    .setMaxQueueSize(2048)
    .setMaxExportBatchSize(512)
    .setScheduleDelay(5, TimeUnit.SECONDS)
    .build();

// 3. 配置 Tracer Provider
var tracerProvider = SdkTracerProvider.builder()
    .addSpanProcessor(processor)
    .build();

// 4. 配置 OpenTelemetry
var openTelemetry = OpenTelemetrySdk.builder()
    .setTracerProvider(tracerProvider)
    .build();

// 5. 创建 Tracer
var llmTracer = new LLMTracer(openTelemetry, true);
var agentTracer = new AgentTracer(openTelemetry, true);

// 6. 注入到组件
llmProvider.setTracer(llmTracer);
agent.setTracer(agentTracer);
```

💡 **配置建议**：
- **BatchSpanProcessor**：批量发送，提高性能
- **maxQueueSize**：队列大小，防止内存溢出
- **scheduleDelay**：发送间隔，平衡延迟和性能

### 20.3.2 追踪链路分析

💡 **分析要点**：

## 20.4 常见问题排查

### 20.4.1 LLM 调用失败

**问题**：LLM API 调用失败

**症状**：
```
ai.core.llm.LLMException: Failed to call LLM API, statusCode=401
```

**排查步骤**：

1. **检查 API Key**：
```bash
echo $OPENAI_API_KEY
# 确保 API Key 正确设置
```

2. **检查网络连通性**：
```bash
curl -v https://api.openai.com/v1/models \
  -H "Authorization: Bearer $OPENAI_API_KEY"
```

3. **检查配额**：
- 登录 OpenAI Dashboard
- 检查 API 配额和使用量

4. **检查模型名称**：
```java
config.setModel("gpt-4");  // 确保模型名称正确
```

💡 **常见原因**：
- API Key 错误或过期
- 网络问题（防火墙、代理）
- 配额超限
- 模型名称错误

### 20.4.2 工具执行超时

**问题**：工具执行超时

**症状**：
```
ai.core.tool.ToolTimeoutException: Tool execution timeout after 300000ms
```

**排查步骤**：

1. **检查工具实现**：
```java
// 检查工具是否有死循环或长时间阻塞
public ToolCallResult execute(String args) {
    // 确保有超时控制
    return executeWithTimeout(args, 60000);
}
```

2. **增加超时时间**：
```java
var tool = new BashTool();
tool.setTimeoutMs(600000);  // 10 分钟
```

3. **检查外部依赖**：
```bash
# 检查外部服务是否正常
curl -v http://external-service/health
```

4. **启用 DEBUG 日志**：
```xml
<logger name="ai.core.tool" level="DEBUG"/>
```

💡 **常见原因**：
- 工具实现有死循环
- 外部服务响应慢
- 网络问题
- 资源不足（CPU、内存）

### 20.4.3 Agent 死循环

**问题**：Agent 陷入死循环

**症状**：
- Agent 不断调用相同的工具
- Token 消耗快速增长
- 执行时间过长

**排查步骤**：

1. **启用 DoomLoop 检测**：
```java
var agent = Agent.builder()
    .lifecycle(new DoomLoopLifecycle())
    .build();
```

2. **查看日志**：
```bash
grep "DoomLoop" logs/core-ai.log
# 查看检测到的重复模式
```

3. **检查工具返回**：
```java
// 确保工具返回明确的结果
public ToolCallResult execute(String args) {
    if (error) {
        return ToolCallResult.error("错误信息");
    }
    return ToolCallResult.success("成功结果");
}
```

4. **限制最大轮次**：
```java
var agent = Agent.builder()
    .maxRound(10)  // 限制最多 10 轮
    .build();
```

💡 **常见原因**：
- 工具返回不明确的结果
- 系统提示词不够清晰
- 缺少 DoomLoop 检测
- 没有最大轮次限制

### 20.4.4 内存溢出

**问题**：内存溢出（OOM）

**症状**：
```
java.lang.OutOfMemoryError: Java heap space
```

**排查步骤**：

1. **增加堆内存**：
```bash
java -Xmx4g -jar your-app.jar
```

2. **分析内存使用**：
```bash
# 使用 VisualVM 或 JProfiler
jvisualvm
```

3. **检查消息历史**：
```java
// 启用压缩
var agent = Agent.builder()
    .lifecycle(new CompressionLifecycle())
    .build();
```

4. **检查向量库**：
```java
// HNSWlib 使用内存存储，大量数据会导致 OOM
// 改用 Milvus
var vectorStore = new MilvusVectorStore("http://localhost:19530");
```

💡 **常见原因**：
- 消息历史过长
- 向量库数据量过大
- 工具结果过大
- 内存泄漏

### 20.4.5 MCP Server 连接失败

**问题**：MCP Server 连接失败

**症状**：
```
ai.core.mcp.McpException: Failed to connect to MCP server: filesystem
```

**排查步骤**：

1. **检查 MCP Server 配置**：
```java
var config = McpServerConfig.builder()

    .command("npx")

    .build();
```

2. **手动启动 MCP Server**：
```bash
npx -y @modelcontextprotocol/server-filesystem /tmp
```

3. **检查 Node.js 安装**：
```bash
node --version
npm --version
```

4. **检查网络权限**：
```bash
# 确保可以访问 npm registry
curl -v https://registry.npmjs.org
```

💡 **常见原因**：
- Node.js 未安装
- npm 网络问题
- MCP Server 包不存在
- 权限问题

## 20.5 性能优化

### 20.5.1 LLM 调用优化

**批量调用**：

```java
// 不推荐：逐个调用
for (var query : queries) {
    llmProvider.completion(query);
}

// 推荐：批量调用
var batchRequest = CompletionRequest.builder()
    .messages(queries.stream()
        .map(q -> Message.of(RoleType.USER, q))
        .toList())
    .build();
var responses = llmProvider.completionBatch(batchRequest);
```

💡 **优化效果**：减少网络往返，提高吞吐量

**缓存结果**：

```java
// 使用 Caffeine 缓存
var cache = Caffeine.newBuilder()
    .maximumSize(1000)
    .expireAfterWrite(1, TimeUnit.HOURS)
    .build();

public String completionWithCache(String query) {
    return cache.get(query, k -> llmProvider.completion(k));
}
```

💡 **优化效果**：避免重复调用，节省 Token 和费用

**流式调用**：

```java
// 不推荐：阻塞等待
var response = llmProvider.completion(request);

// 推荐：流式调用
llmProvider.completionStream(request, new StreamingCallback() {
    @Override
    public void onToken(String token) {
        System.out.print(token);  // 实时输出
    }
});
```

💡 **优化效果**：降低首字延迟，提升用户体验

### 20.5.2 工具执行优化

**并发执行**：

```java
// 不推荐：串行执行
for (var tool : tools) {
    toolExecutor.execute(tool, args);
}

// 推荐：并发执行
var orchestration = new ToolOrchestration(dispatchMap, lifecycles, toolExecutor, context);
orchestration.execute(toolCalls);  // 自动并发
```

💡 **优化效果**：多个工具并行执行，减少总耗时

**工具池化**：

```java
// 使用工具池复用工具实例
var toolPool = new ToolPool<BashTool>(10, () -> new BashTool());

var tool = toolPool.acquire();
try {
    tool.execute(args);
} finally {
    toolPool.release(tool);
}
```

💡 **优化效果**：减少工具创建开销

### 20.5.3 向量检索优化

**批量嵌入**：

```java
// 不推荐：逐个嵌入
for (var doc : documents) {
    doc.embedding = llmProvider.embedding(doc.content);
}

// 推荐：批量嵌入
var embeddings = llmProvider.embeddingBatch(
    documents.stream().map(d -> d.content).toList()
);
for (int i = 0; i < documents.size(); i++) {
    documents.get(i).embedding = embeddings.get(i);
}
```

💡 **优化效果**：减少网络往返，提高嵌入速度

**索引优化**：

```java
// HNSWlib 参数调优
var index = new HnswLibVectorStore.Builder()
    .efConstruction(200)  // 构建时搜索范围
    .efQuery(100)         // 查询时搜索范围
    .numLinks(32)         // 每个节点的连接数
    .build();
```

💡 **优化效果**：平衡检索速度和准确率

## 20.7 安全最佳实践

### 20.7.1 API Key 管理

**使用环境变量**：

```java
// 不推荐：硬编码
config.setApiKey("sk-xxx");

// 推荐：环境变量
config.setApiKey(System.getenv("OPENAI_API_KEY"));
```

💡 **安全建议**：
- 不要把 API Key 提交到代码仓库
- 使用环境变量或配置中心管理
- 定期轮换 API Key

### 20.7.2 权限控制

**工具权限**：

```java
// 危险工具需要权限
var tool = new BashTool();
tool.setNeedAuth(true);  // 需要用户确认

// Agent 构建时配置权限
var agent = Agent.builder()
    .tool(tool)
    .permissionGate(new PermissionGate())
    .build();
```

💡 **安全建议**：
- 危险工具（bash、文件操作）启用权限控制
- 使用 PermissionGate 管理权限
- 记录所有工具调用日志

### 20.7.3 沙箱隔离

**使用沙箱**：

```java
var agent = Agent.builder()
    .sandboxProvider(new DockerSandboxProvider())
    .sandboxConfig(SandboxConfig.enabled())
    .build();
```

💡 **安全建议**：
- 代码执行在沙箱中进行
- 限制沙箱资源（CPU、内存、网络）
- 定期清理沙箱

### 20.7.4 输入验证

**验证用户输入**：

```java
public ToolCallResult execute(String args) {
    var params = JsonUtil.fromJson(args, Params.class);
    
    // 验证参数
    if (params.path.contains("..")) {
        return ToolCallResult.error("Invalid path");
    }
    
    if (params.command.length() > 1000) {
        return ToolCallResult.error("Command too long");
    }
    
    // 执行命令
    return executeCommand(params);
}
```

💡 **安全建议**：
- 验证所有用户输入
- 防止路径遍历攻击
- 限制输入长度
