## 2.1 MultiAgentModule 入口

### 2.1.1 文件位置

```
core-ai/src/main/java/ai/core/MultiAgentModule.java
```

### 2.1.2 类定义

```java
public class MultiAgentModule extends Module {
    @Override
    protected void initialize() {
        var bootstrap = new AgentBootstrap(this::property);
        var result = bootstrap.initialize();
        bindResult(result);
    }
    
    private void bindResult(BootstrapResult r) {
        bind(r.llmProviders);
        bind(r.persistenceProviders);
        bind(r.vectorStores);
        bindLLMProviders(r);
        bindPersistenceProviders(r);
        bindVectorStores(r);
        bindTelemetry(r);
        bindLangfuse(r);
        bindMcp(r);
    }
    
    // ... 其他绑定方法
}
```

💡 **设计意图**：`MultiAgentModule` 是内核的 **DI 入口**。宿主应用只需 `load(new MultiAgentModule())`，就能拿到整套能力。

### 2.1.3 装载流程

```
宿主应用
  │
  │ load(new MultiAgentModule())
  ▼
MultiAgentModule.initialize()
  │
  ├─ 1. new AgentBootstrap(this::property)  ← 创建引导器，传入配置读取函数
  │
  ├─ 2. bootstrap.initialize()              ← 初始化，读配置，构造各 provider
  │      │
  │      └─ 返回 BootstrapResult（包含所有 provider 实例）
  │
  └─ 3. bindResult(result)                  ← 把 result 里的对象绑进 DI 容器
         │
         ├─ bind(r.llmProviders)            ← 绑 LLM 注册表
         ├─ bind(r.persistenceProviders)    ← 绑持久化注册表
         ├─ bind(r.vectorStores)            ← 绑向量库注册表
         ├─ bindLLMProviders(r)             ← 绑具体 LLM 实现（按名字）
         ├─ bindPersistenceProviders(r)     ← 绑具体持久化实现
         ├─ bindVectorStores(r)             ← 绑具体向量库实现
         ├─ bindTelemetry(r)                ← 绑遥测配置 + Tracer
         ├─ bindLangfuse(r)                 ← 绑 Langfuse 配置
         └─ bindMcp(r)                      ← 绑 MCP 客户端管理器
```

### 2.1.4 `Module` 基类

`MultiAgentModule` 继承自 `core.framework.module.Module`（core-ng 框架的模块基类）。

**`Module` 提供的核心方法**：

```java
public abstract class Module {
    // 子类必须实现
    protected abstract void initialize();
    
    // 绑定对象到容器
    protected <T> void bind(T instance);
    protected <T> void bind(Class<T> type, String name, T instance);
    
    // 读取配置
    protected String property(String key);
    
    // 注册 shutdown hook
    protected void onShutdown(Runnable task);
    
    // 加载其他模块
    protected void load(Module module);
}
```

💡 **设计意图**：core-ng 的 `Module` 类似 Spring 的 `@Configuration`，负责 DI 容器的配置。

### 2.1.5 宿主如何使用

**`core-ai-server` 示例**：

```java
// core-ai-server/src/main/java/ai/core/server/ServerApp.java
public class ServerApp extends App {
    @Override
    protected void initialize() {
        // 先加载内核模块
        load(new MultiAgentModule());
        
        // 再加载平台基础设施
        loadPlatformInfrastructure();
        
        // 最后加载领域模块
        loadDomainModules();
    }
}
```

**`core-ai-cli` 示例**：

```java
// core-ai-cli/src/main/java/ai/core/cli/CliApp.java
public class CliApp {
    public void start() {
        // 直接调用 AgentBootstrap
        var bootstrap = new AgentBootstrap(this::property);
        var result = bootstrap.initialize();
        
        // 用 result 构造 agent
        var agent = AgentBuilder.builder()
            .llmProvider(result.llmProviders.getDefault())
            // ...
            .build();
    }
}
```

💡 **设计意图**：server 用 `load()` 挂载模块（DI 方式），cli 直接用 `AgentBootstrap`（编程方式）。两种方式都可以，取决于宿主是否需要 DI 容器。

## 2.2 AgentBootstrap 初始化

### 2.2.1 文件位置

```
core-ai/src/main/java/ai/core/bootstrap/AgentBootstrap.java
core-ai/src/main/java/ai/core/bootstrap/BootstrapResult.java
```

### 2.2.2 类定义

```java
public class AgentBootstrap {
    private final Function<String, String> propertyReader;
    
    public AgentBootstrap(Function<String, String> propertyReader) {
        this.propertyReader = propertyReader;
    }
    
    public BootstrapResult initialize() {
        // 1. 读配置，构造各 provider
        var llmProviders = bootstrapLLMProviders();
        var persistenceProviders = bootstrapPersistenceProviders();
        var vectorStores = bootstrapVectorStores();
        var telemetryConfig = bootstrapTelemetry();
        var langfuseConfig = bootstrapLangfuse();
        var mcpClientManager = bootstrapMcp();
        
        // 2. 组装成 BootstrapResult
        return new BootstrapResult(
            llmProviders,
            persistenceProviders,
            vectorStores,
            telemetryConfig,
            langfuseConfig,
            mcpClientManager
        );
    }
    
    private LLMProviders bootstrapLLMProviders() {
        var providers = new LLMProviders();
        
        // 读配置，构造 LiteLLMProvider
        var baseUrl = propertyReader.apply("llm.base-url");
        var apiKey = propertyReader.apply("llm.api-key");
        var defaultModel = propertyReader.apply("llm.default-model");
        
        if (baseUrl != null && apiKey != null) {
            var provider = new LiteLLMProvider(
                new LLMProviderConfig(defaultModel),
                baseUrl,
                apiKey
            );
            providers.register("default", provider);
        }
        
        // 可以注册多个 provider（OpenAI、Azure、DeepSeek 等）
        // ...
        
        return providers;
    }
    
    private PersistenceProviders bootstrapPersistenceProviders() {
        var providers = new PersistenceProviders();
        
        // 默认用 TemporaryPersistenceProvider（内存）
        providers.register("temporary", new TemporaryPersistenceProvider());
        
        // 如果配置了 Redis，用 RedisPersistenceProvider
        var redisUrl = propertyReader.apply("redis.url");
        if (redisUrl != null) {
            providers.register("redis", new RedisPersistenceProvider(redisUrl));
        }
        
        // 如果配置了文件路径，用 FilePersistenceProvider
        var filePath = propertyReader.apply("persistence.file-path");
        if (filePath != null) {
            providers.register("file", new FilePersistenceProvider(filePath));
        }
        
        return providers;
    }
    
    private VectorStores bootstrapVectorStores() {
        var stores = new VectorStores();
        
        // 默认用 HnswLibVectorStore（轻量，内存）
        stores.register("hnswlib", new HnswLibVectorStore());
        
        // 如果配置了 Milvus，用 MilvusVectorStore
        var milvusUrl = propertyReader.apply("milvus.url");
        if (milvusUrl != null) {
            stores.register("milvus", new MilvusVectorStore(milvusUrl));
        }
        
        return stores;
    }
    
    // ... 其他 bootstrap 方法
}
```

### 2.2.3 初始化流程

```
AgentBootstrap.initialize()
  │
  ├─ 1. bootstrapLLMProviders()
  │      │
  │      ├─ 读 llm.base-url, llm.api-key, llm.default-model
  │      ├─ new LiteLLMProvider(config, baseUrl, apiKey)
  │      └─ providers.register("default", provider)
  │
  ├─ 2. bootstrapPersistenceProviders()
  │      │
  │      ├─ 默认: TemporaryPersistenceProvider（内存）
  │      ├─ 如果配置 redis.url: RedisPersistenceProvider
  │      └─ 如果配置 persistence.file-path: FilePersistenceProvider
  │
  ├─ 3. bootstrapVectorStores()
  │      │
  │      ├─ 默认: HnswLibVectorStore（轻量，内存）
  │      └─ 如果配置 milvus.url: MilvusVectorStore
  │
  ├─ 4. bootstrapTelemetry()
  │      │
  │      ├─ 读 telemetry.enabled
  │      ├─ 如果 enabled: 构造 LLMTracer, AgentTracer, FlowTracer, GroupTracer
  │      └─ 返回 TelemetryConfig + TracerBundle
  │
  ├─ 5. bootstrapLangfuse()
  │      │
  │      ├─ 读 langfuse.enabled, langfuse.base-url, langfuse.api-key
  │      └─ 如果 enabled: 构造 LangfusePromptConfig + LangfusePromptProvider
  │
  └─ 6. bootstrapMcp()
         │
         ├─ 读 mcp.servers（JSON 数组，定义多个 MCP server）
         └─ 如果配置: new McpClientManager(servers)
```

💡 **设计意图**：`AgentBootstrap` 是**配置驱动的**，读配置文件决定用哪些 provider。默认用最轻量的实现（Temporary/HnswLib），配置了才用重型实现（Redis/Milvus）。

### 2.2.4 配置读取机制

`AgentBootstrap` 通过 `propertyReader` 函数读配置：

```java
public AgentBootstrap(Function<String, String> propertyReader) {
    this.propertyReader = propertyReader;
}
```

**不同宿主的 propertyReader 实现**：

- **`core-ai-server`**：从 `application.yml` 或环境变量读
- **`core-ai-cli`**：从命令行参数或 `~/.core-ai/config.yml` 读
- **测试**：从 Map 或 Properties 读

💡 **设计意图**：配置读取解耦，内核不关心配置从哪里来，只关心 key-value。

## 2.3 BootstrapResult 内容详解

### 2.3.1 文件位置

```
core-ai/src/main/java/ai/core/bootstrap/BootstrapResult.java
```

### 2.3.2 类定义

```java
public record BootstrapResult(
    // 注册表
    LLMProviders llmProviders,
    PersistenceProviders persistenceProviders,
    VectorStores vectorStores,
    
    // 具体 LLM 实现（按名字）
    LiteLLMProvider liteLLMProvider,
    LiteLLMProvider openAIProvider,
    LiteLLMProvider azureProvider,
    LiteLLMProvider deepSeekProvider,
    
    // 具体持久化实现
    PersistenceProvider temporaryPersistenceProvider,
    PersistenceProvider redisPersistenceProvider,
    PersistenceProvider filePersistenceProvider,
    
    // 具体向量库实现
    VectorStore milvusVectorStore,
    VectorStore hnswLibVectorStore,
    
    // 遥测
    TelemetryConfig telemetryConfig,
    LLMTracer llmTracer,
    AgentTracer agentTracer,
    FlowTracer flowTracer,
    GroupTracer groupTracer,
    TracerBundle tracerBundle,
    
    // Langfuse
    LangfusePromptConfig langfusePromptConfig,
    LangfusePromptProvider langfusePromptProvider,
    
    // MCP
    McpClientManager mcpClientManager
)
```

💡 **设计意图**：`BootstrapResult` 是一个 **record**（Java 16+ 特性），不可变，包含所有初始化后的 provider 实例。

### 2.3.3 各字段详解

#### 注册表

| 字段 | 类型 | 作用 |
|---|---|---|
| `llmProviders` | `LLMProviders` | LLM 注册表，按 id 管理多个 `LLMProvider` |
| `persistenceProviders` | `PersistenceProviders` | 持久化注册表 |
| `vectorStores` | `VectorStores` | 向量库注册表 |

#### 具体 LLM 实现

| 字段 | 类型 | 作用 |
|---|---|---|
| `liteLLMProvider` | `LiteLLMProvider` | 默认 LLM（通过 LiteLLM 代理） |
| `openAIProvider` | `LiteLLMProvider` | OpenAI 专用（如果配置了） |
| `azureProvider` | `LiteLLMProvider` | Azure OpenAI 专用（如果配置了） |
| `deepSeekProvider` | `LiteLLMProvider` | DeepSeek 专用（如果配置了） |

💡 **设计意图**：可以配置多个 LLM provider，按名字注入。例如 `agent.llmProvider("openai")` 用 OpenAI，`agent.llmProvider("deepseek")` 用 DeepSeek。

#### 具体持久化实现

| 字段 | 类型 | 作用 |
|---|---|---|
| `temporaryPersistenceProvider` | `PersistenceProvider` | 临时持久化（内存，重启丢失） |
| `redisPersistenceProvider` | `PersistenceProvider` | Redis 持久化（分布式，重启保留） |
| `filePersistenceProvider` | `PersistenceProvider` | 文件持久化（本地，重启保留） |

#### 具体向量库实现

| 字段 | 类型 | 作用 |
|---|---|---|
| `milvusVectorStore` | `VectorStore` | Milvus 向量库（分布式，大规模） |
| `hnswLibVectorStore` | `VectorStore` | HNSWlib 向量库（轻量，内存） |

#### 遥测

| 字段 | 类型 | 作用 |
|---|---|---|
| `telemetryConfig` | `TelemetryConfig` | 遥测配置（enabled、endpoint 等） |
| `llmTracer` | `LLMTracer` | LLM 调用追踪 |
| `agentTracer` | `AgentTracer` | Agent 执行追踪 |
| `flowTracer` | `FlowTracer` | Flow 执行追踪 |
| `groupTracer` | `GroupTracer` | Group 执行追踪 |
| `tracerBundle` | `TracerBundle` | Tracer 集合（包含所有 tracer） |

#### Langfuse

| 字段 | 类型 | 作用 |
|---|---|---|
| `langfusePromptConfig` | `LangfusePromptConfig` | Langfuse 配置（enabled、baseUrl、apiKey） |
| `langfusePromptProvider` | `LangfusePromptProvider` | Langfuse 提示词提供者 |

#### MCP

| 字段 | 类型 | 作用 |
|---|---|---|
| `mcpClientManager` | `McpClientManager` | MCP 客户端管理器（管理多个 MCP server 连接） |

## 2.4 绑定顺序与机制

### 2.4.1 绑定顺序

`MultiAgentModule.bindResult()` 按以下顺序绑进 DI 容器：

```java
private void bindResult(BootstrapResult r) {
    // ① 绑注册表
    bind(r.llmProviders);
    bind(r.persistenceProviders);
    bind(r.vectorStores);
    
    // ② 绑具体 LLM 实现（按名字）
    bindLLMProviders(r);
    
    // ③ 绑具体持久化实现
    bindPersistenceProviders(r);
    
    // ④ 绑具体向量库实现
    bindVectorStores(r);
    
    // ⑤ 绑遥测
    bindTelemetry(r);
    
    // ⑥ 绑 Langfuse
    bindLangfuse(r);
    
    // ⑦ 绑 MCP
    bindMcp(r);
}
```

💡 **设计意图**：先绑注册表（接口），再绑具体实现（实现类）。这样宿主可以通过注入注册表获取默认实现，或通过名字注入特定实现。

### 2.4.2 绑定机制

#### 按类型绑定

```java
bind(r.llmProviders);  // 绑 LLMProviders 类型
```

宿主可以通过类型注入：

```java
@Inject
LLMProviders llmProviders;
```

#### 按名字绑定

```java
bind(LiteLLMProvider.class, "openai", r.openAIProvider);
bind(LiteLLMProvider.class, "azure", r.azureProvider);
bind(LiteLLMProvider.class, "deepseek", r.deepSeekProvider);
```

宿主可以通过名字注入：

```java
@Inject
@Named("openai")
LiteLLMProvider openAIProvider;
```

💡 **设计意图**：按名字绑定支持多实现共存在同一个容器，宿主可以按需选择。

### 2.4.3 `bindLLMProviders()` 详解

```java
private void bindLLMProviders(BootstrapResult r) {
    if (r.liteLLMProvider != null) {
        bind(r.liteLLMProvider);  // 绑默认 LLM
    }
    if (r.openAIProvider != null) {
        bind(LiteLLMProvider.class, "openai", r.openAIProvider);
    }
    if (r.azureProvider != null) {
        bind(LiteLLMProvider.class, "azure", r.azureProvider);
    }
    if (r.deepSeekProvider != null) {
        bind(LiteLLMProvider.class, "deepseek", r.deepSeekProvider);
    }
}
```

💡 **设计意图**：只有配置了的 provider 才会绑定。如果没配置 OpenAI，`r.openAIProvider` 就是 `null`，不会绑定。

### 2.4.4 `bindTelemetry()` 详解

```java
private void bindTelemetry(BootstrapResult r) {
    if (r.telemetryConfig != null) {
        bind(r.telemetryConfig);
    }
    if (r.llmTracer != null) {
        bind(r.llmTracer);
    }
    if (r.agentTracer != null) {
        bind(r.agentTracer);
    }
    if (r.flowTracer != null) {
        bind(r.flowTracer);
    }
    if (r.groupTracer != null) {
        bind(r.groupTracer);
    }
    if (r.tracerBundle != null) {
        bind(TracerBundle.class, r.tracerBundle);
    }
}
```

💡 **设计意图**：遥测是可选的。如果 `telemetry.enabled=false`，所有 tracer 都是 `null`，不会绑定。

### 2.4.5 `bindMcp()` 详解

```java
private void bindMcp(BootstrapResult r) {
    if (r.mcpClientManager != null) {
        bind(r.mcpClientManager);
        onShutdown(r.mcpClientManager::close);  // 注册 shutdown hook
    }
}
```

💡 **设计意图**：MCP 客户端管理器需要优雅关闭（关闭所有 MCP server 连接），所以注册了 `onShutdown` hook。

## 2.5 配置文件解析

### 2.5.1 配置文件格式

**`application.yml` 示例**（`core-ai-server`）：

```yaml
# LLM 配置
llm:
  base-url: https://api.litellm.ai/v1
  api-key: ${LITELLM_API_KEY}
  default-model: gpt-4
  
  # 可选：多个 provider
  openai:
    api-key: ${OPENAI_API_KEY}
  azure:
    api-key: ${AZURE_API_KEY}
    endpoint: https://xxx.openai.azure.com
  deepseek:
    api-key: ${DEEPSEEK_API_KEY}

# 持久化配置
persistence:
  file-path: ./data/persistence

# Redis 配置（可选）
redis:
  url: redis://localhost:6379

# 向量库配置
milvus:
  url: http://localhost:19530

# 遥测配置
telemetry:
  enabled: true
  endpoint: http://localhost:4318  # OTLP endpoint

# Langfuse 配置（可选）
langfuse:
  enabled: true
  base-url: https://cloud.langfuse.com
  api-key: ${LANGFUSE_API_KEY}

# MCP 配置（可选）
mcp:
  servers:
    - name: filesystem
      command: npx
      args: ["-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    - name: github
      command: npx
      args: ["-y", "@modelcontextprotocol/server-github"]
      env:
        GITHUB_TOKEN: ${GITHUB_TOKEN}
```

### 2.5.2 环境变量替换

配置值可以用 `${ENV_VAR}` 引用环境变量：

```yaml
llm:
  api-key: ${OPENAI_API_KEY}
```

启动时，core-ng 会自动替换为环境变量值。

💡 **设计意图**：敏感信息（如 API key）不要硬编码在配置文件里，用环境变量更安全。

### 2.5.3 配置优先级

配置优先级从高到低：

1. **命令行参数**（`--llm.api-key=xxx`）
2. **环境变量**（`LLM_API_KEY=xxx`）
3. **配置文件**（`application.yml`）
4. **默认值**（代码里的默认值）

💡 **设计意图**：高优先级覆盖低优先级，方便在不同环境（开发/测试/生产）用不同配置。
